Expand description

A message body and everything the database stores alongside it.

The only way a body reaches the database: a writer constructs one of these and hands it whole to the store, so contents, its reference rows, its kind rows and its search_text can never disagree about which body they describe.

Fields§

§source: String

The body exactly as composed. The stored contents column, and the only field a re-derivation reads back.

§document: Document

source parsed once. Callers that need the tree (rendering, further extraction) take it from here rather than parsing again.

§references: Vec<Reference>

Every hound: reference, in document order, deduplicated.

§links: Vec<String>

Every http(s) URL, in document order, deduplicated — what the unfurler works from.

§kinds: Vec<ContentKind>

The message’s content facets, sorted and deduplicated.

§search_text: String

The body flattened for full-text search: markup removed, link URLs kept (so hosts are searchable), code verbatim, spoilers included, and references elided entirely — a search must not match on a display name the body never contained.

pub fn parse( source: &str, ctx: &MessageContext<'_>, limits: &Limits, ) -> Result<Self, Violation>

Validate source against limits, then derive everything stored beside it.

The documented entry point for a write. Returns the same Violations [crate::validate] does — an empty body is one of them; see ParsedMessage::parse_allowing_empty for the message that is carried by its attachments instead.

Source

pub fn parse_allowing_empty( source: &str, ctx: &MessageContext<'_>, limits: &Limits, ) -> Result<Self, Violation>

ParsedMessage::parse, accepting an empty body.

For the two callers that have one: a message whose attachments carry its meaning, and a re-derivation of a message already stored (which must never reject what was accepted at write time). Every other limit still applies.

Source

pub fn with_context(&self, ctx: &MessageContext<'_>) -> Self

This message re-derived against a new MessageContext.

Only the context-dependent facets change: the source is not re-parsed and not re-validated, so an unfurl landing on a message can add its image/embed facets without any chance of rejecting a body that is already stored.
