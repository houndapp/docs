Hound’s message format: CommonMark plus a fixed extension set.

A message is markup wherever it’s composed or read — the backend stores raw source and re-parses it on the way out, the Flutter client’s Rust core parses the exact same source through this same crate via flutter_rust_bridge. The one invariant this crate exists to hold: server and client run this exact crate, built against the exact comrak version and dialect pinned in [parse] — so what a reader sees resolved as a hound: reference is exactly what the composer typed and exactly what the server extracted, never a client-only or server-only reading of the source.

  • ast — Document/Block/Inline: plain owned data safe to cross the FFI boundary (no lifetimes, no references, no maps; recursion only through Vec).
  • [parse] — comrak wrapped behind a single, total entry point; comrak’s AST types never escape this crate.
  • [reference] — hound:<kind>/<uuid> references: hound’s in-message links to its own objects.
  • [plain_text] — rendering a Document back to plain text for previews and notifications, with references resolved to display names.
  • [validate] — the length and reference-count limits enforced on every accepted message.
  • kind — ContentKind: the coarse content facets (“has code”, “has a picture”) a search filters on.
  • parsed — ParsedMessage: a body plus everything derived from it, in one pass. The entry point for anything that writes a message.
