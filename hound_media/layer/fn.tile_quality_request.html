pub fn tile_quality_request(
    source: VideoSource,

Expand description

Map a rendered tile’s physical pixel size + visibility to a QualityRequest. This is the demand half of demand-driven simulcast — it never asks for more than the tile can use, which is exactly the receiver-CPU win (a thumbnail pulls the low track).

width/height are physical (device) pixels, not logical ones: decode and render cost scale with the pixels the GPU actually paints, so the same 360-wide grid cell is a thumbnail on a 1× display and a genuine 720-wide surface on a 2× one. The UI multiplies by MediaQuery.devicePixelRatioOf before reporting.

The cap is derived from the tile’s own pixel count, not a constant: the tile takes the cheapest rung that covers it (within TILE_UPSCALE_TOLERANCE_NUM/TILE_UPSCALE_TOLERANCE_DEN), priced through rung_bps; past the richest rung it takes the source. A 1 Mbps flat cap — what this used to return for every sub-360p tile, including a 171×96 filmstrip stamp — is 6–12× the per-tile budget Zoom, Daily and LiveKit all converged on, and it was the dominant cost of a large call.
