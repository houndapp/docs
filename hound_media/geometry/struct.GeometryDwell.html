Expand description

Dwell-based hysteresis for the encoder-REBUILD geometry decision (pure, sans-IO — see GEOMETRY_REBUILD_DWELL_US for why this must not track the per-tick crate::Rung directly). Self::observe feeds the freshly-decided rung each tick as a RungTarget (None for crate::Quality::AudioOnly — no video decision, so the last committed geometry carries through unchanged; encode is paused anyway) and returns the geometry the encoder should be built at right now: unchanged unless the SAME candidate has held for GEOMETRY_REBUILD_DWELL_US continuously — any intervening DIFFERENT candidate (a still-settling climb, or genuine flapping) resets the timer, so only a genuinely stable rung ever triggers a rebuild.

§The dwell’s currency is the TARGET, not the geometry it fits to

Two rungs can fit to the same pixels and still be different rungs: a share of a window already smaller than both rungs’ budgets cannot be upscaled onto either (fit_encode_area never upscales), so SCREEN_LOW_RUNG and SCREEN_MID_RUNG both land on the capture geometry — while differing by 15 vs 30 fps and 200 kbps vs 1.1 Mbps. Neither of those can be applied to a LIVE encoder: VideoEncode has no frame-rate setter at all (fps is fixed at construction, and on the software encoders it also fixes the intra period), and set_bitrate is a documented no-op on the software H.264 and AV1 paths. So a rung change with unchanged geometry is still a REBUILD, and debouncing on the fitted geometry would have made it invisible — a cap wobbling across the 1.1 Mbps boundary would then have flipped the encoder’s frame rate and rate-control target every tick with no hysteresis at all, or (with the rung in the rebuild key) rebuilt + IDR’d every tick.

Keying on the target instead means every rung change is debounced by the same rule, whether or not the geometry moves: Self::committed_target only ever moves after a full dwell, so a caller keying its rebuild on (committed(), committed_target()) rebuilds at most once per GEOMETRY_REBUILD_DWELL_US and not at all under a wobble.

impl GeometryDwell

Source

pub fn new(source: (u32, u32)) -> Self

source is the capture’s own geometry — pass the encoder’s ACTUAL geometry at construction (the capture loop always opens its encoder at native/source geometry before any adaptation decision exists), so the first tick at the top rung is a no-op rather than a spurious rebuild.

Source

pub fn with_committed(source: (u32, u32), committed: (u32, u32)) -> Self

Same, for an encoder that is already built BELOW source — the low simulcast layer, whose encoder opens at whatever rung its first coalesced cap bought rather than at capture geometry. Seeding committed at the source instead would make the first tick a no-op for a full dwell and leave the low encoder running at capture resolution for five seconds.

source still bounds the ladder: a rung is fitted to the source’s aspect and never upscaled past it (see fit_encode_dims / fit_encode_area), so this must be the CAPTURE geometry, not the rung’s.

Source

pub fn observe( &mut self, target: Option<RungTarget>, now_us: i64, dwell_us: i64, ) -> (u32, u32)

Advance the dwell state one tick. target is the rung this tick decided (None = crate::Quality::AudioOnly); now_us/dwell_us mirror the CodecSwitch/LayerHysteresis debounce contract elsewhere in this codebase. Returns the committed (width, height) the encoder should be built at; pair it with Self::committed_target for the rung half of a rebuild key.

pub fn committed(&self) -> (u32, u32)

The currently-committed encode geometry (what the encoder should already be built at).

Source

pub fn committed_target(&self) -> Option<RungTarget>

The rung Self::committed belongs to — the other half of the rebuild key for a caller whose ladder can produce two rungs at one geometry (the screen low layer; see this type’s contract). None only before the first Self::observe with a target.
