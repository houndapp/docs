§Encoder-rebuild geometry dwell + encode-geometry fitting

The follow-up to the resolution-adaptation hotfix: the sender’s VideoEncoder is opened once at a fixed geometry, so honoring a rung’s resolution (not just its bitrate/fps) means tearing down and rebuilding the encoder when the chosen rung’s geometry changes. That is expensive (a real device open/close) and visible (forces a fresh IDR — a decoder can’t switch resolution mid-GOP, so every receiver must resync), so unlike bitrate/fps — which the SAME encoder retargets for free every tick via crate::AdaptDecision::target_bps / AdaptShared::target_fps — a resolution change must not flap with ordinary AIMD/delay-BWE noise. GeometryDwell is the dedicated hysteresis for that one decision; the IO shell (the capture/encode loop) drives it independently of crate::VideoAdaptation::on_tick, mirroring the CodecSwitch/LayerHysteresis dwell pattern already used for the codec-switch and receive-side layer-switch decisions (crates/client/src/call/policy.rs) — kept here instead so the decision stays sans-IO and unit-tested in this crate.

Structs§

GeometryDwell
Dwell-based hysteresis for the encoder-REBUILD geometry decision (pure, sans-IO — see GEOMETRY_REBUILD_DWELL_US for why this must not track the per-tick crate::Rung directly). Self::observe feeds the freshly-decided rung each tick as a RungTarget (None for crate::Quality::AudioOnly — no video decision, so the last committed geometry carries through unchanged; encode is paused anyway) and returns the geometry the encoder should be built at right now: unchanged unless the SAME candidate has held for GEOMETRY_REBUILD_DWELL_US continuously — any intervening DIFFERENT candidate (a still-settling climb, or genuine flapping) resets the timer, so only a genuinely stable rung ever triggers a rebuild.

Enums§

RungTarget
What a GeometryDwell tick is asking for, in whatever unit its ladder measures rungs in — the dwell fits it to the source with the matching function, so the hysteresis and the producer’s own geometry derivation can never disagree about what a rung means.

Constants§

GEOMETRY_REBUILD_DWELL_US
How long a candidate encode geometry must hold, unchanged, before the encoder actually rebuilds at it. Without a dwell, ordinary AIMD noise — or the delay-based estimator pinning low for a beat before recovering — would rebuild the encoder every few seconds. ~5 ticks at the 1 s adaptation cadence the client drives crate::VideoAdaptation::on_tick at.

fit_encode_dims
Fit a rung’s target HEIGHT to the SOURCE capture’s own aspect ratio, even- clamped. The camera and screen quality ladders both store a nominal 16:9 width on each crate::Rung purely for the bitrate model (see crate::screen_rungs) — a screen source is not always 16:9 (a portrait phone mirror, a near-square shared window), so encoding at the rung’s raw width would stretch it. Deriving the width from the source’s own aspect instead — the same approach the low simulcast layer uses for its fixed low-resolution encode — keeps every encode at the right aspect regardless of what the ladder’s rung table says. For the camera ladder, whose capture geometry and rungs are both already 16:9, this reproduces the rung’s own width exactly.
