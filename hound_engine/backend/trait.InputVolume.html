Expand description

A resolved OS input-volume handle for one capture device (P5: the Chrome/Discord-style controller that drives the OS mic slider, not just digital gain). Unlike the streaming traits above there is no next_frame — this is a query/command surface, resolved once per device (see each backend’s inherent resolve(device_name: &str) -> Option<Self>, matched by the same name crate::platform::generic::audio_devices treats as the device id) and cheap to call repeatedly thereafter.

§Implementor contract

  • resolve returns None when no device matches, or the matched device has no READABLE+SETTABLE volume property at all (aggregate devices, some USB/virtual interfaces) — never a panic, never a silently-wrong handle.
  • Self::get/Self::set are best-effort: a transient platform error is None/false, not a panic and not a permanent failure (the caller keeps its last-known reading and tries again next tick).
  • Every call here does real platform I/O (a HAL/COM round trip) — the caller (call::audio_tx’s volume actor) is responsible for keeping it off the real-time capture thread, never this trait’s job.

fn get(&self) -> Option<f32>

Current OS input-volume scalar (0.0..=1.0) for this handle’s device. None on a read failure (device removed, transient HAL/COM error).

Source

fn set(&self, scalar: f32) -> bool

Set the OS input-volume scalar (0.0..=1.0; out-of-range values are the caller’s bug, not this trait’s to clamp silently — implementors clamp defensively anyway since a wrong write is worse than a refused one). false = the write failed, or the property was settable at resolve time but no longer is (a device can lose the capability live).
