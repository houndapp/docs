§OS input-volume control (P5, Linux) — not wired yet

apm.rs enables sonora’s input_volume_controller unconditionally (safe: it only computes a recommendation, independent of the digital gain stages — see that module’s doc), but this backend never resolves a device, so Linux never gets an OS write and stays on the digital-only gain chain.

TODO (follow-up, not this pass): PipeWire/PulseAudio source volume — pw_stream’s PW_STREAM_FLAG_AUTOCONNECT node already carries a SPA_PROP_channelVolumes prop that a pw_core/pw_registry client can read and set per-node (mirroring the loopback/app-audio plumbing already in [super::pw_audio]), or the simpler libpulse-binding path against the default source if the desktop is PulseAudio-compatible (PipeWire’s pulse shim included). Either slots in here as a real crate::backend::InputVolume impl; nothing above this module needs to change.
