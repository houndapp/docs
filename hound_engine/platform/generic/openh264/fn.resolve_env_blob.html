Resolve BLOB_PATH_ENV, which may name either the library itself or a directory containing it.

The directory form exists because the library’s file name is not predictable. mise’s http: backend renames what it extracts, and not consistently: the same mise on linux-x64 leaves libopenh264-2.6.0-linux64.8.so but on linux-arm64 leaves plain libopenh264 (macOS keeps the full …-mac-arm64.dylib). Any hardcoded name is therefore wrong on some runner — it was, and it broke the arm64 CI fleet — so callers may just point at the install directory and let this pick the one library inside.

Deliberately strict about “one”: silently choosing between several candidates is how you end up loading the wrong architecture. Ambiguity is treated as “no blob”, which surfaces as the ordinary typed Unsupported.
