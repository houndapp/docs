The software-AV1 seam: the ONE av1-sw-decode cfg boundary, so no decoder selector or capability probe carries a feature gate of its own. Built everywhere — with the feature off it resolves to an uninhabited decoder and a false capability. The software-AV1 seam: one cfg boundary for the whole engine.

The dav1d decoder is behind an optional dependency (see super::dav1d_decoder for why — not linked, it only exists under its feature), but the three places that select a decoder — the Apple HW-or-SW composite, the portable SW backend, and the decode_caps probe — should not each carry a feature cfg. They ask this module instead:

  • [available] — is there a real AV1 decoder in this build? The single input to decode_caps().av1 on the software side, so a client can never advertise AV1 to peers and then fail to construct a decoder for it.
  • [open] — build one, or a typed [CaptureError::Unsupported].
  • [SwAv1Decoder] — the decoder type, uninhabited when the feature is off, exactly like crate::platform::stub’s never-backends. That is what lets the composite decoders hold it in an enum arm unconditionally: the arm exists in the type, no value can ever occupy it, and it costs nothing.
