Process-wide accounting of live SOFTWARE decode sessions — what makes decode_session_budget answer with the CPU-shaped bound once any stream has degraded off hardware. Process-wide accounting of live software video-decode sessions.

A hardware decode session is a silicon resource: the platform hands out a bounded number (see crate::platform::decode_session_budget) and the cost of one more is a queue entry on a fixed-function block. A software session is the opposite — an unbounded resource with a per-session CPU price, paid on the same cores the real-time audio mix thread runs on. The two therefore have different budgets, and a receiver that has silently degraded from one to the other must be budgeted as what it now is.

Every software decoder (crate::platform::generic::openh264::Openh264Decoder, the dav1d AV1 decoder) holds a [SwSessionGuard] for its whole life, so the count here is exact regardless of how the session came to be software: opened that way (a Linux/Windows client with no HW codec), or switched into it mid-stream by a HW session-create failure (the Apple/Windows fallback arms).

§What reads it

  • crate::platform::decode_session_budget — the receiver’s session ceiling collapses from the HW bound to the CPU-shaped SW bound while any session is software. This is what the task-level requirement “SW sessions register against the SW bound, not the HW bound” means in practice: the client’s DecodeBudget re-reads the ceiling each reconcile pass and retargets.
  • [crate::api::Engine::sw_decode_fallbacks] — the cumulative activation count, so a fleet-wide VideoToolbox/MFT regression is visible as software decoders appearing everywhere rather than only as a per-call log line.

Relaxed ordering throughout: these are counters read by a 2 Hz control loop and a 1 Hz stats emitter, never a synchronisation edge.

Structs§

SwSessionGuard 🔒
RAII registration of one live software decode session. Held by the software decoders themselves, so the count cannot drift from reality: whatever path drops the decoder (clean teardown, a codec switch, a panic unwinding the decode thread) also drops this.

Statics§

ACTIVATIONS 🔒
Software decode sessions ever constructed in this process — monotonic, so a metric consumer can rate it. Counts constructions, so a stream that falls back, is rebuilt onto hardware and falls back again counts twice (which is the interesting signal: churn between the arms).
LIVE 🔒
Software decode sessions alive right now.
