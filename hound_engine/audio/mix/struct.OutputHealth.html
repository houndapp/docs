Struct OutputHealth 

Source 
struct OutputHealth {
    outage: DeviceOutage,
    cause: Option<String>,
}
Expand description

Output-device health: WHEN a device failure stops being a hiccup and becomes an operator event.

The stream error callback cannot make that call — it fires before recovery has been attempted, and the reopen a tick later fixes nearly every one of them (a USB headset unplugged, a suspend/resume, an ALSA EIO from a PipeWire node that went away). Reporting there filed a Sentry issue per recovered hiccup while a device whose reopens quietly failed forever produced nothing. So the callback only ever warns, and the escalation lives here: the shared DeviceOutage latch, plus the last cause so the one report that DOES reach Sentry can name it.

impl OutputHealth

Source

fn opened(&mut self, now: Instant)

The sink is open. Closes any outage; announces the recovery only if the outage had already been escalated, so the filed event gets a visible end and ordinary hiccups stay quiet.

Source

fn died(&mut self, now: Instant, cause: Option<String>)

The live stream died (its error callback marked it dead). cause is the backend’s message for that error, if it captured one.

Source

fn open_failed(&mut self, now: Instant, e: &AudioError)

A reopen attempt failed — the outage continues and the ladder backs off.

Source

fn poll_down(&mut self, now: Instant)

Called every tick while there is NO open sink. Keeps the outage clock running and emits the single error! once recovery has been failing for super::outage::OUTAGE_ESCALATE_AFTER.
