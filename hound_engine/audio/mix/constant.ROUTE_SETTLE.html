const ROUTE_SETTLE: Duration;

How long an automatic output-route change must stay QUIET before the bus re-syncs its sink.

cpal’s ErrorKind::DeviceChanged is informational — the stream was already rerouted and is still playing — so nothing is urgent. But the sink’s geometry (device_rate, its 48 k→device resampler, and hence the scale of buffered_ms) still describes the OLD device, so a 48 k→24 k hop silently halves the cushion regulator’s units. One reopen fixes that.

The debounce exists because a single Bluetooth connect/disconnect makes macOS move the default output repeatedly (5 changes in 50 s observed on AirPods). Each change PUSHES this deadline, so a whole flap burst costs ONE reopen instead of one per event — and each reopen is a blocking device open (up to ~1 s inside CoreAudio) on this real-time thread plus a fresh OUTPUT_CUSHION_MS prefill. 2 s is comfortably longer than the gaps within an observed burst and short enough that the stale geometry never outlives a call’s cushion tuning.
