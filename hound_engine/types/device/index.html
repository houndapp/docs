Device identity — separate id types per device kind, so the “opened the wrong device kind” class is unrepresentable.

Macros§

device_id 🔒

Structs§

CameraId
A camera selection token. On Apple platforms this is the AVFoundation uniqueID — stable across reconnects, distinct from the localized name.
MicId
A microphone (audio input) selection token. For the cpal backend the human-readable device name IS the id (a documented cpal limitation — there is no portable stable identifier).
SpeakerId
A speaker (audio output) selection token. Name == id, like MicId.

Enums§

DeviceChoice
Which device to open: the host default, or a specific one by typed id.
DeviceKind
Which kind of media device an id/choice/error refers to.
DevicePermission
The OS’s privacy verdict for a device, as reported by crate::api::Engine::device_permission — a non-prompting query, so a UI toggle can refuse up front instead of enabling a device that will never produce a frame.

Traits§

DeviceId
Trait tying a device-id newtype to its DeviceKind, so generic device plumbing (choice resolution, error construction) can name the kind without a concrete id type. Implemented only by the id newtypes above.
