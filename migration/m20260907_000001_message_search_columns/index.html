The search-facing projection of a message body: its flattened search_text and its ContentKind facets.

Derived data, like the reference table beside it — every value here is always equal to what a fresh hound_markup::ParsedMessage would produce from the owning message’s current contents plus its attachments and embeds. Nothing is stored here that those three do not already say, so the whole projection is rebuildable: POST /internal/messages/reindex walks every message and re-derives it.

search_text defaults to the empty string so the column can be added to a populated table; a reindex is what fills it. No text index yet — that lands with the search feature that reads it.
