Event-driven decoded-geometry reporting for the render path.

A tile’s native texture is allocated at the DECODED frame size, so Flutter has to learn a resolution change (an inbound simulcast layer switch, a shared-window resize, a camera hot-swap) to rebuild it. Deriving that from the 1 Hz StatsSnapshot cadence means up to a second of the sharp new layer being scaled into the old texture — visibly soft.

This is the event side of that: the decode→render sink (crate::api’s RenderVideoSink) sees every frame’s dimensions, so it reports them here and the change detector below wakes watch_frame_sizes the instant a stream’s geometry moves.

§Division of labour with the stats snapshot

The snapshot still decides membership (which stream keys exist, and the self-capture / self-screen geometry it alone knows); this map only decides freshness — it overrides the geometry of keys the snapshot already emits. That keeps the DTO’s contract intact: no phantom key can survive a peer leaving or a call ending, because a key the snapshot has dropped is never emitted no matter what this map still remembers.

§Cost

One mutex + one borrowed-key hash lookup per decoded frame on the decode task (a hit in steady state: compare, unlock, no allocation, no wakeup). Only a real change allocates (the key) and bumps the watch.
