Log bridge: Rust tracing → Dart (plus the stderr mirror for CI smoke runs and the persistent log file’s bridge commands). The file mechanics themselves live in crate::logfile; this is the bridge half.

Structs§

LogSink 🔒
A std::io::Write that accumulates a formatted log event and pushes it to the live Dart StreamSink as one line when dropped (fmt drops the writer per event).

Statics§

LOG_SINK 🔒
The live Dart log sink. Swapped on each init_log (e.g. a hot restart hands us a fresh sink); the tracing layer — installed exactly once — reads this per event, so it always forwards to the current sink and never to a dead one.

Functions§

init_log
Install a tracing subscriber that forwards every formatted Rust log line to Dart over sink. WITHOUT this, the core’s tracing::{info,warn,error}! (the call/transport/engine diagnostics) have no subscriber and are silently dropped.
log_file_path
Absolute path of the file this instance’s logs are written to, or None when file logging could not be brought up (no usable OS log directory — see crate::logfile). Settings shows it so the path can be typed into a support thread or pasted into a file dialog; None is why the reveal button is hidden.
log_sink_slot 🔒
mirrors_logs_to_stderr 🔒
Whether this process mirrors every engine log line to stderr. The CI launch smoke’s pass/fail contract greps captured stdio for session restore:, so the marker’s visibility must not hinge on the Dart-side relay.
open_log_file
Open the current log file with the OS default handler (Console/Notepad/whatever the desktop associates with .log) — the settings screen’s “open logs” action.
