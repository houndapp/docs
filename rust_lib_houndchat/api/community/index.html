Module community 

Source
Expand description

Community + channel management commands.

Thin marshalling over the HoundClient surface of the same names: the tree-folding, the upload-then-patch sequencing and the error copy all live in the core, so each function here is one call plus the shape changes the bridge forces.

Three of those shape changes are worth naming:

  • update_community takes flat parameters rather than the core’s [CommunityPatch], because its clearable fields are Option<Option<T>> — a shape Dart has no spelling for. The clear is a separate boolean (clear_description), which is why the two are documented as a pair.
  • set_community_icon takes the file’s bytes, already read by Dart. The engine never reads a user-chosen path: the file picker is a platform surface, and handing Rust a path would mean re-deriving permissions and sandbox translation the Dart side has already done.
  • set_space_overwrites takes the two overwrite lists flat rather than the core’s SpaceOverwrites, so the call reads the way the editor’s table is built. It is still a full replace — two empty lists clear the channel.

One function here is not marshalling at all: parse_invite_code is #[frb(sync)] pure string work, bridged so a paste handler gets the same answer on every platform without a round trip.
