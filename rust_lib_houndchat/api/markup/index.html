Module markup

Expand description

Message-markup commands: parsing preview text, live source highlighting for the composer, plain-text rendering (the “Copy text” action), autolinking a reference, and fetching a single message.

NamedId + its [hound_markup::Resolve] impl are the only logic here, and both are trivial: they exist to adapt three flat Vec<NamedId> lists (a shape FRB mirrors cleanly) onto Resolve’s by-id lookup, because the UI already holds the roster as lists, not as a map keyed for this purpose.

highlight_markup
Style runs over text for the composer’s live source highlighting: which UTF-16 spans of the text being typed are bold/quoted/code/…, and which are the syntax markers to mute. Offsets are UTF-16 code units — what a Dart String (and therefore a TextEditingValue) indexes by.
markup_plain_text
Render doc as plain text, resolving references against the roster the UI already holds (users/spaces/communities). Backs the “Copy text” action; a reference the caller has no name for falls back to @unknown user etc. (see hound_markup::plain_text).
parse_markup
Parse source as hound markup. Backs the composer’s live preview and markup-focused tests; the real ingestion path never calls this directly — it goes through hound_client::model::Message::body, parsed once at fetch time.
