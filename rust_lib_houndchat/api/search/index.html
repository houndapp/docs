Message search: running one, parsing what is being typed, and the detached-history commands a jump to a hit drives.

§Why this module re-declares half of hound-search

Everything on this surface is mirrored by default (see the projection rule in crate::api) — but three of the query language’s enums are #[non_exhaustive] on purpose ([hound_search::TokenKind], [hound_search::DiagnosticKind], [hound_markup::ContentKind]: they track the language, not a wire contract), and a mirror’s generated match carries no wildcard arm, so mirroring one stops compiling the moment a variant is added upstream. They therefore cross as the DTOs below, whose From impls fold an unrecognised variant onto an explicit Unknown — the Dart side gets a value it can render as “something this build doesn’t know” instead of a build that no longer compiles.

Query and Parsed follow them because they contain those enums, and SearchToken / SearchDiagnostic additionally flatten a Range<u32> into start/end (the same shape hound_markup::StyleRun already crosses as). Everything that mirrors cleanly still does: Term, DateSpec, and the whole result surface (SearchPage, [SearchHit], SearchScope, SearchSort) are declared in crate::api::mirrors.

Offsets in SearchToken/SearchDiagnostic are UTF-16 code units — what a Dart String and a TextEditingValue index by.
