1//! Voice/video **call orchestration** — the UI-free engine that drives a live
2//! call from `HoundClient`.
3//!
4//! It parallels the legacy Tauri orchestration in `src/voice/session/*` but
5//! reuses the engine/transport/control crates directly and stays free of any
6//! UI/FFI machinery (no Tauri `Channel`/`AppHandle`/`emit`). The decode→render
7//! seam is a [`VideoSink`] trait the FRB layer supplies (its closure calls
8//! `video_render::push_frame(...)`); decoded frames reach the right tile keyed by
9//! peer without this crate ever knowing about textures or Dart.
10//!
11//! ## What a join wires up
12//!
13//! ```text
14//! REST voice/join  ──► relay_url + relay_token + sfu_node_id + peers
15//!        │
16//!        ├─► control WS (hound-control)  ──► SessionView reducer ──► watch<CallView>
17//!        │
18//!        └─► dial iroh ──► MoqRelaySession ─┬─► publish mic (Opus)
19//!                                           ├─► publish camera (H.264) [if enabled]
20//!                                           └─► subscribe loop: for each remote track
21//!                                                 video → decode → VideoSink (push_frame)
22//!                                                 audio → decode → mix bus (PlayoutBus)
23//! ```
24//!
25//! ## Module tree
26//!
27//! ## Module tree
28//!
29//! This file is the shared hub — the public seams ([`VideoSink`],
30//! [`RenderSurfaceHandle`]), the dedicated runtimes, and the stream-key scheme.
31//! Everything else lives in the submodules:
32//!
33//! * [`view`] — the observable snapshot types ([`CallView`], [`ConnectionState`],
34//!   [`LevelsView`]) + the shared receive-side joins ([`PeerIdentities`]).
35//! * [`pickers`] — the share/device picker enumerations + the process-global
36//!   screen-share error surface ([`watch_screen_error`]).
37//! * [`tuning`] — the cross-module tuning constants + the broadcast-path scheme.
38//!
39//! * [`session`] — [`CallSession`] (join/leave/commands), `establish_live`, the
40//!   auto-reconnect supervisor + screen-share command handling.
41//! * [`reconnect`] — the pure backoff/classification policy + the retry loop.
42//! * [`control`] — the `/control` WebSocket IO shell + the iroh relay dial.
43//! * [`policy`] — the pure, unit-tested decision policies (codec switch, layer
44//!   hysteresis, restart pacing, resize debounce, gain, gap math…).
45//! * [`adapt`] — sender-side BWE/congestion adaptation glue ([`adapt::AdaptShared`],
46//!   the 1 s tick, the keyframe/feedback listeners, the shared encode core).
47//! * [`simulcast`] — demand-driven simulcast (the layer planner + low publish).
48//! * [`audio_tx`] / [`camera_tx`] / [`screen_tx`] — the publish paths.
49//! * [`speaking`] — the shared dominant-speaker ranking + this client's own
50//!   speaking-level report.
51//! * [`subscribe`] — the roster-diffing subscribe loop + per-track pipelines.
52//! * [`audio_rx`] / [`video_rx`] — the decode pipelines.
53//!
54//! ## Observable state
55//!
56//! Three `watch` channels, driven the same way as the realtime→reducer→watch task
57//! in [`crate::app`]: [`CallView`] (self id, peers, tracks) is derived from the
58//! control plane's [`SessionView`]; [`ConnectionState`] reflects the control WS +
59//! reconnect attempts; [`LevelsView`] carries mic + per-peer speaking levels. A
60//! fourth, [`watch_screen_error`], carries the last TERMINAL screen-share failure —
61//! process-global rather than per-call, because it must outlive the share that
62//! produced it (see [`ScreenShareError`]).
63//!
64//! ## Auto-reconnect supervisor
65//!
66//! A live call heals a dropped control WebSocket or MoQ/iroh connection **without
67//! the user re-joining** — "nothing drops a call except total network loss."
68//!
69//! * [`reconnect::Backoff`] + [`reconnect::classify`] — the pure, headless policy
70//!   (exp-backoff+jitter; retryable-vs-fatal over [`HoundError`]). Only an
71//!   auth/permission outcome (`Http 401/403` or `Auth`) is fatal; everything
72//!   transient retries FOREVER.
73//! * [`session::LiveSession`] — the per-establish layers (relay/conn/control/tasks).
74//!   Its `monitor` selects over the control-WS-closed signal and the iroh
75//!   `Connection::closed()`, naming which layer dropped.
76//! * [`session::ConnectionParams`] — the Arc-cloneable cross-reconnect state.
77//!   `establish_live` builds one `LiveSession` (re-minting the relay token via
78//!   `voice/join` each time, so no standalone token-refresh task is needed).
79//! * [`session::spawn_supervisor`] — owns `live` + a `Backoff` + the screen-share
80//!   state; monitors, tears down on failure, and rebuilds with backoff. Recovery is
81//!   a FULL re-establish (fresh `PeerId`); the reactive subscribe loop re-diffs the
82//!   roster for free and re-publish is a fresh mic/cam announce.

117// ─── Dedicated call runtime ─────────────────────────────────────────────────────
118
119/// The runtime every call task is spawned onto.
120///
121/// flutter_rust_bridge builds its async runtime with `tokio::runtime::Runtime::new()`
122/// — one worker per core. The call's steady-state tasks (mic publish, per-track
123/// decode, the moq session driver, supervisor/heartbeat) are light and
124/// latency-bound, not CPU-bound, so spreading them over a per-core pool only adds
125/// park/unpark + work-steal coordination that dwarfs the actual Opus/moq work. A
126/// small pool carries the same load with a fraction of that overhead.
127///
128/// All `spawn` sites in this module target this runtime, and `CallSession::join` is
129/// driven on it (so moq-net's internally-spawned session driver lands here too rather
130/// than on the FRB pool). `'static` so it is never dropped — dropping a runtime from
131/// within an async context panics, and FRB commands call us from async context.
132pub(crate) fn call_runtime() -> &'static tokio::runtime::Runtime {
133    static RT: std::sync::OnceLock<tokio::runtime::Runtime> = std::sync::OnceLock::new();
134    RT.get_or_init(|| {
135        tokio::runtime::Builder::new_multi_thread()
136            // 3 workers: 2 carry the steady control + video load with headroom; the
137            // third is margin so a high-bitrate screenshare's moq frame delivery —
138            // which can saturate a worker — cannot head-of-line-block the others on
139            // the same pool. NB: audio fill does not run here — it has its own RT
140            // runtime (`audio_runtime`) so video CPU can't starve voice ("audio is
141            // sacred").
142            .worker_threads(3)
143            .enable_all()
144            .thread_name("hound-call")
145            .build()
146            .expect("build dedicated call runtime")
147    })
148}
149
150/// The dedicated runtime for the audio RECEIVE/fill path (per-peer Opus decode → mix
151/// jitter buffer). Isolated from [`call_runtime`] and **real-time promoted** (each
152/// worker runs [`promote_current_thread_for_audio_fill`] on start) so a CPU-heavy
153/// screen-share decode/scale/render load can never deschedule the fill — the RT mix
154/// bus would otherwise find the jitter buffer dry at its 10 ms pull tick and the call
155/// audibly stutters (`mix_starve`). The playout (mix) side is already RT; this extends
156/// the same guarantee to the producer side. "Audio is sacred": video can freeze, voice
157/// cannot.
158///
159/// Two workers: the decode of a 20 ms Opus frame is sub-millisecond and mostly parked
160/// on the network, so a couple of RT threads comfortably carry many peers without any
161/// busy-loop that would starve the system. (Caveat: the shared moq/QUIC demux driver
162/// still runs on `call_runtime`; the jitter buffer absorbs brief demux delay, and RT
163/// decode here removes the dominant — CPU-bound — starvation source.)
164pub(crate) fn audio_runtime() -> &'static tokio::runtime::Runtime {
165    static RT: std::sync::OnceLock<tokio::runtime::Runtime> = std::sync::OnceLock::new();
166    RT.get_or_init(|| {
167        tokio::runtime::Builder::new_multi_thread()
168            .worker_threads(2)
169            .enable_all()
170            .thread_name("hound-audio-rx")
171            .on_thread_start(hound_engine::api::promote_current_thread_for_audio_fill)
172            .build()
173            .expect("build dedicated audio runtime")
174    })
175}

177// ─── Public seam: the decode → render sink (UI-free) ────────────────────────────
178
179/// The decode→render seam. The orchestration decodes remote video into tightly
180/// packed I420 and hands it here, keyed by a stream key (`"self"`, `"cam:{peer}"`,
181/// `"screen:{peer}"`). The FRB layer supplies an impl whose body calls
182/// `video_render::push_frame(key, w, h, i420)` — so this crate stays free of any
183/// texture/FFI dependency. The sink must be cheap and non-blocking (drop-oldest);
184/// it is called on a decode task, never on a real-time audio thread.
185pub trait VideoSink: Send + Sync + 'static {
186    /// Hand one decoded I420 frame to the renderer for `stream_key`. `i420` is
187    /// tightly packed: `w*h + 2*(w/2 * h/2)` bytes.
188    fn push_frame(&self, stream_key: &str, w: u32, h: u32, i420: Vec<u8>);
189
190    /// Zero-copy fast path: hand one decoded frame that is still GPU-resident
191    /// ([`RenderSurfaceHandle`]) so the renderer can sample it without a CPU
192    /// readback / colour conversion / re-upload. Returns `true` if the sink took
193    /// it. The default returns `false` ("I can't take a surface"), so the caller
194    /// falls back to [`Self::push_frame`] with materialized I420 — meaning software
195    /// decoders, non-GPU sinks (tests/headless), and platforms without a surface
196    /// renderer all keep working unchanged. The handle is valid only for the
197    /// duration of the call; an impl that keeps it must retain synchronously.
198    fn push_surface(&self, stream_key: &str, surface: RenderSurfaceHandle) -> bool {
199        let _ = (stream_key, surface);
200        false
201    }
202
203    /// Nothing is feeding `stream_key` any more — the renderer may release
204    /// everything it holds for it (a mailbox otherwise pins the last decoded frame:
205    /// on macOS a retained VideoToolbox decode-pool buffer, elsewhere a ~1.4 MB
206    /// I420 `Vec`, for the rest of the process).
207    ///
208    /// Called when a tile's LAST subscription goes away with no replacement: the
209    /// peer left, the track was withdrawn, the receiver's allocator hid the tile, or
210    /// video was paused. Deliberately NOT called for the losing half of a simulcast
211    /// LAYER SWITCH — that stops one track and starts another under the same stream
212    /// key in the same pass, and the mailbox is the seam the make-before-break
213    /// texture swap hands its first new frame through.
214    ///
215    /// Releasing can never blank a tile: what is on screen is the target buffer the
216    /// last frame was drawn INTO, not the mailbox (see `hound_render::drop_stream`).
217    ///
218    /// Default: no-op (tests/headless).
219    fn stream_ended(&self, stream_key: &str) {
220        let _ = stream_key;
221    }
222}

224/// A decoded frame still resident in a platform GPU buffer, handed to the renderer
225/// for a zero-copy sample (no NV12→I420 readback, no re-upload). One variant per
226/// GPU backend; a platform without a surface renderer never builds one (the
227/// [`VideoSink::push_surface`] default declines and the I420 path runs).
228///
229/// Designed once for all platforms: macOS/iOS today; Windows (D3D11 shared NV12)
230/// and Linux (dmabuf NV12) slot in as new variants behind the same seam.
231pub enum RenderSurfaceHandle {
232    /// macOS/iOS: an IOSurface-backed NV12 `CVPixelBuffer` (raw `CVPixelBufferRef`
233    /// as a pointer-sized int). The producer holds a +1 retain for the duration of
234    /// the `push_surface` call; the renderer wraps the two IOSurface planes (luma
235    /// R8, chroma RG8) as Metal textures on wgpu's device.
236    AppleCvPixelBuffer { ptr: usize, width: u32, height: u32 },
237    /// Windows: an NV12 `ID3D11Texture2D` on the engine's shared device (raw COM
238    /// pointer as a pointer-sized int). BORROWED — the frame's texture-pool lease
239    /// is what guards the texture against being rewritten, and that lease lives
240    /// on the frame, so the renderer must consume it synchronously inside the
241    /// `push_surface` call (it blits NV12→BGRA into the Flutter-shared target
242    /// there and then).
243    WindowsD3d11Nv12 { ptr: usize, width: u32, height: u32 },
244}
245
246impl RenderSurfaceHandle {
247    /// The platform surface handle for a GPU-resident frame, or `None` for byte
248    /// frames / platforms without a surface renderer (callers then take the
249    /// materialized-I420 [`VideoSink::push_frame`] fallback).
250    pub fn for_frame(frame: &hound_engine::types::RawFrame) -> Option<Self> {
251        let (width, height) = (frame.dims.width(), frame.dims.height());
252        let surface = frame.surface.as_ref()?;
253        if let Some(ptr) = surface.cv_pixel_buffer_ptr() {
254            return Some(Self::AppleCvPixelBuffer { ptr, width, height });
255        }
256        if let Some(ptr) = surface.d3d11_texture_ptr() {
257            return Some(Self::WindowsD3d11Nv12 { ptr, width, height });
258        }
259        None
260    }
261}

270/// The self-preview stream key, and the `cam:{peer}` / `screen:{peer}` builders —
271/// kept here so the key scheme has one source of truth across publish + subscribe.
272const SELF_KEY: &str = "self";
273fn cam_key(peer: PeerId) -> String {
274    format!("cam:{}", peer.0)
275}
276fn screen_key(peer: PeerId) -> String {
277    format!("screen:{}", peer.0)
278}
279
280/// The render stream key one remote video TILE draws into. A tile is a
281/// `(peer, source)` pair, not a track: the source and low simulcast layers of the
282/// same camera are two tracks feeding this one key, which is exactly why a layer
283/// switch is invisible to the renderer (see [`VideoSink::stream_ended`]).
284fn video_key(peer: PeerId, source: Source) -> String {
285    match source {
286        Source::Screen => screen_key(peer),
287        _ => cam_key(peer),
288    }
289}

291/// Which inbound-video stats bucket a remote video track feeds: a screen source is
292/// counted as [`InboundVideoKind::Screen`], everything else (camera) as `Camera`. So
293/// a peer publishing BOTH cam + screen has each tile's fps/bitrate reported from its
294/// own track, not the summed total.
295fn inbound_video_kind(source: Source) -> InboundVideoKind {
296    match source {
297        Source::Screen => InboundVideoKind::Screen,
298        _ => InboundVideoKind::Camera,
299    }
300}

315    #[default]
316    Default,
317    /// Moving test pattern — real per-frame motion keeps the encoder

319    /// depend on it).

321    /// Static test card — pixel-identical frames for visual snapshot runs
322    /// (ui/integration_test), where motion is exactly what a diff can't
323    /// tolerate.
324    SyntheticTestcard,
