1//! Voice/video **call orchestration** — the UI-free engine that drives a live
2//! call from `HoundClient`.
3//!
4//! It parallels the legacy Tauri orchestration in `src/voice/session/*` but
5//! reuses the engine/transport/control crates directly and stays free of any
6//! UI/FFI machinery (no Tauri `Channel`/`AppHandle`/`emit`). The decode→render
7//! seam is a [`VideoSink`] trait the FRB layer supplies (its closure calls
8//! `video_render::push_frame(...)`); decoded frames reach the right tile keyed by
9//! peer without this crate ever knowing about textures or Dart.
10//!
11//! ## What a join wires up
12//!
13//! ```text
14//! REST voice/join  ──► relay_url + relay_token + sfu_node_id + peers
15//!        │
16//!        ├─► control WS (hound-control)  ──► SessionView reducer ──► watch<CallView>
17//!        │
18//!        └─► dial iroh ──► MoqRelaySession ─┬─► publish mic (Opus)
19//!                                           ├─► publish camera (H.264) [if enabled]
20//!                                           └─► subscribe loop: for each remote track
21//!                                                 video → decode → VideoSink (push_frame)
22//!                                                 audio → decode → mix bus (PlayoutBus)
23//! ```
24//!

26//!
27//! ## Module tree
28//!
29//! This file is the shared hub — the public seams ([`VideoSink`],
30//! [`RenderSurfaceHandle`]), the dedicated runtimes, and the stream-key scheme.
31//! Everything else lives in the submodules:
32//!
33//! * [`view`] — the observable snapshot types ([`CallView`], [`ConnectionState`],
34//!   [`LevelsView`]) + the shared receive-side joins ([`PeerIdentities`]).
35//! * [`pickers`] — the share/device picker enumerations + the process-global
36//!   screen-share error surface ([`watch_screen_error`]).
37//! * [`tuning`] — the cross-module tuning constants + the broadcast-path scheme.
38//!
39//! * [`session`] — [`CallSession`] (join/leave/commands), `establish_live`, the
40//!   auto-reconnect supervisor + screen-share command handling.
41//! * [`reconnect`] — the pure backoff/classification policy + the retry loop.
42//! * [`control`] — the `/control` WebSocket IO shell + the iroh relay dial.
43//! * [`policy`] — the pure, unit-tested decision policies (codec switch, layer
44//!   hysteresis, restart pacing, resize debounce, gain, gap math…).
45//! * [`adapt`] — sender-side BWE/congestion adaptation glue ([`adapt::AdaptShared`],
46//!   the 1 s tick, the keyframe/feedback listeners, the shared encode core).
47//! * [`simulcast`] — demand-driven simulcast (the layer planner + low publish).
48//! * [`audio_tx`] / [`camera_tx`] / [`screen_tx`] — the publish paths.
49//! * [`mic_monitor`] — the out-of-call mic test: the same capture+APM+meter path
50//!   with nothing downstream of the meter. Never runs while a call does.
51//! * [`speaking`] — the shared dominant-speaker ranking + this client's own
52//!   speaking-level report.
53//! * [`subscribe`] — the roster-diffing subscribe loop + per-track pipelines.
54//! * [`audio_rx`] / [`video_rx`] — the decode pipelines.
55//!
56//! ## Observable state
57//!
58//! Three `watch` channels, driven the same way as the realtime→reducer→watch task
59//! in [`crate::app`]: [`CallView`] (self id, peers, tracks) is derived from the
60//! control plane's [`SessionView`]; [`ConnectionState`] reflects the control WS +
61//! reconnect attempts; [`LevelsView`] carries mic + per-peer speaking levels. A
62//! fourth, [`watch_screen_error`], carries the last TERMINAL screen-share failure —
63//! process-global rather than per-call, because it must outlive the share that
64//! produced it (see [`ScreenShareError`]).
65//!
66//! ## Auto-reconnect supervisor
67//!
68//! A live call heals a dropped control WebSocket or MoQ/iroh connection **without
69//! the user re-joining** — "nothing drops a call except total network loss."
70//!
71//! * [`reconnect::Backoff`] + [`reconnect::classify`] — the pure, headless policy
72//!   (exp-backoff+jitter; retryable-vs-fatal over [`HoundError`]). Only an
73//!   auth/permission outcome (`Http 401/403` or `Auth`) is fatal; everything
74//!   transient retries FOREVER.
75//! * [`session::LiveSession`] — the per-establish layers (relay/conn/control/tasks).
76//!   Its `monitor` selects over the control-WS-closed signal and the iroh
77//!   `Connection::closed()`, naming which layer dropped.
78//! * [`session::ConnectionParams`] — the Arc-cloneable cross-reconnect state.
79//!   `establish_live` builds one `LiveSession` (re-minting the relay token via
80//!   `voice/join` each time, so no standalone token-refresh task is needed).
81//! * [`session::spawn_supervisor`] — owns `live` + a `Backoff` + the screen-share
82//!   state; monitors, tears down on failure, and rebuilds with backoff. Recovery is
83//!   a FULL re-establish (fresh `PeerId`); the reactive subscribe loop re-diffs the
84//!   roster for free and re-publish is a fresh mic/cam announce.

121// ─── Dedicated call runtime ─────────────────────────────────────────────────────
122
123/// The runtime every call task is spawned onto.
124///
125/// flutter_rust_bridge builds its async runtime with `tokio::runtime::Runtime::new()`
126/// — one worker per core. The call's steady-state tasks (mic publish, per-track
127/// decode, the moq session driver, supervisor/heartbeat) are light and
128/// latency-bound, not CPU-bound, so spreading them over a per-core pool only adds
129/// park/unpark + work-steal coordination that dwarfs the actual Opus/moq work. A
130/// small pool carries the same load with a fraction of that overhead.
131///
132/// All `spawn` sites in this module target this runtime, and `CallSession::join` is
133/// driven on it (so moq-net's internally-spawned session driver lands here too rather
134/// than on the FRB pool). `'static` so it is never dropped — dropping a runtime from
135/// within an async context panics, and FRB commands call us from async context.
136pub(crate) fn call_runtime() -> &'static tokio::runtime::Runtime {
137    static RT: std::sync::OnceLock<tokio::runtime::Runtime> = std::sync::OnceLock::new();
138    RT.get_or_init(|| {
139        tokio::runtime::Builder::new_multi_thread()
140            // 3 workers: 2 carry the steady control + video load with headroom; the
141            // third is margin so a high-bitrate screenshare's moq frame delivery —
142            // which can saturate a worker — cannot head-of-line-block the others on
143            // the same pool. NB: audio fill does not run here — it has its own RT
144            // runtime (`audio_runtime`) so video CPU can't starve voice ("audio is
145            // sacred").
146            .worker_threads(3)
147            .enable_all()
148            .thread_name("hound-call")
149            .build()
150            .expect("build dedicated call runtime")
151    })
152}
153
154/// The dedicated runtime for the audio RECEIVE/fill path (per-peer Opus decode → mix
155/// jitter buffer). Isolated from [`call_runtime`] and **real-time promoted** (each
156/// worker runs [`promote_current_thread_for_audio_fill`] on start) so a CPU-heavy
157/// screen-share decode/scale/render load can never deschedule the fill — the RT mix
158/// bus would otherwise find the jitter buffer dry at its 10 ms pull tick and the call
159/// audibly stutters (`mix_starve`). The playout (mix) side is already RT; this extends
160/// the same guarantee to the producer side. "Audio is sacred": video can freeze, voice
161/// cannot.
162///
163/// Two workers: the decode of a 20 ms Opus frame is sub-millisecond and mostly parked
164/// on the network, so a couple of RT threads comfortably carry many peers without any
165/// busy-loop that would starve the system. (Caveat: the shared moq/QUIC demux driver
166/// still runs on `call_runtime`; the jitter buffer absorbs brief demux delay, and RT
167/// decode here removes the dominant — CPU-bound — starvation source.)
168pub(crate) fn audio_runtime() -> &'static tokio::runtime::Runtime {
169    static RT: std::sync::OnceLock<tokio::runtime::Runtime> = std::sync::OnceLock::new();
170    RT.get_or_init(|| {
171        tokio::runtime::Builder::new_multi_thread()
172            .worker_threads(2)
173            .enable_all()
174            .thread_name("hound-audio-rx")
175            .on_thread_start(hound_engine::api::promote_current_thread_for_audio_fill)
176            .build()
177            .expect("build dedicated audio runtime")
178    })
179}

181// ─── Public seam: the decode → render sink (UI-free) ────────────────────────────
182
183/// The decode→render seam. The orchestration decodes remote video into tightly
184/// packed I420 and hands it here, keyed by a stream key (`"self"`, `"cam:{peer}"`,
185/// `"screen:{peer}"`). The FRB layer supplies an impl whose body calls
186/// `video_render::push_frame(key, w, h, i420)` — so this crate stays free of any
187/// texture/FFI dependency. The sink must be cheap and non-blocking (drop-oldest);
188/// it is called on a decode task, never on a real-time audio thread.
189pub trait VideoSink: Send + Sync + 'static {
190    /// Hand one decoded I420 frame to the renderer for `stream_key`. `i420` is
191    /// tightly packed: `w*h + 2*(w/2 * h/2)` bytes.
192    fn push_frame(&self, stream_key: &str, w: u32, h: u32, i420: Vec<u8>);
193
194    /// Zero-copy fast path: hand one decoded frame that is still GPU-resident
195    /// ([`RenderSurfaceHandle`]) so the renderer can sample it without a CPU
196    /// readback / colour conversion / re-upload. Returns `true` if the sink took
197    /// it. The default returns `false` ("I can't take a surface"), so the caller
198    /// falls back to [`Self::push_frame`] with materialized I420 — meaning software
199    /// decoders, non-GPU sinks (tests/headless), and platforms without a surface
200    /// renderer all keep working unchanged. The handle is valid only for the
201    /// duration of the call; an impl that keeps it must retain synchronously.
202    fn push_surface(&self, stream_key: &str, surface: RenderSurfaceHandle) -> bool {
203        let _ = (stream_key, surface);
204        false
205    }
206
207    /// Nothing is feeding `stream_key` any more — the renderer may release
208    /// everything it holds for it (a mailbox otherwise pins the last decoded frame:
209    /// on macOS a retained VideoToolbox decode-pool buffer, elsewhere a ~1.4 MB
210    /// I420 `Vec`, for the rest of the process).
211    ///
212    /// Called when a tile's LAST subscription goes away with no replacement: the
213    /// peer left, the track was withdrawn, the receiver's allocator hid the tile, or
214    /// video was paused. Deliberately NOT called for the losing half of a simulcast
215    /// LAYER SWITCH — that stops one track and starts another under the same stream
216    /// key in the same pass, and the mailbox is the seam the make-before-break
217    /// texture swap hands its first new frame through.
218    ///
219    /// Releasing can never blank a tile: what is on screen is the target buffer the
220    /// last frame was drawn INTO, not the mailbox (see `hound_render::drop_stream`).
221    ///
222    /// Default: no-op (tests/headless).
223    fn stream_ended(&self, stream_key: &str) {
224        let _ = stream_key;
225    }
226}

228/// A decoded frame still resident in a platform GPU buffer, handed to the renderer
229/// for a zero-copy sample (no NV12→I420 readback, no re-upload). One variant per
230/// GPU backend; a platform without a surface renderer never builds one (the
231/// [`VideoSink::push_surface`] default declines and the I420 path runs).
232///
233/// Designed once for all platforms: macOS/iOS today; Windows (D3D11 shared NV12)
234/// and Linux (dmabuf NV12) slot in as new variants behind the same seam.
235pub enum RenderSurfaceHandle {
236    /// macOS/iOS: an IOSurface-backed NV12 `CVPixelBuffer` (raw `CVPixelBufferRef`
237    /// as a pointer-sized int). The producer holds a +1 retain for the duration of
238    /// the `push_surface` call; the renderer wraps the two IOSurface planes (luma
239    /// R8, chroma RG8) as Metal textures on wgpu's device.
240    AppleCvPixelBuffer { ptr: usize, width: u32, height: u32 },
241    /// Windows: an NV12 `ID3D11Texture2D` on the engine's shared device (raw COM
242    /// pointer as a pointer-sized int). BORROWED — the frame's texture-pool lease
243    /// is what guards the texture against being rewritten, and that lease lives
244    /// on the frame, so the renderer must consume it synchronously inside the
245    /// `push_surface` call (it blits NV12→BGRA into the Flutter-shared target
246    /// there and then).
247    WindowsD3d11Nv12 { ptr: usize, width: u32, height: u32 },
248}
249
250impl RenderSurfaceHandle {
251    /// The platform surface handle for a GPU-resident frame, or `None` for byte
252    /// frames / platforms without a surface renderer (callers then take the
253    /// materialized-I420 [`VideoSink::push_frame`] fallback).
254    pub fn for_frame(frame: &hound_engine::types::RawFrame) -> Option<Self> {
255        let (width, height) = (frame.dims.width(), frame.dims.height());
256        let surface = frame.surface.as_ref()?;
257        if let Some(ptr) = surface.cv_pixel_buffer_ptr() {
258            return Some(Self::AppleCvPixelBuffer { ptr, width, height });
259        }
260        if let Some(ptr) = surface.d3d11_texture_ptr() {
261            return Some(Self::WindowsD3d11Nv12 { ptr, width, height });
262        }
263        None
264    }
265}

274/// The self-preview stream key, and the `cam:{peer}` / `screen:{peer}` builders —
275/// kept here so the key scheme has one source of truth across publish + subscribe.
276const SELF_KEY: &str = "self";
277fn cam_key(peer: PeerId) -> String {
278    format!("cam:{}", peer.0)
279}
280fn screen_key(peer: PeerId) -> String {
281    format!("screen:{}", peer.0)
282}

284/// The render stream key one remote video TILE draws into. A tile is a
285/// `(peer, source)` pair, not a track: the source and low simulcast layers of the
286/// same camera are two tracks feeding this one key, which is exactly why a layer
287/// switch is invisible to the renderer (see [`VideoSink::stream_ended`]).
288fn video_key(peer: PeerId, source: Source) -> String {
289    match source {
290        Source::Screen => screen_key(peer),
291        _ => cam_key(peer),
292    }
293}

295/// Which inbound-video stats bucket a remote video track feeds: a screen source is
296/// counted as [`InboundVideoKind::Screen`], everything else (camera) as `Camera`. So
297/// a peer publishing BOTH cam + screen has each tile's fps/bitrate reported from its
298/// own track, not the summed total.
299fn inbound_video_kind(source: Source) -> InboundVideoKind {
300    match source {
301        Source::Screen => InboundVideoKind::Screen,
302        _ => InboundVideoKind::Camera,
303    }
304}

326    /// (ui/integration_test), where motion is exactly what a diff can't
