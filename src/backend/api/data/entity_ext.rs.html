1//! Hand-written extensions to the generated entities in [`super::entity`].
2//!
3//! `mise run db:generate` deletes and rewrites `entity/` from the live schema,
4//! so nothing in there is ever edited by hand: derives and attributes are
5//! generator flags (see the task), and every method, invariant or note that
6//! belongs to an entity type lives here instead. The enums' variant names are
7//! derived from their database values, which is why those values are
8//! snake_case (`view_channels` becomes [`Permission::ViewChannels`]); the wire
9//! form is the database form.
10//!
11//! Semantics of the permission enums, since the generated file cannot carry
12//! per-variant documentation:
13//!
14//! [`Permission`] (community roles; stored in `role_permission` and the two
15//! overwrite tables):
16//! - `ManageCommunity`: community-level settings.
17//! - `ManageChannels`: create, delete and rename channels.
18//! - `ManageUsers`: kick members.
19//! - `ManageRoles`: create, delete and edit roles; assign permissions.
20//! - `ViewChannels`: view and read a channel (channel-applicable).
21//! - `SendMessages`: send messages in a channel (channel-applicable).
22//! - `ReadHistory`: read message history in a channel (channel-applicable).
23//! - `ManageMessages`: edit or delete other members' messages
24//!   (channel-applicable).
25//!
26//! [`InstancePermission`](super::entity::sea_orm_active_enums::InstancePermission) (scoped to the server instance, stored in
27//! `instance_user_permission`): `ManageCommunities` creates and deletes
28//! communities; `ManageInstance` manages instance-level settings.
29//!
30//! [`IdentityProvider`](super::entity::sea_orm_active_enums::IdentityProvider) (one `identity` row per login method; that table is
31//! the only one holding PII): `Email` signs in with a passkey ceremony keyed by
32//! the address; `Steam` with a Steamworks session ticket or Steam OpenID.
33
34use super::entity::sea_orm_active_enums::Permission;
35
36impl Permission {
37    /// Whether the permission can appear as a per-channel overwrite. The
38    /// community-only permissions (`ManageCommunity`, `ManageChannels`,
39    /// `ManageUsers`, `ManageRoles`) cannot be scoped to a single channel.
40    pub fn is_channel_applicable(self) -> bool {
41        matches!(
42            self,
43            Permission::ViewChannels
44                | Permission::SendMessages
45                | Permission::ReadHistory
46                | Permission::ManageMessages
47        )
48    }
49}
