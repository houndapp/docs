1//! # Cross-platform software H.264 (Cisco openh264)
2//!
3//! Software H.264 encode + decode via Cisco's [openh264] (the WebRTC baseline
4//! real-time codec), wired behind [`VideoEncode`] / [`VideoDecode`]. This is the
5//! path that completes functional video parity **wherever the hardware H.264
6//! codecs are absent** — Linux/Windows desktops (VideoToolbox is
7//! Apple-only; there is no MediaCodec/NVENC backend). The wire codec for
8//! all-Apple calls is H.264 (the encoder sends HW H.264, receivers pick the
9//! decoder by wire codec), so a Linux client needs H.264 **both ways** to join a
10//! call with a Mac: SW-encode H.264 to send, SW-decode H.264 to receive.
11//!
12//! ## The interop contract (why this matters)
13//!
14//! A Linux↔Mac call only works if the bytes are mutually decodable:
15//! * Mac VideoToolbox encodes H.264 Annex-B with SPS+PPS prepended on every IDR;
16//!   this decoder ([`Openh264Decoder`]) must decode exactly that.
17//! * This encoder ([`Openh264Encoder`]) must emit the SAME shape — Annex-B with
18//!   SPS+PPS in-band on every IDR — so a Mac's VideoToolbox decoder accepts it.
19//!
20//! openh264 satisfies both natively: its bitstream is Annex-B (4-byte
21//! `00 00 00 01` start codes) and, with the default `SpsPpsStrategy::ConstantId`,
22//! every IDR access unit carries SPS (NAL 7) + PPS (NAL 8) + the IDR slice
23//! (NAL 5) — byte-shape-identical to the VideoToolbox encoder's output. The
24//! engine's `h264_*` round-trip tests prove the cross-codec interop on this Mac
25//! (VT-encoded → openh264-decoded AND openh264-encoded → VT-decoded).
26//!
27//! ## Latency profile (why these settings)
28//! * `UsageType::CameraVideoRealTime` — the real-time usage scenario (no
29//!   buffering for look-ahead, single reference).
30//! * `Profile::Baseline` — no B-frames, no CABAC: lowest decode latency and the
31//!   widest-compatibility profile, matching the VideoToolbox path's
32//!   `Baseline_AutoLevel` SPS/PPS shape.
33//! * `skip_frames(false)` — never drop a frame to hit the rate target. For
34//!   real-time voice/video we'd rather briefly overshoot bitrate than starve the
35//!   receiver of a frame (a dropped frame is a freeze until the next one).
36//!   openh264 prints a one-line warning that bitrate can't be strictly held
37//!   without frame-skip; that is the intended tradeoff, and the encoder's trace
38//!   level is lowered so the warning does not spam.
39//! * `intra_frame_period` caps the GOP so a late joiner is never more than a few
40//!   seconds from a keyframe; [`request_keyframe`](Openh264Encoder::request_keyframe)
41//!   forces an IDR on demand (PLI relay) via `ForceIntraFrame`.
42//!
43//! ## Real-time-safety
44//! Runs on the dedicated capture/encode (or decode) thread, never async/UI. The
45//! encoder borrows the I420 planes zero-copy through [`YUVSlices`] (no RGB
46//! round-trip, no intermediate allocation beyond openh264's own bitstream
47//! buffer). The decoder copies the decoded planes out respecting openh264's
48//! internal (padded) stride into a tightly-packed I420 buffer — the same
49//! stride-respecting plane copy the NV12→I420 path does.
50//!
51//! ## LICENSING — where the codec comes from at runtime
52//!
53//! Cisco's H.264 patent grant rides on the **binary** `libopenh264` releases
54//! Cisco publishes, and only when that binary is *downloaded onto the end user's
55//! device*, separately from the product (openh264 BINARY_LICENSE condition 1 —
56//! which is why the blob is fetched at first run and never bundled into a
57//! release artifact). A **from-source** build carries no grant at all.
58//!
59//! So there is exactly ONE software H.264 implementation, in every build —
60//! development, CI and shipped alike (openh264's `libloading` backend; the
61//! `source` backend is not compiled anywhere, so no build of ours can contain a
62//! dormant H.264 codec). It is supplied at runtime, never at compile time:
63//!
64//! * [`install_blob`], via `Engine::set_openh264_blob` — what the app calls once
65//!   its first-run download lands, and
66//! * the `HOUND_OPENH264_PATH` env var, for every context with no app to run
67//!   that download: CI jobs, benches, and local development (`mise install`
68//!   fetches the blob and mise exports the variable — see the root `.mise.toml`).
69//!
70//! `OpenH264API::from_blob_path` SHA-256-verifies the file against the crate's
71//! baked allowlist of Cisco 2.6.0 releases, so a corrupt or substituted library
72//! is a typed error, never a load.
73//!
74//! ## Cost of the runtime load
75//!
76//! Every encoder/decoder construction re-reads the ~1.2 MB library, SHA-256s it
77//! and `dlopen`s it: roughly 1–3 ms, against ~0 for the old compiled-in build.
78//! That is per codec OBJECT, not per frame, so it lands on stream start and on
79//! an encoder rebuild (a BWE resolution-rung change forces one, with a 5 s dwell
80//! between rebuilds) — comfortably inside the IDR those already cost. It is NOT
81//! on any per-frame path. Caching the loaded API instead is not possible:
82//! `OpenH264API` owns its `libloading::Library`, is not `Clone`, and each
83//! encoder takes one by value.
84//!
85//! With no blob — a fresh install before the download completes — building a
86//! codec is a typed [`CaptureError::Unsupported`] and [`sw_h264_available`]
87//! reports `false`, so the capability probes stay honest: a client advertises no
88//! SW H.264 rather than promising peers a codec it cannot build.
89//!
90//! The user-facing kill switch required by BINARY_LICENSE conditions 2–4 is
91//! [`set_blob_enabled`]: turning the Cisco codec off makes the installed blob
92//! invisible to both the constructors and the capability probes.
93//!
94//! [openh264]: https://github.com/cisco/openh264
95

125/// Filesystem path of Cisco's `libopenh264` binary, installed once per process by
126/// [`install_blob`]. A `OnceLock` (not a parameter) deliberately: [`crate::Engine`]
127/// is a `Copy` ZST constructed ad hoc at ~30 call sites, so threading a codec path
128/// through the facade would touch every one of them for a process-global fact.
129///
130/// The **path** is stored rather than the loaded `OpenH264API`, because that type
131/// owns its `libloading::Library` and is neither `Clone` nor shareable — each
132/// encoder/decoder takes one by value. Re-loading per codec is cheap (`dlopen`
133/// refcounts an already-mapped library) and re-runs the SHA-256 check.
134static BLOB_PATH: OnceLock<PathBuf> = OnceLock::new();
135
136/// The user's kill switch for Cisco's binary codec (openh264 BINARY_LICENSE
137/// conditions 2–4 require one). While `false` the installed blob is invisible to
138/// both the codec constructors and [`sw_h264_available`]. There is no other
139/// software H.264 to fall back to, so off means none at all — which is exactly
140/// the user's stated choice.
141static BLOB_ENABLED: AtomicBool = AtomicBool::new(true);
142
143/// Escape hatch naming an already-downloaded Cisco binary, for contexts with no
144/// app to run the download: CI jobs (the blob comes from the `http:openh264` mise
145/// tool), benches, and offline dev. Same posture as `HOUND_APP_ROLE` /
146/// `HOUND_ZEROCOPY_VIDEO`. Consulted only when nothing was installed explicitly.
147const BLOB_PATH_ENV: &str = "HOUND_OPENH264_PATH";
148
149/// Install Cisco's `libopenh264` binary at `path` for the rest of the process.
150///
151/// Verifies eagerly — the library is loaded once here, so a bad SHA-256 (the
152/// crate's allowlist of Cisco 2.6.0 releases), a truncated download or a
153/// wrong-architecture file is a typed error at install time rather than a
154/// mysterious codec failure at call setup. Installing is idempotent for the same
155/// path; a *different* path after one is already live is refused (the first
156/// install may already back live encoders).
157pub(crate) fn install_blob(path: PathBuf) -> Result<(), CaptureError> {
158    // Load-and-drop: proves the blob is a well-known Cisco release AND that this
159    // host can actually map it, before anything depends on it.
160    load_blob(&path)?;
161    match BLOB_PATH.set(path) {
162        Ok(()) => Ok(()),
163        // `set` hands the value back on contention; compare rather than fail
164        // blind, so a re-install of the same cached file stays a no-op.
165        Err(rejected) if BLOB_PATH.get() == Some(&rejected) => Ok(()),
166        Err(_) => Err(CaptureError::Unsupported {
167            what: "replacing an already-installed openh264 binary",
168        }),
169    }
170}
171
172/// Turn Cisco's binary codec on/off at runtime (the settings toggle). Off also
173/// means "do not use a blob that is already installed" — the switch has to be
174/// effective, not merely advisory.
175pub(crate) fn set_blob_enabled(enabled: bool) {
176    BLOB_ENABLED.store(enabled, Ordering::Relaxed);
177}
178
179/// Whether Cisco's binary codec is currently permitted (the settings toggle).
180pub(crate) fn blob_enabled() -> bool {
181    BLOB_ENABLED.load(Ordering::Relaxed)
182}
183
184/// The Cisco binary this process should use right now, if any: the explicitly
185/// installed path, else [`BLOB_PATH_ENV`]. `None` when the user turned the codec
186/// off, when nothing is installed, or when the named file has since vanished.
187fn active_blob_path() -> Option<PathBuf> {
188    if !blob_enabled() {
189        return None;
190    }
191    // Existence is re-checked on every call, including for the installed path.
192    // The `OnceLock` cannot be un-set, but the FILE can go away underneath it —
193    // turning the setting off deletes it — so a stale slot would otherwise make
194    // `sw_h264_available` promise peers a codec that no longer loads, in the
195    // window between re-enabling the setting and the fresh download landing.
196    let path = match BLOB_PATH.get() {
197        Some(path) => path.clone(),
198        None => PathBuf::from(std::env::var_os(BLOB_PATH_ENV)?),
199    };
200    path.is_file().then_some(path)
201}
202
203/// Load (and SHA-256-verify) the Cisco binary at `path`.
204fn load_blob(path: &std::path::Path) -> Result<OpenH264API, CaptureError> {
205    OpenH264API::from_blob_path(path).map_err(|e| {
206        CaptureError::UnsupportedFormat(format!(
207            "openh264: cannot load the Cisco binary at {}: {e}",
208            path.display()
209        ))
210    })
211}
212
213/// The openh264 API backing a new encoder/decoder: the Cisco binary, or a typed
214/// error naming the one thing that fixes it. There is no compiled-in codec to
215/// fall back to — by design, since only Cisco's own binary carries their patent
216/// grant — so "not downloaded yet" is a legitimate state, not a bug.
217fn api() -> Result<OpenH264API, CaptureError> {
218    match active_blob_path() {
219        Some(path) => load_blob(&path),
220        None => Err(CaptureError::Unsupported {
221            what: "software H.264 (no Cisco openh264 binary: the app downloads one at first run; \
222                   elsewhere set HOUND_OPENH264_PATH — `mise install` fetches it)",
223        }),
224    }
225}

227/// Whether this process can build a SW H.264 codec **right now** — the honest
228/// input to `encode_caps`/`decode_caps`. False when the blob has not landed yet
229/// (or the user disabled it), where advertising H.264 would promise peers a codec
230/// we cannot construct.
231pub(crate) fn sw_h264_available() -> bool {
232    active_blob_path().is_some()
233}

239/// Software H.264 encoder (Cisco openh264). One per outbound video track. Not
240/// `Send` in our contract: construct, drive, and drop on the one encode thread.
241pub(crate) struct Openh264Encoder {
242    enc: Encoder,
243    width: usize,
244    height: usize,
245    /// Set by [`VideoEncode::request_keyframe`]; applied to the next frame as a
246    /// forced IDR, then cleared. The PLI throttle lives upstream, so by the time
247    /// a request reaches here it is already coalesced.
248    force_keyframe: bool,
249}
250
251impl Openh264Encoder {
252    /// Build a real-time SW H.264 encoder for `dims`@`fps` targeting `bitrate`,
253    /// with `cadence` governing self-refreshing IDRs ([`KeyframeCadence`] — the
254    /// shared per-content-type GOP policy; openh264 only takes a frame count, so
255    /// the cadence's frame bound is what maps here). Baseline profile, real-time
256    /// usage, SPS+PPS on every IDR (the in-band parameter-set contract the
257    /// decoder/session depends on). The geometry must match the [`RawFrame`]s
258    /// that will be fed.
259    pub(crate) fn new(
260        dims: Dimensions,
261        fps: Fps,
262        bitrate: Bitrate,
263        cadence: KeyframeCadence,
264    ) -> Result<Self, CaptureError> {
265        let (width, height) = (dims.width() as usize, dims.height() as usize);
266
267        let config = EncoderConfig::new()
268            // Real-time scenario: no multi-frame look-ahead buffering.
269            .usage_type(UsageType::CameraVideoRealTime)
270            // Baseline: no B-frames, no CABAC — lowest latency, matches the VT
271            // path's Baseline SPS/PPS so the two interop.
272            .profile(Profile::Baseline)
273            .max_frame_rate(FrameRate::from_hz(fps.get() as f32))
274            .bitrate(BitRate::from_bps(bitrate.bps()))
275            .rate_control_mode(RateControlMode::Bitrate)
276            // Never drop a frame to hit the rate target — a dropped frame is a
277            // receiver freeze. We accept a brief bitrate overshoot instead.
278            .skip_frames(false)
279            // The cadence's frame bound caps the GOP; on-demand keyframes still
280            // force an IDR sooner ([`VideoEncode::request_keyframe`]).
281            .intra_frame_period(IntraFramePeriod::from_num_frames(
282                cadence.max_interval_frames(fps),
283            ));
284
285        // Cisco's downloaded binary, or a typed error — there is no compiled-in
286        // codec to fall back to (see the crate-level LICENSING docs).
287        let enc = Encoder::with_api_config(api()?, config)
288            .map_err(|e| CaptureError::Encoder(format!("openh264 encoder init failed: {e}")))?;
289
290        Ok(Self {
291            enc,
292            width,
293            height,
294            force_keyframe: false,
295        })
296    }
297}

301impl VideoEncode for Openh264Encoder {
302    fn codec(&self) -> VideoCodec {
303        VideoCodec::H264
304    }
305
306    fn backend(&self) -> &'static str {
307        "openh264 (software)"
308    }
309
310    fn encode(&mut self, frame: &RawFrame) -> Result<Vec<EncodedChunk>, CaptureError> {
311        // openh264 takes I420. The HW encoder consumes capture-native NV12
312        // directly; the software path is the one place that pays the NV12→I420
313        // de-interleave, here (`as_i420` is a zero-copy borrow when the frame is
314        // already I420 — non-Apple capture / software-scaled frames).
315        let frame = frame.as_i420().ok_or_else(|| {
316            CaptureError::UnsupportedFormat(format!("openh264: cannot convert {:?} to I420", {
317                // `frame` is shadowed below; name the original format for the error.
318                frame.format
319            }))
320        })?;
321        if frame.width() as usize != self.width || frame.height() as usize != self.height {
322            // The capturer renegotiated geometry mid-stream (hot-swap / format
323            // change). We don't rebuild the encoder here; surface it rather than
324            // feed openh264 mismatched plane sizes (it would panic in YUVSlices).
325            return Err(CaptureError::UnsupportedFormat(format!(
326                "frame {} != encoder {}x{}",
327                frame.dims, self.width, self.height
328            )));
329        }
330
331        // Tightly-packed I420: Y (w*h) || U (w/2*h/2) || V (w/2*h/2), stride ==
332        // plane width. Validate the length before slicing so a short buffer is a
333        // typed error, never a panic / OOB (YUVSlices::new asserts exact sizes).
334        let (w, h) = (self.width, self.height);
335        let (cw, ch) = (w / 2, h / 2);
336        let y_size = w * h;
337        let c_size = cw * ch;
338        if frame.data.len() < y_size + 2 * c_size {
339            return Err(CaptureError::Encoder(format!(
340                "I420 buffer too small: {} < {}",
341                frame.data.len(),
342                y_size + 2 * c_size
343            )));
344        }
345        let y = &frame.data[..y_size];
346        let u = &frame.data[y_size..y_size + c_size];
347        let v = &frame.data[y_size + c_size..y_size + 2 * c_size];
348        // Zero-copy borrow of our planes; strides equal the plane widths.
349        let yuv = YUVSlices::new((y, u, v), (w, h), (w, cw, cw));
350
351        if self.force_keyframe {
352            self.enc.force_intra_frame();
353            self.force_keyframe = false;
354        }
355
356        let bitstream = self
357            .enc
358            .encode(&yuv)
359            .map_err(|e| CaptureError::Encoder(format!("openh264 encode failed: {e}")))?;
360
361        // openh264 emits one access unit per input frame (no B-frames at
362        // Baseline / real-time). A `Skip` frame type means it produced no
363        // bitstream this call (shouldn't happen with skip_frames(false), but be
364        // defensive); emit nothing rather than a zero-length chunk.
365        let frame_type = bitstream.frame_type();
366        if matches!(frame_type, FrameType::Skip) {
367            return Ok(Vec::new());
368        }
369
370        let data = bitstream.to_vec();
371        if data.is_empty() {
372            return Ok(Vec::new());
373        }
374
375        // IDR/I are keyframes (independently decodable); P references prior
376        // frames. The IDR access unit carries SPS+PPS in-band (ConstantId
377        // strategy default) — verified byte-for-byte in the unit tests.
378        let keyframe = matches!(frame_type, FrameType::IDR | FrameType::I);
379
380        Ok(vec![EncodedChunk {
381            data,
382            keyframe,
383            // The pipeline pairs each chunk with the source frame's timestamp;
384            // carry it straight through so A/V sync is preserved.
385            timestamp_us: frame.timestamp_us,
386        }])
387    }
388
389    fn request_keyframe(&mut self) {
390        self.force_keyframe = true;
391    }
392
393    fn set_bitrate(&mut self, _bitrate: Bitrate) -> Result<(), CaptureError> {
394        // The Cisco C encoder supports a live target-bitrate retarget
395        // (`ENCODER_OPTION_BITRATE` via `SetOption`), but the safe `openh264`
396        // crate exposes no wrapper for it — only the `unsafe fn raw_api()` raw
397        // FFI escape hatch. We deliberately keep this `generic` module free of
398        // raw FFI (the engine's unsafe lives only in the sealed platform sys
399        // layers, e.g. `apple/`), so we do NOT reach through `raw_api` here.
400        //
401        // Like the rav1e fallback, this is a no-op (not an error) so callers stay
402        // uniform: the live retarget is the HW encoders' (VideoToolbox) job and
403        // the Phase-4 BWE target; the SW path holds its configured rate. The
404        // churn test proves the stream stays decodable across repeated calls.
405        // If live SW retarget becomes load-bearing, expose it via a thin safe
406        // wrapper (upstream PR) or a tiny sealed FFI shim rather than inlining
407        // `unsafe` here.
408        Ok(())
409    }
410
411    fn flush(&mut self) -> Result<Vec<EncodedChunk>, CaptureError> {
412        // openh264 is a no-look-ahead, one-AU-per-frame encoder at Baseline /
413        // real-time: there is nothing buffered to drain at stream end.
414        Ok(Vec::new())
415    }
416}

422/// Software H.264 decoder (Cisco openh264). One per inbound video track. Decodes
423/// the Annex-B access units the encoders (this one OR VideoToolbox) emit — SPS/
424/// PPS arrive in-band on each IDR, so there is no separate bootstrap step: the
425/// decoder buffers internally until it has seen a keyframe and returns
426/// `Ok(None)` until then. Not `Send` in our contract.
427pub(crate) struct Openh264Decoder {
428    dec: Decoder,
429}
430
431impl Openh264Decoder {
432    /// Build a SW H.264 decoder. Infallible setup beyond openh264's own init;
433    /// the session needs no parameters up front (SPS/PPS are in-band).
434    pub(crate) fn new() -> Result<Self, CaptureError> {
435        let dec = Decoder::with_api_config(api()?, DecoderConfig::new())
436            .map_err(|e| CaptureError::Decoder(format!("openh264 decoder init failed: {e}")))?;
437        Ok(Self { dec })
438    }
439
440    /// Copy a decoded openh264 frame (planes at the decoder's internal, possibly
441    /// padded, stride) into a tightly-packed I420 [`RawFrame`]. Returns `None`
442    /// (rather than panicking) on a geometry that is not a valid 4:2:0
443    /// [`Dimensions`] or a plane shorter than its declared stride×height.
444    fn decoded_to_raw_frame(yuv: &openh264::decoder::DecodedYUV<'_>) -> Option<RawFrame> {
445        let (w, h) = yuv.dimensions();
446        let dims = Dimensions::try_new(w as u32, h as u32)?;
447        let (cw, ch) = (w / 2, h / 2);
448        let (sy, su, sv) = yuv.strides();
449        let (yp, up, vp) = (yuv.y(), yuv.u(), yuv.v());
450
451        // Bounds: each plane must cover stride × rows. openh264 guarantees this,
452        // but validate before indexing so a malformed frame is a skip, not OOB.
453        if sy < w || su < cw || sv < cw {
454            return None;
455        }
456        if yp.len() < sy * h || up.len() < su * ch || vp.len() < sv * ch {
457            return None;
458        }
459
460        // Build the tightly-packed buffer by APPENDING each row, rather than filling a
461        // `vec![0u8; total]` and overwriting it: every byte is written exactly once
462        // here, so pre-zeroing was a second full pass over 1.3 MB per 720p frame (a
463        // `calloc` the kernel must back with fresh pages) for no observable effect.
464        // Planes are appended in I420 order — all of Y, then all of U, then all of V —
465        // which is what the destination `split_at_mut` layout produced before.
466        let total = w * h + 2 * cw * ch;
467        let mut data = Vec::with_capacity(total);
468        // Y: drop the row padding (copy w bytes per row from a sy-stride source).
469        for row in 0..h {
470            data.extend_from_slice(&yp[row * sy..row * sy + w]);
471        }
472        // U/V: half-res planes, same stride-dropping copy.
473        for row in 0..ch {
474            data.extend_from_slice(&up[row * su..row * su + cw]);
475        }
476        for row in 0..ch {
477            data.extend_from_slice(&vp[row * sv..row * sv + cw]);
478        }
479        debug_assert_eq!(
480            data.len(),
481            total,
482            "I420 plane append must fill exactly {w}x{h} + 2x{cw}x{ch}"
483        );
484
485        Some(RawFrame {
486            dims,
487            format: PixelFormat::I420,
488            // The wire timestamp is carried alongside the chunk by the pipeline;
489            // the decoder does not thread it through openh264, so leave it zero
490            // and let the receive path stamp from the packet header (mirrors the
491            // VideoToolbox decoder).
492            timestamp_us: TimestampUs::ZERO,
493            captured_at: std::time::Instant::now(),
494            data,
495            surface: None,
496        })
497    }
498}

502impl VideoDecode for Openh264Decoder {
503    fn codec(&self) -> VideoCodec {
504        VideoCodec::H264
505    }
506
507    fn backend(&self) -> &'static str {
508        "openh264 (software)"
509    }
510
511    fn decode(&mut self, chunk: &[u8]) -> Result<Option<RawFrame>, CaptureError> {
512        if chunk.is_empty() {
513            return Ok(None);
514        }
515
516        // openh264 buffers internally and returns `Ok(None)` until it has the
517        // parameter sets + a keyframe; a mid-stream parameter-set change is
518        // absorbed the same way (the new SPS/PPS arrive in-band on the next IDR).
519        // Decode errors on garbage are caught and reported as a typed
520        // `Decoder` error — never a panic — so the receive loop can drop the AU
521        // and wait for the next keyframe.
522        match self.dec.decode(chunk) {
523            Ok(Some(yuv)) => Ok(Self::decoded_to_raw_frame(&yuv)),
524            Ok(None) => Ok(None),
525            Err(e) => Err(CaptureError::Decoder(format!(
526                "openh264 decode failed: {e}"
527            ))),
528        }
529    }

544    /// Split an Annex-B stream into NAL types (the low 5 bits of the first byte
545    /// of each NAL), accepting both 3- and 4-byte start codes. Test helper to
546    /// assert the in-band parameter-set shape.
547    fn annex_b_nal_types(stream: &[u8]) -> Vec<u8> {
548        let mut types = Vec::new();
549        let mut i = 0usize;
550        while i + 3 <= stream.len() {
551            let (is_start, len) = if stream[i] == 0 && stream[i + 1] == 0 && stream[i + 2] == 1 {
552                (true, 3)
553            } else if i + 4 <= stream.len()
554                && stream[i] == 0
555                && stream[i + 1] == 0
556                && stream[i + 2] == 0
557                && stream[i + 3] == 1
558            {
559                (true, 4)
560            } else {
561                (false, 0)
562            };
563            if is_start {
564                if let Some(&b) = stream.get(i + len) {
565                    types.push(b & 0x1f);
566                }
567                i += len;
568            } else {
569                i += 1;
570            }
571        }
572        types
573    }

718    /// The tightly-packed I420 layout contract, pinned byte-for-byte against the
719    /// straightforward "allocate zeroed, then index each plane" construction that
720    /// [`Openh264Decoder::decoded_to_raw_frame`] replaced with sequential appends.
721    /// The two must agree exactly — the append order (all Y, then all U, then all V)
722    /// is the only thing standing between this and a plane-swapped frame, and a
723    /// PSNR test would not catch a U/V swap on the near-flat chroma these fixtures use.
724    ///
725    /// Runs against a REAL `DecodedYUV` (padded, decoder-owned strides) rather than a
726    /// synthetic one, because dropping that row padding is exactly what is under test.
727    #[test]
728    fn decoded_frame_layout_matches_zeroed_plane_construction() {
729        let (w, h, fps) = (320u32, 240u32, 30u32);
730        let mut enc = Openh264Encoder::new(
731            Dimensions::new(w, h),
732            Fps::new(fps),
733            Bitrate::from_bps(1_000_000),
734            KeyframeCadence::MOTION,
735        )
736        .expect("build encoder");
737        let mut dec = Decoder::with_api_config(api().expect("openh264 api"), DecoderConfig::new())
738            .expect("build raw decoder");
739
740        let mut compared = 0usize;
741        for idx in 0..8 {
742            for chunk in enc.encode(&i420_frame(w, h, idx)).expect("encode") {
743                let Some(yuv) = dec.decode(&chunk.data).expect("decode") else {
744                    continue;
745                };
746                let got = Openh264Decoder::decoded_to_raw_frame(&yuv).expect("valid geometry");
747
748                // The prior construction, verbatim: zero-fill, split into planes, then
749                // copy each row out from under the decoder's stride.
750                let (dw, dh) = yuv.dimensions();
751                let (cw, ch) = (dw / 2, dh / 2);
752                let (sy, su, sv) = yuv.strides();
753                let (yp, up, vp) = (yuv.y(), yuv.u(), yuv.v());
754                // The whole point of this comparison is that row padding gets dropped,
755                // so fail loudly if openh264 ever hands back tightly-packed planes —
756                // otherwise the test would silently stop covering the stride case.
757                assert!(
758                    sy > dw && su > cw && sv > cw,
759                    "expected padded decoder strides, got y={sy}/{dw} u={su}/{cw} v={sv}/{cw} \
760                     — this test no longer covers stride-dropping"
761                );
762                let mut want = vec![0u8; dw * dh + 2 * cw * ch];
763                let (y_dst, rest) = want.split_at_mut(dw * dh);
764                let (u_dst, v_dst) = rest.split_at_mut(cw * ch);
765                for row in 0..dh {
766                    y_dst[row * dw..row * dw + dw].copy_from_slice(&yp[row * sy..row * sy + dw]);
767                }
768                for row in 0..ch {
769                    u_dst[row * cw..row * cw + cw].copy_from_slice(&up[row * su..row * su + cw]);
770                    v_dst[row * cw..row * cw + cw].copy_from_slice(&vp[row * sv..row * sv + cw]);
771                }
772
773                assert_eq!(
774                    got.data.len(),
775                    want.len(),
776                    "tight packing: Y ‖ U ‖ V with stride == width"
777                );
778                assert!(
779                    got.data == want,
780                    "frame {idx}: appended planes differ from the zeroed-plane layout"
781                );
782                compared += 1;
783            }
784        }
785        assert!(compared > 0, "no frame decoded — nothing was compared");
786    }

793    fn encode_decode_round_trip_psnr_and_timing() {
794        let (w, h, fps) = (640u32, 360u32, 30u32);
795        let mut enc = Openh264Encoder::new(
796            Dimensions::new(w, h),
797            Fps::new(fps),
798            Bitrate::from_bps(2_000_000),
799            KeyframeCadence::MOTION,
800        )
801        .expect("build encoder");
802        let mut dec = Openh264Decoder::new().expect("build decoder");
803
804        const FRAMES: usize = 30;
805        let mut decoded_count = 0usize;
806        let mut total_psnr = 0.0f64;
807        let mut total_mae = 0.0f64;
808        let mut encode_total = std::time::Duration::ZERO;
809        let mut decode_total = std::time::Duration::ZERO;
810        let mut max_encode = std::time::Duration::ZERO;
811        let mut pending_src: Vec<RawFrame> = Vec::new();
812
813        for idx in 0..FRAMES {
814            let src = i420_frame(w, h, idx);
815            let t0 = Instant::now();
816            let chunks = enc.encode(&src).expect("encode must not error");
817            let et = t0.elapsed();
818            encode_total += et;
819            max_encode = max_encode.max(et);
820            pending_src.push(src);
821
822            for chunk in chunks {
823                let t1 = Instant::now();
824                let decoded = dec.decode(&chunk.data).expect("decode must not error");
825                decode_total += t1.elapsed();
826                if let Some(frame) = decoded {
827                    let src = &pending_src[decoded_count];
828                    assert_eq!(frame.dims.wh(), (w, h), "decoded dims mismatch");
829                    assert_eq!(frame.format, PixelFormat::I420, "decoder must output I420");
830                    let expected =
831                        w as usize * h as usize + 2 * (w as usize / 2) * (h as usize / 2);
832                    assert_eq!(frame.data.len(), expected, "decoded I420 wrong size");
833                    total_mae += mean_abs_luma_error(src, &frame, w as usize, h as usize);
834                    total_psnr += luma_psnr_db(src, &frame, w as usize, h as usize);
835                    decoded_count += 1;
836                }
837            }
838        }
839
840        assert!(
841            decoded_count >= FRAMES - 2,
842            "decoded only {decoded_count}/{FRAMES} frames — expected ~1:1 post-bootstrap"
843        );
844
845        let mean_psnr = total_psnr / decoded_count as f64;
846        let mean_mae = total_mae / decoded_count as f64;
847        let mean_encode = encode_total / FRAMES as u32;
848        let mean_decode = decode_total / decoded_count as u32;
849
850        eprintln!(
851            "openh264 SW H.264 round-trip @ {w}x{h}: decoded {decoded_count}/{FRAMES}; \
852             mean luma MAE {mean_mae:.2}, mean luma PSNR {mean_psnr:.1} dB; \
853             encode mean {mean_encode:?}/frame (max {max_encode:?}), decode mean {mean_decode:?}/frame"
854        );
855
856        assert!(
857            mean_psnr > 30.0,
858            "mean luma PSNR {mean_psnr:.1} dB below 30 dB — SW H.264 decode does not match source"
859        );
860        // Timing is REPORTED (the eprintln above) but deliberately NOT
861        // asserted: the encode cost lives in the cc-built C library, compiled
862        // independently of the Rust profile (measured: zeroing the
863        // openh264/hound-engine opt-level overrides moves 640x360 encode only
864        // ~2.0 → 2.1 ms/frame), so a wall-clock bound here can only measure
865        // machine load — it flaked at ~50 ms/frame on a contended CI runner
866        // with the suite in parallel. The profile-override regression guard is
867        // `rav1e_encoder::encodes_720p_fast_when_optimized`, whose
868        // optimized/debug gap is ~100x and therefore load-immune.

1072    /// The cross-platform pin of the [`KeyframeCadence`] contract (openh264 is
1073    /// deterministic SW, so this runs everywhere, unlike the VideoToolbox pins):
1074    /// over the same 10 s of STATIC media (the same frame repeated — the
1075    /// screenshare-nobody-is-drawing-on case), `Periodic{4}` still salts the
1076    /// stream with self-refreshing IDRs while `OnDemand` emits ONLY the
1077    /// stream-start one — the "near-zero data on a static screenshare" property
1078    /// (each redundant IDR is the dominant static-content bandwidth waste).
1079    /// Static frames deliberately: openh264 also runs content-adaptive
1080    /// scene-change IDR detection, which moving content legitimately triggers —
1081    /// that adaptivity is kept (a real full-screen change deserves a refresh) and
1082    /// is exactly why the static case, not a moving pattern, is the contract.
1083    #[test]
1084    fn cadence_governs_self_refreshing_idrs() {
1085        let (w, h, fps) = (320u32, 240u32, 30u32);
1086        let count_idrs = |cadence: KeyframeCadence| -> usize {
1087            let mut enc = Openh264Encoder::new(
1088                Dimensions::new(w, h),
1089                Fps::new(fps),
1090                Bitrate::from_bps(500_000),
1091                cadence,
1092            )
1093            .expect("build openh264 encoder");
1094            let mut idrs = 0usize;
1095            let frame = i420_frame(w, h, 0); // identical content every frame
1096            for _ in 0..300 {
1097                for chunk in enc.encode(&frame).expect("encode") {
1098                    if chunk.keyframe {
1099                        idrs += 1;
1100                    }
1101                }
1102            }
1103            idrs
1104        };
1105
1106        let periodic = count_idrs(KeyframeCadence::Periodic { seconds: 4 });
1107        assert!(
1108            periodic >= 3,
1109            "Periodic{{4s}} must self-refresh over 10 s (got {periodic} IDRs)"
1110        );
1111        let on_demand = count_idrs(KeyframeCadence::OnDemand {
1112            safety_seconds: 60,
1113            max_gop_frames: 900,
1114        });
1115        assert_eq!(
1116            on_demand, 1,
1117            "OnDemand must emit only the stream-start IDR in 10 s"
1118        );
1119    }
