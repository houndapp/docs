1//! # Mixed-playout audio bus — one device stream + one coherent AEC reference
2//!
3//! All remote peers play through ONE mixed output stream. Echo cancellation
4//! requires it: [`Apm::process_render`] must be fed the one coherent stream the
5//! speaker actually plays — interleaving independent per-peer render references
6//! corrupts AEC3's canceller for any N>1. A single mixed playout makes the
7//! render reference exact for any N by construction, and halves the device
8//! handles (one stream per call, not one per peer).
9//!
10//! ## The tick model (PULL-based: the RT thread is the sole release clock)
11//!
12//! One dedicated playback thread per call owns the single [`CpalPlayback`]. It
13//! ticks on a **wall-clock 10 ms cadence** (the APM chunk size,
14//! [`MIX_CHUNK_SAMPLES`]) — driven by the OUTPUT side, never by peer frame
15//! arrival, because the cpal ring absorbs the jitter between the tick and the
16//! DAC. On each tick the bus, for EACH registered producer:
17//!
18//! 1. **pops every due frame from that peer's jitter buffer** on its OWN
19//!    real-time clock — `playout.pop_due_into(clock.now() + lookahead, …)` — appending the
20//!    released PCM to the slot's sample carry-queue, then drains up to
21//!    [`MIX_CHUNK_SAMPLES`] from the carry,
22//! 2. **sums** the producers sample-for-sample in **i32**, **soft-limits** the sum
23//!    (AGC2's limiter, as libwebrtc's `frame_combiner.cc` does) and converts to i16
24//!    with a saturating backstop — so N loud peers cost ~a dB of gain rather than a
25//!    flat-topped, broadband-distorted mix,
26//! 3. pushes the mixed chunk to the [`CpalPlayback`] ring, and
27//! 4. feeds what the ring ACCEPTED to [`Apm::process_render`] (the single coherent
28//!    reference — only what the speaker actually emits belongs in it).
29//!
30//! Usually that is exactly one chunk per tick, but the count is REGULATED by the
31//! device ring's depth ([`chunks_for_tick`]): the DAC drains on its own crystal and
32//! this thread refills on a software clock, so an open-loop one-chunk-per-tick push
33//! walks the ring either dry (continuous dropouts) or full (latency pinned at the
34//! ring depth, overproduction silently discarded). Feeding back off the depth also
35//! makes a scheduling stall recoverable — the drained cushion is replayed instead of
36//! being spent for the rest of the call.
37//!
38//! ### Why pull, not push
39//!
40//! A push design — a per-peer pump task (a normal async task) calling `pop_due_into`
41//! and PUSHING samples into the slot for this RT thread to drain — puts a
42//! **second, non-real-time scheduler on the release path**: under video-encode
43//! load the pump gets descheduled, feeds its slot late, and the RT drain finds
44//! the slot short — an audible per-peer gap (`mix_starves`) with the device ring
45//! still full (`output_underruns == 0`). No slot lead or cushion can fix that,
46//! because the producer's *timing* is the variable. Pull — the RT thread is the
47//! ONLY thing that calls `pop_due_into`, on its own steady clock — removes that
48//! scheduler from the release path entirely. The pump's sole job is to FILL
49//! the jitter buffer (network-paced; its scheduling never affects playout),
50//! and the jitter buffer IS the cushion that absorbs the pump's arrival jitter.
51//! Both push (pump) and pop (this thread) read the same `Copy` [`CaptureClock`],
52//! so the buffer's sender→local timeline mapping is consistent across the two
53//! threads.
54//!
55//! ### How the tick is paced
56//!
57//! The cadence comes from an ABSOLUTE deadline schedule ([`TickPacer`]): tick `n`
58//! is due at `epoch + n × MIX_TICK`, never at `now + MIX_TICK`, so a late wake is
59//! not folded into the next deadline and the grid cannot drift. Each tick waits
60//! coarsely to within [`SPIN_MARGIN`] of its deadline and then busy-waits the
61//! remainder, because the coarse wait only guarantees a LOWER bound on the delay:
62//! its overshoot is the OS timer granularity, which on Windows is 15.6 ms by
63//! default — three tick periods over the ask, landing straight in the tick-late
64//! histogram (and, downstream, in the receiver's decode-budget limitation signal).
65//! The coarse wait is therefore per-platform ([`CoarseWait`]): a plain `sleep` off
66//! Windows, and on Windows a **high-resolution waitable timer** whose ~0.5 ms
67//! accuracy is independent of that 15.6 ms clock.
68//!
69//! When **zero** producers are registered the bus STILL ticks (pushing silence),
70//! so the device stream and the AEC reference stay warm for the whole call —
71//! AEC3's delay/echo state does not have to re-converge each time the room goes
72//! briefly quiet or the last peer's pipeline is mid-rebuild.
73//!
74//! ## Registration + bounds
75//!
76//! A per-peer pipeline, instead of owning a playback thread, registers a
77//! [`BusProducer`] and PUSHES its decoded, timestamped PCM into the slot's jitter
78//! buffer via [`BusProducer::push`] (which also folds the arrival into the slot's
79//! [`AdaptiveJitter`] and reports back the depth/jitter for stats). The RT thread
80//! pulls from that buffer. The jitter buffer is bounded (drop-oldest at its frame
81//! cap) and the sample carry-queue is bounded to ~100 ms ([`SLOT_CAPACITY_SAMPLES`])
82//! drop-oldest, so one stalled or runaway peer can never grow the bus's memory.
83//! Dropping a [`BusProducer`] (its pipeline torn down / aborted) unregisters its
84//! slot from the bus, so a left peer stops contributing to the mix with no explicit
85//! teardown call.
86//!
87//! ## Hot-swap / vanish / reopen
88//!
89//! The bus thread owns the speaker [`DeviceChoice`] hot-swap, the vanished-device
90//! fallback (handled inside [`CpalPlayback::start`]), and the reopen backoff —
91//! in ONE place targeting the ONE stream. `call_set_speaker` nudges the shared `watch` sender;
92//! the bus thread re-opens the single device in place without disturbing the mix.
93//!
94//! Only a stream that actually DIED takes the immediate reopen. Everything the
95//! backend reports on a still-live stream — an automatic reroute, and the demoted
96//! quality faults (cpal `Xrun` / `RealtimeDenied`) — rides one debounce
97//! ([`RouteSettle`]) that collapses a burst into a single re-sync, because each
98//! reopen is itself a blocking device open on this real-time thread plus a fresh
99//! cushion prefill.
100//!
101//! Being the only party that sees a recovery's OUTCOME, this thread also owns the
102//! decision to report one: a stream error is logged at `warn` where it happens and
103//! only becomes an `error!` (a Sentry event) if playout is still down after the
104//! whole reopen ladder has run — see [`OutputHealth`].
105//!
106//! ## `!Send` discipline
107//!
108//! `cpal::Stream` is `!Send` on CoreAudio, so the [`CpalPlayback`] is constructed,
109//! driven, and dropped on the bus's own thread and never crosses a thread
110//! boundary. Producers (`Send`/`Sync`) only ever touch the bounded slot queues.
111//!
112//! ## Decoupling
113//!
114//! This module is deliberately free of session-specific types: it takes raw mono
115//! i16 PCM (`&[i16]`) in and plain handles out. The only audio dependencies are
116//! [`Apm`] (the render-reference sink) and [`CpalPlayback`] (the device), both
117//! behind narrow calls.

137/// Opens the output sink for a [`DeviceChoice`] on the bus thread, returning a
138/// boxed [`AudioOutput`] or the typed failure. Production passes
139/// [`cpal_sink_factory`] ([`CpalPlayback`]); tests inject a fake so they never
140/// touch a real (possibly sandbox-blocked) audio device. Runs ONLY on the bus
141/// thread, so the `!Send` `cpal::Stream` never crosses a thread boundary.
142///
143/// The failure is returned rather than swallowed because the bus — not the
144/// factory — decides whether a failed open is a hiccup or an outage worth an
145/// event, and the escalation has to be able to name the cause ([`OutputHealth`]).
146type SinkFactory =
147    Box<dyn FnMut(&DeviceChoice<SpeakerId>) -> Result<Box<dyn AudioOutput>, AudioError> + Send>;

149/// The production sink factory: open a [`CpalPlayback`] for the choice (with the
150/// vanish-fallback inside `open`), boxed as [`AudioOutput`].
151///
152/// A failure is logged at WARN, not error: the bus keeps ticking the AEC
153/// reference and retries on its backoff ladder, and most failures here are a
154/// device that is momentarily busy or mid-reroute. Only an outage that survives
155/// the ladder is escalated — see [`OutputHealth`].
156fn cpal_sink_factory() -> SinkFactory {
157    Box::new(
158        |choice: &DeviceChoice<SpeakerId>| match CpalPlayback::open(choice) {
159            Ok(playback) => {
160                tracing::info!(
161                    opened = playback.opened_name().unwrap_or("<unknown>"),
162                    "voice: mix-bus playback opened"
163                );
164                Ok(Box::new(playback) as Box<dyn AudioOutput>)
165            }
166            Err(e) => {
167                tracing::warn!("voice: mix-bus playback open failed ({e}) — retrying");
168                Err(e)
169            }
170        },
171    )
172}

202/// The wall-clock period the bus thread ticks at: 10 ms, matching

210/// How long before a tick's deadline [`TickPacer`] stops sleeping and busy-waits.
211///
212/// The trade is spin cost against release precision. Every coarse wait
213/// ([`CoarseWait`]) guarantees only a lower bound on the delay; the overshoot is the
214/// OS timer granularity, so a pure `sleep(deadline - now)` releases the tick a
215/// granularity-sized quantum LATE, every tick — 15.6 ms on default-configured
216/// Windows (worse than the 10 ms period itself), and hundreds of µs on a loaded
217/// mac/Linux box. Ending each wait in a busy loop makes the release precise to
218/// within the loop's own iteration cost regardless of the wait clock.
219///
220/// 1.5 ms on every platform. On Windows it is sized off the worst overshoot the bus
221/// can still see from [`CoarseWait`]: ~0.5 ms from the high-resolution waitable
222/// timer, or a 1 ms `timeBeginPeriod` quantum on the pre-1803 fallback — a full
223/// quantum with headroom either way, so the busy loop is entered before the deadline
224/// rather than after it. A smaller non-Windows margin was tried and measured out: at
225/// 300 µs a loaded mac released 2.3 ms late on average — macOS timer coalescing gives
226/// short sleeps multi-ms slop — so the margin that keeps the release precise is the
227/// same one everywhere. It is also the worst-case busy time per tick (15% of one
228/// core, only while a call runs the bus); the actual figure is lower, since the wait
229/// only spins the part of the margin the preceding coarse wait did not consume, and
230/// the [`SPIN_YIELD_FLOOR`] band yields rather than spins.
231const SPIN_MARGIN: Duration = Duration::from_micros(1_500);
232
233/// Inside [`SPIN_MARGIN`], the point at which the pacer stops offering the CPU to
234/// other threads and only spins. Above the floor a `yield_now` per iteration keeps
235/// the busy wait from starving a runnable sibling on a core-starved box (this thread
236/// is RT-priority — it can and will win the CPU outright); below it, `yield_now`'s
237/// own syscall cost is on the order of the remaining wait, so the cheaper
238/// `spin_loop` hint carries the last stretch to the deadline.
239const SPIN_YIELD_FLOOR: Duration = Duration::from_micros(200);
240
241/// How far PAST strictly-due the RT thread pops each tick: exactly one [`MIX_TICK`]
242/// (10 ms). A 20 ms audio frame spans two 10 ms ticks, so its due-instant lands
243/// between ticks for some phase offsets; a one-tick lookahead releases the next
244/// frame into the carry-queue *before* the carry can bottom out, so the slot
245/// always has a full chunk to drain regardless of how the frame-due phase aligns
246/// to the tick grid. Because the RT thread (not the pump) owns this read, the
247/// lookahead is immune to producer scheduling — it just smooths the frame/tick
248/// phase. Net latency is unchanged: a frame released `lookahead` early simply
249/// waits that long in the carry-queue instead of the jitter buffer.
250const MIX_PULL_LOOKAHEAD_US: i64 = MIX_TICK_MS as i64 * 1_000;
251
252/// Target depth of the output device ring the bus keeps filled (~3 chunks). The
253/// device drains the ring on its hardware clock while this thread refills it on a
254/// software clock; without a cushion the ring sits at ~0 and underruns on the
255/// slightest pacing jitter (or when encode load deschedules this thread). 30 ms
256/// absorbs normal jitter at a small, constant added output latency (AEC3 tolerates
257/// the fixed delay); the thread-priority promotion handles longer stalls.
258///
259/// The cushion is *regulated*, not merely seeded — see [`chunks_for_tick`].
260const OUTPUT_CUSHION_MS: u32 = 30;
261
262/// Dead band around [`OUTPUT_CUSHION_MS`] within which the tick pushes exactly one
263/// chunk. It must exceed one device callback (a cpal default buffer is ~10–21 ms),
264/// because the depth sampled at tick time swings by that much purely from the
265/// tick-vs-callback phase — a narrower band would toggle the regulator on phase
266/// noise instead of on real drift.
267const CUSHION_HYSTERESIS_MS: u32 = 15;

269/// Ceiling on chunks emitted in ONE tick while catching up. Each chunk is a full
270/// mix + AEC render pass, so an unbounded catch-up would turn a stall into a CPU
271/// spike on the RT thread. 4 (40 ms) restores the whole cushion from a dry ring in
272/// a single tick, which is the worst case the depth signal can report.
273const MAX_CHUNKS_PER_TICK: usize = 4;

275/// Per-producer slot bound: ~100 ms of 48 kHz mono audio (4800 samples). A
276/// drop-oldest policy keeps a stalled/runaway peer from growing the bus's memory;
277/// 100 ms is ~5 mix chunks of slack, enough to ride out a scheduling hiccup
278/// without unbounded growth.
279const SLOT_CAPACITY_SAMPLES: usize = (SAMPLE_RATE.hz() as usize / 1000) * 100;

281/// Recycled PCM buffers per slot: the pump allocates a frame's samples in
282/// [`Slot::push`] and the bus thread frees them after draining into the carry, so a
283/// small free-list keeps ~50 malloc/free per second per peer off the RT tick. Bounded
284/// (a runaway pump can't grow it) and best-effort (the RT side only `try_lock`s).
285const SLOT_POOL_CAP: usize = 8;

287/// Initial capacity of the bus thread's per-tick release scratch ([`MixScratch::due`]).
288/// A steady 10 ms tick releases 0 or 1 of a peer's 20 ms frames. The headroom is for the
289/// case that actually produces a burst: a DESCHEDULED tick, where everything that came
290/// due while the thread was off-CPU is released at once (bounded by the jitter buffer's
291/// `max_frames`, 256). Pre-sizing keeps the common tick off the allocator entirely; a
292/// long stall still grows the `Vec` a handful of times, once, and then never again.
293const MIX_DUE_SCRATCH_FRAMES: usize = 8;

295/// Initial capacity of the bus thread's per-tick glitch buffer. One tick can record at

297/// call (mic + screen audio per peer) without the allocator ever appearing on the RT
298/// path — least of all on the already-late tick that is doing the recording.

305/// Ceiling for the reopen backoff. A *persistently* unavailable output device
306/// (e.g. an ALSA `hw:` held exclusively by another process on Linux — where each
307/// failed open/close churn can itself prolong the `EBUSY`) must not retry at

313/// How long the non-fatal output-stream events must stay QUIET before the bus re-syncs
314/// its sink.
315///
316/// cpal's `ErrorKind::DeviceChanged` is informational — the stream was already rerouted
317/// and is still playing — so nothing is urgent. But the sink's geometry (`device_rate`,
318/// its 48 k→device resampler, and hence the scale of `buffered_ms`) still describes the
319/// OLD device, so a 48 k→24 k hop silently halves the cushion regulator's units. One
320/// reopen fixes that. `Xrun` / `RealtimeDenied` arrive on the same (still-live) stream
321/// and are demoted into this same window, where the eventual reopen's fresh cushion
322/// prefill is the only remedy on offer — and, since a persistent fault storm keeps
323/// pushing the deadline out, one that a sustained problem never triggers.
324///
325/// The debounce exists because a single Bluetooth connect/disconnect makes macOS move
326/// the default output repeatedly (5 changes in 50 s observed on AirPods). Each change
327/// PUSHES this deadline, so a whole flap burst costs ONE reopen instead of one per
328/// event — and each reopen is a blocking device open (up to ~1 s inside CoreAudio) on
329/// this real-time thread plus a fresh [`OUTPUT_CUSHION_MS`] prefill. 2 s is comfortably
330/// longer than the gaps within an observed burst and short enough that the stale
331/// geometry never outlives a call's cushion tuning.
332const ROUTE_SETTLE: Duration = Duration::from_secs(2);

390/// What an [`AudioGlitch`] is — the discrete audible-gap events the bus records, each
391/// already attributed to a stage so the debug report reads a cause, not a raw count.
392#[derive(Debug, Clone, Copy, PartialEq, Eq)]
393pub enum GlitchKind {
394    /// A primed slot came up short when the RT bus drained it: the per-peer jitter
395    /// buffer had nothing due (network starvation / buffer too shallow).
396    Underflow,
397    /// The 10 ms mix tick fired late (the RT feeder thread was descheduled) — a
398    /// device-side gap affecting ALL audio. `detail_us` is how late.
399    LateTick,
400    /// The output sink was torn down and re-opened (the stream died, or an automatic
401    /// route change settled and the device geometry had to be re-derived). The open is
402    /// a BLOCKING device call on the RT mix thread and is followed by a fresh
403    /// [`OUTPUT_CUSHION_MS`] silence prefill, so it shows up as a late tick + output
404    /// underruns — without this event those get misattributed to CPU contention.
405    /// Affects ALL audio; `detail_us` is how long the reopen took.
406    DeviceReopen,
407}

442/// One producer's per-peer slot. The PUMP pushes decoded, timestamped PCM into
443/// `state.buffer` (the jitter buffer); the BUS THREAD pops the due frames on its
444/// own real-time clock into `carry` and drains [`MIX_CHUNK_SAMPLES`] per tick. The
445/// two mutexes are each held only for a bounded op, never across IO; the producer
446/// is the async per-peer pump, the consumer is the bus's own thread (neither is a
447/// cpal RT callback).
448struct Slot {
449    /// Jitter buffer + adaptive depth. Pump writes (push), bus reads (pop_due_into).
450    state: Mutex<PlayoutState>,
451    /// Sample carry-queue between the 20 ms popped frames and the 10 ms drained
452    /// chunks. Touched ONLY by the bus thread, so it is uncontended — the mutex is
453    /// for the `Arc<Slot>` interior mutability, not cross-thread coordination.
454    carry: Mutex<VecDeque<i16>>,
455    /// Shared bus counter of mix STARVATION events: a tick where this slot was
456    /// primed (not idle) but its carry came up SHORT of a full chunk — a per-peer
457    /// audible gap. Held as a shared `Arc` so a dropped slot's events still count
458    /// toward the bus total. THIS is the per-peer stutter signal (distinct from the
459    /// output-ring underrun, which is the device-side gap). With the pull model a
460    /// rising count means the JITTER BUFFER itself ran dry (real network loss /
461    /// total starvation), not a producer-scheduling race.
462    starves: Arc<AtomicU64>,
463    /// THIS slot's own cumulative starve count (the shared `starves` above is the
464    /// bus-wide sum). Used only to attribute the aggregate to a source kind
465    /// ([`Self::label`]) so the stutter log can say WHICH audio starves — e.g. a
466    /// screen-share's intermittent app audio vs the remote mic (voice).
467    own_starves: AtomicU64,
468    /// A human label for the slot's source kind ("mic" / "screen_audio"), for the
469    /// per-kind starve breakdown. Static — the call sites pass a string literal.
470    label: &'static str,
471    /// DTX-aware starvation classifier (warmup gate + gap-onset window + recent-energy
472    /// silence discriminator). Touched ONLY by the bus thread each tick, so the mutex
473    /// is uncontended interior mutability over the `Arc<Slot>`, never cross-thread
474    /// coordination. See [`crate::audio::starve`].
475    starve: Mutex<StarveTracker>,
476    /// The control-plane peer id this slot's audio belongs to ([`NO_PEER_TAG`] if
477    /// registered untagged), so a recorded underflow [`AudioGlitch`] can name the peer.
478    peer_tag: u32,
479    /// Free-list of PCM buffers recycled from the bus thread's drain back to the
480    /// pump's push, so neither the allocation nor the free lands on the RT tick.
481    /// Bounded by [`SLOT_POOL_CAP`]; the RT side `try_lock`s and simply frees the
482    /// buffer when contended, so it can never block on the pump.
483    pool: Mutex<Vec<Vec<i16>>>,
484}

486impl Slot {
487    fn new(
488        starves: Arc<AtomicU64>,
489        playout_floor_us: i64,
490        label: &'static str,
491        peer_tag: u32,
492    ) -> Self {
493        Self {
494            state: Mutex::new(PlayoutState {
495                buffer: PlayoutBuffer::new(playout_floor_us),
496                adapt: AdaptiveJitter::with_floor(playout_floor_us),
497            }),
498            carry: Mutex::new(VecDeque::with_capacity(SLOT_CAPACITY_SAMPLES)),
499            starves,
500            own_starves: AtomicU64::new(0),
501            label,
502            starve: Mutex::new(StarveTracker::new()),
503            peer_tag,
504            pool: Mutex::new(Vec::with_capacity(SLOT_POOL_CAP)),
505        }
506    }
507
508    /// A slot with a throwaway starvation counter and a zero playout floor (release
509    /// ASAP) — for the mix/drain unit tests that seed the carry directly.
510    #[cfg(test)]
511    fn unmetered() -> Self {
512        Self::new(Arc::new(AtomicU64::new(0)), 0, "test", NO_PEER_TAG)
513    }
514
515    /// Producer side (pump): fold this frame's arrival into the adaptive jitter depth
516    /// and push it into the jitter buffer, both under one lock so the depth retarget
517    /// and the insert stay consistent. Returns the post-push depth + jitter estimate
518    /// for the caller's per-peer stats.
519    ///
520    /// The two clocks are deliberately separate, and both are on the shared
521    /// [`CaptureClock`] the bus thread pops against:
522    ///
523    /// * `arrival_us` — when the frame came off the WIRE, or `None` for a frame that
524    ///   never crossed it (locally CONCEALED audio; see [`BusProducer::push_concealed`]),
525    ///   which is folded into the buffer but never into the estimator. Only the jitter
526    ///   estimator sees this instant, and it must be the wire one, because that estimator
527    ///   is differential (`D = arrivalΔ − tsΔ`): feed it anything the receive pipeline
528    ///   delayed — or synthesized — and it measures the pipeline instead of the link.
529    /// * `now_us` — when the frame became available for PLAYOUT, i.e. now. This is what
530    ///   the buffer schedules and computes cushion against, so the cushion stays honest
531    ///   about how long the frame really has before it is due.
532    ///
533    /// They differ whenever something between the wire and here holds a frame — the
534    /// audio path's encoded reorder hold being the case that matters. See
535    /// [`BusProducer::push_at`].
536    fn push(
537        &self,
538        arrival_us: Option<i64>,
539        now_us: i64,
540        ts_us: i64,
541        samples: &[i16],
542    ) -> PushStatus {
543        // Own the samples BEFORE taking the lock: this copy must not happen inside
544        // `state.lock()`, which the RT mix pull also takes every 10 ms tick — an alloc
545        // under that lock would let a fill push briefly block the sacred playout
546        // thread. A recycled buffer from the pool (returned by the RT drain) usually
547        // makes it allocation-free entirely.
548        let mut buf = self
549            .pool
550            .lock()
551            .ok()
552            .and_then(|mut p| p.pop())
553            .unwrap_or_default();
554        buf.clear();
555        buf.extend_from_slice(samples);
556        let frame = MixFrame {
557            ts_us,
558            samples: buf,
559        };
560        // `ever_fed` is set when audio first REACHES the carry (the first release
561        // below), NOT here: a frame pushed now sits in the jitter buffer for ~target
562        // ms before it is due, and that intentional warmup delay must not count as
563        // starvation. Setting it on push would flag the whole warmup as a gap.
564        let Ok(mut st) = self.state.lock() else {
565            // poisoned ⇒ a prior op panicked; degrade rather than propagate.
566            return PushStatus {
567                jitter_us: 0,
568                buffered_frames: 0,
569                target_delay_us: 0,
570                recommended_delay_us: 0,
571                late_drops: 0,
572                overflow_drops: 0,
573                underflow_total: 0,
574            };
575        };
576        let PlayoutState { buffer, adapt } = &mut *st;
577        if let Some(arrival_us) = arrival_us {
578            adapt.on_frame(buffer, arrival_us, ts_us);
579        }
580        buffer.push(now_us, frame);
581        PushStatus {
582            jitter_us: adapt.jitter_us(),
583            buffered_frames: buffer.len() as u32,
584            target_delay_us: buffer.target_delay_us(),
585            recommended_delay_us: adapt.recommended_delay_us(),
586            late_drops: buffer.late_drops(),
587            overflow_drops: buffer.overflow_drops(),
588            // The slot's running starve count (updated by the RT pop) — read here so
589            // the per-peer underflow gauge advances without a second lock.
590            underflow_total: self.own_starves.load(Ordering::Relaxed),
591        }
592    }
593
594    /// Bus side (one tick): release every frame whose playout time has arrived (up
595    /// to `now_us + MIX_PULL_LOOKAHEAD_US`) into the carry-queue, then accumulate up
596    /// to `out.len()` carry samples into `out` (summing in i32), leaving the rest of
597    /// `out` untouched. Returns a [`PullOutcome`] (samples contributed + whether this
598    /// was an underflow), so the bus loop can record a per-peer glitch. Bumps the
599    /// shared starvation counter when a primed, non-idle slot comes up short — which,
600    /// under the pull model, means the jitter buffer genuinely had nothing due
601    /// (network starvation), not a producer-scheduling race.
602    ///
603    /// `due` is the bus loop's release scratch ([`MixScratch::due`]), reused across
604    /// every slot and every tick: this thread must not allocate, so the frames come
605    /// out via `pop_due_into` rather than a fresh `Vec` per call. The invariant is
606    /// **clear on entry**, which is what keeps one slot's released frames out of the
607    /// next slot's carry; draining them is best-effort, since a poisoned carry lock
608    /// leaves them in the scratch to be dropped by the next call's clear.
609    fn pull_into(&self, now_us: i64, out: &mut [i32], due: &mut Vec<MixFrame>) -> PullOutcome {
610        // 1) Release due frames from the jitter buffer into the carry (bounded).
611        // The jitter lock is held for the drain ONLY — the carry (and the pool
612        // `try_lock`) are touched after it is released, never nested under it.
613        due.clear();
614        if let Ok(mut st) = self.state.lock() {
615            st.buffer.pop_due_into(now_us + MIX_PULL_LOOKAHEAD_US, due);
616        }
617        if !due.is_empty()
618            && let Ok(mut q) = self.carry.lock()
619        {
620            for frame in due.drain(..) {
621                // Bulk-append the frame's samples, then trim the oldest past
622                // capacity in ONE drain (drop-oldest backpressure) — a single
623                // memcpy + bounds check per frame instead of one per sample.
624                let mut buf = frame.samples;
625                q.extend(buf.iter().copied());
626                if q.len() > SLOT_CAPACITY_SAMPLES {
627                    let excess = q.len() - SLOT_CAPACITY_SAMPLES;
628                    q.drain(..excess);
629                }
630                // Hand the buffer back to the pump instead of freeing it on this
631                // (RT) thread. Best-effort: `try_lock` so the RT tick never waits
632                // on the pump — a contended tick just drops the buffer as before.
633                buf.clear();
634                if let Ok(mut pool) = self.pool.try_lock()
635                    && pool.len() < SLOT_POOL_CAP
636                {
637                    pool.push(buf);
638                }
639            }
640        }
641
642        // 2) Drain a chunk from the carry into the mix accumulator, tracking the peak
643        // |sample| released so the starve classifier can tell speech from silence.
644        let want = out.len();
645        let mut peak_abs: i32 = 0;
646        let n = {
647            let Ok(mut q) = self.carry.lock() else {
648                return PullOutcome {
649                    contributed: 0,
650                    starved: false,
651                };
652            };
653            let n = want.min(q.len());
654            // Bulk-drain the oldest n samples into the mix accumulator (sum in i32),
655            // one pass instead of a per-sample pop_front.
656            for (slot, s) in out.iter_mut().zip(q.drain(..n)) {
657                *slot += s as i32;
658                let a = (s as i32).abs();
659                if a > peak_abs {
660                    peak_abs = a;
661                }
662            }
663            n
664        };
665
666        // 3) Starvation accounting (bus thread only) via the DTX-aware classifier: a
667        // dry/short carry counts as audible stutter only if real audio was recently
668        // playing — a silent peer's comfort-noise gaps are not stutter. The tracker
669        // owns the warmup gate + gap-onset window + silence discrimination.
670        let counted = self
671            .starve
672            .lock()
673            .map(|mut tr| {
674                tr.observe(Tick {
675                    contributed: n,
676                    want,
677                    peak_abs,
678                })
679            })
680            .unwrap_or(false);
681        if counted {
682            self.starves.fetch_add(1, Ordering::Relaxed);
683            self.own_starves.fetch_add(1, Ordering::Relaxed);
684        }
685        PullOutcome {
686            contributed: n,
687            starved: counted,
688        }
689    }
690
691    /// Test-only: seed the carry-queue directly (bypassing the jitter buffer) so the
692    /// pure sum/clamp/drain unit tests can drive the accumulator without scheduling.
693    /// The first `pull_into` that drains a sample marks the slot fed (via the
694    /// classifier), so starvation accounting goes live exactly as in production.
695    #[cfg(test)]
696    fn seed_carry(&self, samples: &[i16]) {
697        let mut q = self.carry.lock().unwrap();
698        for &s in samples {
699            if q.len() >= SLOT_CAPACITY_SAMPLES {
700                q.pop_front();
701            }
702            q.push_back(s);
703        }
704    }
705}

707/// A handle a per-peer pipeline holds to push its decoded PCM into the mix. Pushing
708/// is non-blocking and bounded (the jitter buffer + the ~100 ms carry are both
709/// drop-oldest). Dropping the handle unregisters the producer's slot from the bus
710/// (so a torn-down peer stops contributing with no explicit call) — the Drop-safe
711/// teardown the ghost discipline requires.
712pub struct BusProducer {
713    id: u64,
714    slot: Arc<Slot>,
715    registry: Arc<Registry>,
716}
717
718impl BusProducer {
719    /// Push one decoded audio frame into this producer's jitter buffer: `now_us` is
720    /// the local receive time and `ts_us` the sender's capture timestamp (BOTH on the
721    /// session's shared [`CaptureClock`], which the bus thread pops against), and
722    /// `samples` the 48 kHz mono PCM. Folds the arrival into the adaptive jitter depth
723    /// and returns the resulting depth/jitter for per-peer stats. The bus thread
724    /// releases the frame on its own real-time clock — the pump's scheduling never
725    /// affects playout timing.
726    ///
727    /// For a pipeline that pushes as soon as the frame lands, this is the whole story.
728    /// A pipeline that HOLDS frames before pushing must use [`Self::push_at`].
729    pub fn push(&self, now_us: i64, ts_us: i64, samples: &[i16]) -> PushStatus {
730        self.slot.push(Some(now_us), now_us, ts_us, samples)
731    }
732
733    /// [`Self::push`] for a pipeline that delays frames between the wire and here:
734    /// `arrival_us` is when the frame came off the wire, `now_us` when it reaches the
735    /// buffer.
736    ///
737    /// The jitter estimator is differential — it measures `arrivalΔ − tsΔ` — so it must
738    /// be fed the WIRE instant or it measures the receive pipeline instead of the link.
739    /// The audio path is exactly this case: its encoded reorder hold releases by COUNT,
740    /// so how long a frame waits depends on when the *next* frames arrive. Push both as
741    /// `now_us` and the hold's own release cadence is reported as transit deviation —
742    /// which, against a publisher that suppresses silence, means each 500 ms keepalive
743    /// contributes a ~500 ms "spike", the windowed peak pins the recommended depth at
744    /// its cap for the full peak window, and a peer who was merely quiet comes back with
745    /// half a second of latency stapled to their first word.
746    pub fn push_at(&self, arrival_us: i64, now_us: i64, ts_us: i64, samples: &[i16]) -> PushStatus {
747        self.slot.push(Some(arrival_us), now_us, ts_us, samples)
748    }
749
750    /// [`Self::push`] for audio the receiver FABRICATED rather than received: Opus PLC
751    /// concealment over a gap. It is scheduled and played like any other frame, but it
752    /// is never folded into the jitter estimator.
753    ///
754    /// A concealed frame has no arrival instant to fold. The only clock available at the
755    /// point it is synthesized is the pipeline's own `now`, and pushing that as an
756    /// arrival makes the estimator measure the receive path instead of the link twice
757    /// over: the pair (last real frame → first PLC frame) books the whole concealed gap
758    /// PLUS however long the reorder hold and the task scheduler took, and the pair
759    /// (last PLC frame → the real frame behind it) books the mirror image, because that
760    /// real frame's WIRE stamp predates the `now` the PLC was pushed with. Both are pure
761    /// artefacts — the wire event that triggered them deviated by microseconds. Measured
762    /// on a live call across a one-frame (30 ms) gap: D = +62.6 ms then −61.7 ms against
763    /// a true deviation of +0.9 ms, and since the estimator provisions for the windowed
764    /// MAX deviation, that single fabricated spike deepened the buffer to 142 ms and held
765    /// it there for the whole 90 s peak window. Concealment happens precisely when a link
766    /// is lossy, so feeding it back into the depth is also a feedback loop.
767    ///
768    /// Skipping the observation entirely (rather than inventing an arrival) is what keeps
769    /// the estimate honest: the next REAL frame is then differenced against the last real
770    /// one, so a concealed gap contributes `arrivalΔ − tsΔ ≈ 0` — which is correct, since
771    /// loss is not jitter.
772    pub fn push_concealed(&self, now_us: i64, ts_us: i64, samples: &[i16]) -> PushStatus {
773        self.slot.push(None, now_us, ts_us, samples)
774    }
775}

786/// The set of live producer slots, shared between the bus thread (which iterates
787/// it every tick) and `register`/`unregister` (called from the async subscribe
788/// loop as peers come and go). A `std::sync::Mutex` is right: the critical section
789/// is a `HashMap` insert/remove or a cheap clone of the slot `Arc`s, never held
790/// across IO.
791#[derive(Default)]
792struct Registry {
793    slots: Mutex<HashMap<u64, Arc<Slot>>>,
794}
795
796impl Registry {
797    /// Snapshot the current slots into a caller-owned buffer (cheap `Arc` clones), so
798    /// the tick iterates without holding the registry lock across the mix/APM/playback
799    /// work AND without allocating a fresh `Vec` on the RT thread every 10 ms.
800    fn snapshot_into(&self, out: &mut Vec<Arc<Slot>>) {
801        out.clear();
802        if let Ok(g) = self.slots.lock() {
803            out.extend(g.values().cloned());
804        }
805    }
806
807    /// Allocating [`Self::snapshot_into`], for the non-RT callers (stats, tests).
808    fn snapshot(&self) -> Vec<Arc<Slot>> {
809        let mut out = Vec::new();
810        self.snapshot_into(&mut out);
811        out
812    }
813
814    fn unregister(&self, id: u64) {
815        if let Ok(mut g) = self.slots.lock() {
816            g.remove(&id);
817        }
818    }
819}

1117/// Pull one mixed [`MIX_CHUNK_SAMPLES`]-sample chunk from the snapshot's slots at
1118/// local time `now_us`: each slot releases its due jitter-buffered frames (on the
1119/// RT clock) into its carry-queue and accumulates a chunk in i32 (no overflow on N
1120/// loud peers), then **soft-limits** the sum and converts to i16. A slot with
1121/// nothing due contributes silence. Returns the mixed chunk.
1122///
1123/// The limiter is libwebrtc's mixer shape (`frame_combiner.cc`): straight sum →
1124/// AGC2 limiter → saturating convert. Without it the i16 conversion IS the
1125/// overload behaviour — a hard clip, whose flat tops are broadband distortion
1126/// across every peer at once. That was survivable only while every source was
1127/// quiet; it is not once the capture chain hits its loudness target, which is why
1128/// this landed with the gain raise (see `audio::apm`).
1129///
1130/// Allocation-free given a warm [`MixScratch`] and a `glitches` buffer with capacity
1131/// (the bus loop pre-sizes both — see [`TICK_GLITCH_CAPACITY`]), except for one
1132/// 1-element `Vec` of channel views that `Limiter::process` builds internally per
1133/// call. Not pure: the limiter carries gain state ACROSS chunks (its whole point —
1134/// a per-chunk-independent gain would step audibly at chunk boundaries), so the
1135/// bus loop's several catch-up chunks must run through the same [`MixScratch`], in
1136/// order. `now_us` still makes the release schedule explicit/testable.
1137fn mix_chunk(
1138    slots: &[Arc<Slot>],
1139    now_us: i64,
1140    scratch: &mut MixScratch,
1141    glitches: &mut Vec<AudioGlitch>,
1142) -> [i16; MIX_CHUNK_SAMPLES] {
1143    let MixScratch {
1144        acc,
1145        due,
1146        limit,
1147        limiter,
1148    } = scratch;
1149    acc.fill(0);
1150    for slot in slots {
1151        let outcome = slot.pull_into(now_us, acc, due);
1152        if outcome.starved {
1153            // Record a per-peer underflow at the moment it happened, attributed to
1154            // the slot's peer + source kind (the bus loop drains these into the ring).
1155            glitches.push(AudioGlitch {
1156                at_us: now_us,
1157                peer_tag: slot.peer_tag,
1158                label: slot.label,
1159                kind: GlitchKind::Underflow,
1160                detail_us: 0,
1161            });
1162        }
1163    }
1164    // The limiter works in libwebrtc's FloatS16 domain — float values on the i16
1165    // scale — so the i32 accumulator crosses to f32 for the gain pass and back.
1166    // Below the knee (~0 dBFS) it looks up an exact 1.0 and this is a no-op round
1167    // trip; above it, it spends gain instead of flat-topping the waveform.
1168    for (f, &sum) in limit.iter_mut().zip(acc.iter()) {
1169        *f = sum as f32;
1170    }
1171    // RT caveat: `Limiter::process` collects a 1-element `Vec` of channel views per
1172    // call — the only allocator touch left on the tick, and it comes from inside
1173    // the crate. Bounded and tiny (one 16-byte alloc per 10 ms chunk), but it IS an
1174    // allocation on an RT-promoted thread; if the tick-lateness histogram ever
1175    // implicates it, the fix is a fork or a hand-rolled gain-curve pass.
1176    limiter.process(&mut [limit.as_mut_slice()]);
1177    let mut out = [0i16; MIX_CHUNK_SAMPLES];
1178    for (o, &f) in out.iter_mut().zip(limit.iter()) {
1179        // The limiter already clamps to the FloatS16 rails, so this normally only
1180        // rounds — but it stays SATURATING as the backstop: no change upstream may
1181        // ever wrap a sample to the opposite sign.
1182        *o = f.round().clamp(i16::MIN as f32, i16::MAX as f32) as i16;
1183    }
1184    out
1185}

1187/// Everything one mix tick reuses so the RT bus thread allocates nothing. Owned by
1188/// the bus loop for the life of the thread and threaded through [`mix_chunk`].
1189struct MixScratch {
1190    /// Per-tick i32 accumulator the slots sum into (i32 so N loud peers cannot wrap
1191    /// before the limiter sees the true sum).
1192    acc: [i32; MIX_CHUNK_SAMPLES],
1193    /// Frames released from ONE slot's jitter buffer this tick — `pop_due_into`'s
1194    /// destination, cleared and drained per slot. Pre-sized ([`MIX_DUE_SCRATCH_FRAMES`])
1195    /// so a steady tick never grows it; only a descheduled tick's catch-up burst can,
1196    /// and only until it has grown once.
1197    due: Vec<MixFrame>,
1198    /// FloatS16 view of [`Self::acc`] the limiter gain-scales in place (it works in
1199    /// float on the i16 scale, not in normalised float).
1200    limit: [f32; MIX_CHUNK_SAMPLES],
1201    /// The mix bus's output limiter — AGC2's, the same one the capture chain ends
1202    /// in. STATEFUL across chunks (gain smoothing, attack/decay envelope), so there
1203    /// is exactly one per bus thread and every chunk of every tick goes through it
1204    /// in order. [`MIX_CHUNK_SAMPLES`] is its frame size: 480 = 10 ms @ 48 kHz,
1205    /// which is also its maximum and divides its 20 sub-frames evenly.
1206    limiter: Limiter,
1207}
1208
1209impl MixScratch {
1210    fn new() -> Self {
1211        Self {
1212            acc: [0i32; MIX_CHUNK_SAMPLES],
1213            due: Vec::with_capacity(MIX_DUE_SCRATCH_FRAMES),
1214            limit: [0.0f32; MIX_CHUNK_SAMPLES],
1215            limiter: Limiter::new(MIX_CHUNK_SAMPLES),
1216        }
1217    }
1218}

1220/// Pre-fill a freshly-opened output sink's ring with [`OUTPUT_CUSHION_MS`] of
1221/// SILENCE — the cushion's initial condition, from which [`chunks_for_tick`] holds it
1222/// closed-loop. Silence (not slot audio) means the pre-fill costs nothing from any
1223/// peer's stream; it is a fixed ~cushion of added output latency, which AEC absorbs.
1224fn prefill_output(playback: &mut Option<Box<dyn AudioOutput>>) {
1225    if let Some(p) = playback.as_mut() {
1226        let silent = chunk_to_frame(vec![0i16; MIX_CHUNK_SAMPLES]);
1227        for _ in 0..(OUTPUT_CUSHION_MS / MIX_TICK_MS) {
1228            let _ = p.play(&silent);
1229        }
1230    }
1231}

1233/// How many mixed chunks this tick should push, from the sink's reported ring depth
1234/// (`depth_ms`, sampled BEFORE the push) and how late the tick fired (`late_us`).
1235///
1236/// This is the closed loop around [`OUTPUT_CUSHION_MS`]. The bus produces on a
1237/// software 10 ms clock while the DAC drains on its own crystal, so one chunk per
1238/// tick is only right if the two rates match exactly. They never do: tens of ppm is
1239/// normal (far worse on an OS-resampled BT/HFP route), and open-loop the ring walks
1240/// to one of the two ends within minutes — dry (continuous fine-grained dropouts,
1241/// which `diagnose()` then misattributes to the device/route) or full (output latency
1242/// pinned at the ring depth, with the overproduction silently discarded).
1243///
1244/// * depth ABOVE the dead band ⇒ push **nothing**. The chunk is not mixed at all, so
1245///   no audio is lost: the slots simply keep it and the whole playout timeline slips
1246///   10 ms later, which is exactly the correction a slow DAC needs.
1247/// * depth BELOW it ⇒ push the deficit as extra chunks (bounded by
1248///   [`MAX_CHUNKS_PER_TICK`]). The extra chunks come from the slots' carry, which is
1249///   where a stall's un-drained backlog sits — so catching the ring up also drains
1250///   the backlog instead of leaving it as permanent added latency.
1251/// * a LATE tick means the device drained for `late_us` with no refill; replay those
1252///   chunks even when the depth reading has not caught up yet, so a scheduling stall
1253///   costs a one-time gap rather than the cushion for the rest of the call.
1254///
1255/// `depth_ms == None` (a sink that cannot report depth — the synthetic/null sinks)
1256/// keeps the previous strictly-open-loop behaviour: exactly one chunk per tick.
1257fn chunks_for_tick(depth_ms: Option<u32>, late_us: u128) -> usize {
1258    let Some(depth) = depth_ms else {
1259        return 1;
1260    };
1261    if depth > OUTPUT_CUSHION_MS + CUSHION_HYSTERESIS_MS {
1262        return 0;
1263    }
1264    // Below the band: refill the whole shortfall to target (floored to whole chunks,
1265    // so the correction converges on the cushion instead of overshooting past it).
1266    let deficit_chunks = if depth + CUSHION_HYSTERESIS_MS < OUTPUT_CUSHION_MS {
1267        ((OUTPUT_CUSHION_MS - depth) / MIX_TICK_MS) as usize
1268    } else {
1269        0
1270    };
1271    let late_chunks = (late_us / (MIX_TICK_MS as u128 * 1_000)) as usize;
1272    (1 + deficit_chunks.max(late_chunks)).min(MAX_CHUNKS_PER_TICK)
1273}

1436/// The bus tick's clock: an ABSOLUTE deadline schedule with a precise wait.
1437///
1438/// Deadlines accumulate from a fixed epoch (`epoch + n × period`) rather than from
1439/// each wake (`now + period`). The difference is drift: with a per-iteration
1440/// re-anchor every wake's error — sleep overshoot, the mix work itself — is added
1441/// permanently to the schedule, so a 10 ms tick that wakes 300 µs late runs at an
1442/// effective 10.3 ms and the bus underfeeds the device by 3% forever. Accumulating
1443/// from the epoch makes a late tick self-correcting: the NEXT deadline is where it
1444/// always was, so the following wait is simply shorter.
1445///
1446/// [`TickPacer::pace`] is the wait itself — a coarse [`CoarseWait`] down to
1447/// [`SPIN_MARGIN`], then busy-wait to the deadline (see that constant for the trade).
1448struct TickPacer {
1449    /// Anchor the schedule is measured from. Re-anchored only by an overrun (see
1450    /// [`TickPacer::advance`]).
1451    epoch: Instant,
1452    /// Which tick since `epoch` is currently due: the deadline is `epoch + n × period`.
1453    n: u32,
1454    period: Duration,
1455    /// The platform mechanism for the coarse half of each wait. Owned here so its
1456    /// (Windows) OS handle lives exactly as long as the pacing does, and so nothing
1457    /// else on the RT path has to know which mechanism is in play.
1458    waiter: CoarseWait,
1459}
1460
1461impl TickPacer {
1462    /// Start the schedule at `now`; the first deadline is one `period` out. Acquires
1463    /// the platform coarse-wait mechanism (a syscall on Windows) once, here — never
1464    /// per tick.
1465    fn new(now: Instant, period: Duration) -> Self {
1466        Self {
1467            epoch: now,
1468            n: 1,
1469            period,
1470            waiter: CoarseWait::acquire(),
1471        }
1472    }
1473
1474    /// The instant the currently-due tick is scheduled for.
1475    fn deadline(&self) -> Instant {
1476        self.epoch + self.period * self.n
1477    }
1478
1479    /// Wait until the current deadline. Returns immediately if it has already passed
1480    /// (an overrun — the caller's catch-up path owns that case).
1481    fn pace(&self) {
1482        let deadline = self.deadline();
1483        loop {
1484            let now = Instant::now();
1485            if now >= deadline {
1486                return;
1487            }
1488            let remaining = deadline - now;
1489            if remaining > SPIN_MARGIN {
1490                // Coarse: hand the CPU back for everything but the last margin. Wakes
1491                // late by the wait mechanism's granularity, which the margin is sized
1492                // to absorb; the loop re-checks the deadline either way, so an early
1493                // or late return only shifts work between the coarse and busy halves.
1494                self.waiter.wait(remaining - SPIN_MARGIN);
1495            } else if remaining > SPIN_YIELD_FLOOR {
1496                std::thread::yield_now();
1497            } else {
1498                std::hint::spin_loop();
1499            }
1500        }
1501    }
1502
1503    /// Move to the next tick. If that deadline is ALREADY past — the tick body ran
1504    /// longer than a whole period, i.e. the thread was descheduled — re-anchor the
1505    /// schedule to `now` instead of trying to replay the missed ticks back to back.
1506    fn advance(&mut self, now: Instant) {
1507        // `n` is re-anchored long before it could overflow in practice (a call would
1508        // have to run ~500 days without a single overrun); the check keeps the
1509        // multiply in `deadline` total regardless.
1510        if self.n == u32::MAX {
1511            self.re_anchor(now);
1512            return;
1513        }
1514        self.n += 1;
1515        if self.deadline() < now {
1516            self.re_anchor(now);
1517        }
1518    }
1519
1520    /// Restart the schedule from `now` (next deadline one period out).
1521    fn re_anchor(&mut self, now: Instant) {
1522        self.epoch = now;
1523        self.n = 1;
1524    }
1525}

1527/// The coarse half of [`TickPacer::pace`]: wait *most* of the remaining time, which
1528/// the pacer's busy tail then finishes precisely. Acquired once per pacer, never per
1529/// tick — the tick path must not allocate or open handles.
1530///
1531/// Off Windows this is `std::thread::sleep`: its overshoot (hundreds of µs on a
1532/// loaded mac/Linux box) already fits inside [`SPIN_MARGIN`].
1533#[cfg(not(windows))]
1534struct CoarseWait;
1535
1536#[cfg(not(windows))]
1537impl CoarseWait {
1538    fn acquire() -> Self {
1539        Self
1540    }
1541
1542    fn wait(&self, d: Duration) {
1543        std::thread::sleep(d);
1544    }
1545}

1547/// Windows coarse wait: a **high-resolution waitable timer**
1548/// (`CREATE_WAITABLE_TIMER_HIGH_RESOLUTION`, Windows 10 1803+).
1549///
1550/// Windows' default timer granularity is 15.6 ms — a plain `sleep` on the bus thread
1551/// overshoots to the next quantum, which is longer than the entire 10 ms tick period.
1552/// [`SPIN_MARGIN`] cannot absorb that (a 15.6 ms margin would mean spinning the whole
1553/// tick), which is the tick-late tail this platform used to show. A high-resolution
1554/// waitable timer signals to within ~0.5 ms *independently* of that clock, so the
1555/// coarse wait lands inside the margin without perturbing the system timer at all.
1556///
1557/// Pre-1803 (where the flag is rejected) falls back to the older mechanism: pull the
1558/// timer granularity itself to 1 ms with `timeBeginPeriod`
1559/// ([`WindowsTimerResolution`]) and keep sleeping. The raise is acquired ONLY on that
1560/// path — it is process-wide and costs idle power, and the timer makes it unnecessary.
1561///
1562/// RT-safety: no allocation, no lock, and no unbounded wait on the tick path — the
1563/// handle is created in [`Self::acquire`], each tick issues one `SetWaitableTimer` +
1564/// one `WaitForSingleObject` with a finite timeout, and every failure mode degrades to
1565/// `sleep` rather than blocking the mix thread.
1566///
1567/// Not unit-testable here (no Windows runner in the unit suite) — the validation
1568/// channel is nightly Windows telemetry: the mix-tick-late p95 gauge (the same
1569/// signal the receiver's decode budget calibrates against) must sit near zero
1570/// rather than near the granularity.
1571#[cfg(windows)]
1572struct CoarseWait {
1573    /// The timer handle, or `None` where the high-resolution flag was refused.
1574    timer: Option<windows::Win32::Foundation::HANDLE>,
1575    /// Held only on the fallback path (see the type doc); dropped with the pacer.
1576    _resolution: Option<WindowsTimerResolution>,
1577}
1578
1579#[cfg(windows)]
1580impl CoarseWait {
1581    fn acquire() -> Self {
1582        use windows::Win32::System::Threading::{
1583            CREATE_WAITABLE_TIMER_HIGH_RESOLUTION, CreateWaitableTimerExW, TIMER_ALL_ACCESS,
1584        };
1585
1586        // SAFETY: a plain kernel32 call with no in/out buffers. A null name asks for an
1587        // unnamed, process-private timer; the returned handle is owned by `self` and
1588        // closed exactly once, in `Drop`.
1589        let timer = unsafe {
1590            CreateWaitableTimerExW(
1591                None,
1592                windows::core::PCWSTR::null(),
1593                CREATE_WAITABLE_TIMER_HIGH_RESOLUTION,
1594                TIMER_ALL_ACCESS.0,
1595            )
1596        }
1597        .ok();
1598
1599        let _resolution = match timer {
1600            Some(_) => {
1601                tracing::info!(
1602                    "voice: mix tick paced by a high-resolution waitable timer (system \
1603                     timer resolution left alone)"
1604                );
1605                None
1606            }
1607            None => {
1608                tracing::info!(
1609                    "voice: high-resolution waitable timer unavailable — pacing the mix \
1610                     tick with a 1 ms timeBeginPeriod instead"
1611                );
1612                WindowsTimerResolution::acquire(1)
1613            }
1614        };
1615        Self { timer, _resolution }
1616    }
1617
1618    fn wait(&self, d: Duration) {
1619        use windows::Win32::System::Threading::{SetWaitableTimer, WaitForSingleObject};
1620
1621        let Some(timer) = self.timer else {
1622            std::thread::sleep(d);
1623            return;
1624        };
1625        // Due time is in 100 ns units; NEGATIVE means "relative to now" (a positive
1626        // value would be an absolute FILETIME). Round UP so the timer cannot signal
1627        // before the requested delay.
1628        let due: i64 = -(d.as_nanos().div_ceil(100).min(i64::MAX as u128) as i64);
1629        // SAFETY: `timer` is a live handle owned by `self`; `due` outlives the call; no
1630        // completion APC is supplied, so nothing escapes into a kernel callback.
1631        if unsafe { SetWaitableTimer(timer, &due, 0, None, None, false) }.is_err() {
1632            std::thread::sleep(d);
1633            return;
1634        }
1635        // Bounded on purpose: a timer that somehow never signals degrades to an
1636        // ordinary coarse wait instead of wedging the RT mix thread. The +2 ms keeps
1637        // the bound from pre-empting a timer that is about to fire.
1638        let cap_ms = (d.as_millis().min(u32::MAX as u128) as u32).saturating_add(2);
1639        // SAFETY: waiting on a handle this type owns, with a finite timeout.
1640        let _ = unsafe { WaitForSingleObject(timer, cap_ms) };
1641    }
1642}
1643
1644#[cfg(windows)]
1645impl Drop for CoarseWait {
1646    fn drop(&mut self) {
1647        if let Some(timer) = self.timer {
1648            // SAFETY: closes the handle `acquire` created, exactly once.
1649            unsafe {
1650                let _ = windows::Win32::Foundation::CloseHandle(timer);
1651            }
1652        }
1653    }
1654}

1656/// Raises the Windows multimedia timer resolution to 1 ms for as long as it is
1657/// held, and restores it on drop. The pre-1803 fallback for [`CoarseWait`] — see
1658/// that type for when it is (and is not) acquired.
1659///
1660/// The effect is process-wide, and historically was system-wide — hence the RAII
1661/// scoping to the bus thread's lifetime (a live call), never the app's. Since
1662/// Windows 10 2004 the raised resolution applies to the requesting process rather
1663/// than globally, so a modern box pays nothing for other apps; the scoping still
1664/// matters for this process's own idle power.
1665#[cfg(windows)]
1666struct WindowsTimerResolution {
1667    period_ms: u32,
1668}
1669
1670#[cfg(windows)]
1671impl WindowsTimerResolution {
1672    /// Best-effort: a driver may refuse the requested period, in which case the
1673    /// pacer still works — just with coarser sleeps eating into the spin margin.
1674    fn acquire(period_ms: u32) -> Option<Self> {
1675        // SAFETY: a plain C call taking a scalar; the matching `timeEndPeriod` is
1676        // issued exactly once, from this type's `Drop`.
1677        let rc = unsafe { windows::Win32::Media::timeBeginPeriod(period_ms) };
1678        if rc == windows::Win32::Media::TIMERR_NOERROR {
1679            Some(Self { period_ms })
1680        } else {
1681            tracing::warn!(rc, period_ms, "voice: timeBeginPeriod refused");
1682            None
1683        }
1684    }
1685}
1686
1687#[cfg(windows)]
1688impl Drop for WindowsTimerResolution {
1689    fn drop(&mut self) {
1690        // SAFETY: pairs the successful `timeBeginPeriod` in `acquire`.
1691        unsafe {
1692            let _ = windows::Win32::Media::timeEndPeriod(self.period_ms);
1693        }
1694    }
1695}

1697/// The bus thread body: own the single output sink (opened via `sink_factory`,
1698/// with the speaker hot-swap / vanish-fallback / reopen-backoff), and every
1699/// [`MIX_TICK`] sum the producers into one chunk, feed it
1700/// to the APM render reference once, and play it. Ticks silence with zero
1701/// producers so the device stream + AEC reference stay warm. The `!Send` sink
1702/// never leaves this thread.
1703#[allow(clippy::too_many_arguments)]
1704fn mix_bus_loop(
1705    stop: Arc<AtomicBool>,
1706    mut speaker_rx: watch::Receiver<DeviceChoice<SpeakerId>>,
1707    apm: Option<Arc<Apm>>,
1708    registry: Arc<Registry>,
1709    clock: CaptureClock,
1710    ticks: Arc<AtomicU64>,
1711    output_underruns: Arc<AtomicU64>,
1712    output_overruns: Arc<AtomicU64>,
1713    output_soft_faults: Arc<AtomicU64>,
1714    tick_late_lat: Arc<Mutex<hound_media::LatencyHistogram>>,
1715    glitch_ring: Arc<Mutex<VecDeque<AudioGlitch>>>,
1716    mut sink_factory: SinkFactory,
1717) {
1718    // Promote this thread to real-time scheduling: it feeds the output device ring on
1719    // a 10 ms software clock, and if video-encode load deschedules it the ring drains
1720    // and the device plays silence (the under-load playout stutter the instrumentation
1721    // showed spiking when a 60 fps screen share starts). The cpal output callback is
1722    // already RT; this lets its feeder keep up. Best-effort — a failure just logs and
1723    // runs at normal priority (the output cushion still absorbs ordinary jitter). The
1724    // handle must stay alive for the thread's lifetime to hold the policy.
1725    let _rt_handle = match audio_thread_priority::promote_current_thread_to_real_time(
1726        MIX_CHUNK_SAMPLES as u32,
1727        SAMPLE_RATE.hz(),
1728    ) {
1729        Ok(h) => {
1730            tracing::info!("voice: mix-bus thread promoted to real-time priority");
1731            Some(h)
1732        }
1733        Err(e) => {
1734            tracing::warn!("voice: mix-bus RT priority unavailable ({e:?}) — normal priority");
1735            None
1736        }
1737    };
1738
1739    let mut choice = speaker_rx.borrow().clone();
1740    // Tracks whether the output device is UP, and escalates an outage the reopen
1741    // ladder cannot fix (the only path from this thread to a Sentry event).
1742    let mut health = OutputHealth::default();
1743    let mut playback = open_sink(&mut sink_factory, &choice, &mut health, Instant::now());
1744    prefill_output(&mut playback);
1745    // One-shot reopen for a non-48k (BT/HFP) output whose route may not be live yet.
1746    let mut warmup_reopen = warmup_reopen_at(&playback, Instant::now());
1747    // Debounce for OS route changes (see `RouteSettle` / `ROUTE_SETTLE`).
1748    let mut route_settle = RouteSettle::default();
1749    let mut last_open_attempt = Instant::now();
1750    // Exponential reopen backoff: doubles from REOPEN_BACKOFF up to
1751    // REOPEN_BACKOFF_MAX while the device stays down, resets on a successful
1752    // open or a hot-swap. Stops the persistent-failure log/device-churn storm.
1753    let mut reopen_backoff = REOPEN_BACKOFF;
1754
1755    // Reused scratch so the per-tick mix allocates nothing — neither in the i32
1756    // accumulate nor in releasing each slot's due frames.
1757    let mut scratch = MixScratch::new();
1758    // Reused per-tick glitch buffer — empty in steady state, filled only on the rare
1759    // tick that has an underflow / late slip, then drained into the ring. Pre-sized
1760    // because that tick is by definition ALREADY struggling: growing the `Vec` there
1761    // would put the allocator on the RT path at exactly the wrong moment. A tick can
1762    // record at most one glitch per slot plus the late-tick one.
1763    let mut tick_glitches: Vec<AudioGlitch> = Vec::with_capacity(TICK_GLITCH_CAPACITY);
1764    // Reused wrapper buffer for the mixed chunk fed to the APM + device each tick, so
1765    // the RT thread allocates nothing per tick.
1766    let mut mixed_buf: Vec<i16> = Vec::with_capacity(MIX_CHUNK_SAMPLES);
1767    // Reused silence buffer for the render reference while no sink is open.
1768    let mut silence_buf: Vec<i16> = Vec::with_capacity(MIX_CHUNK_SAMPLES);
1769    // Reused registry snapshot (see `Registry::snapshot_into`).
1770    let mut slots: Vec<Arc<Slot>> = Vec::new();
1771    // Owns the platform coarse-wait mechanism (`CoarseWait`) for the bus thread's
1772    // lifetime: on Windows a high-resolution waitable timer, so the coarse half of
1773    // each wait lands inside `SPIN_MARGIN` instead of three tick periods past it.
1774    // Dropped with this frame — the OS handle never outlives the call.
1775    let mut pacer = TickPacer::new(Instant::now(), MIX_TICK);
1776
1777    while !stop.load(Ordering::Relaxed) {
1778        // Pace to the next 10 ms boundary (output-side cadence) off the absolute
1779        // deadline schedule; the cpal ring absorbs the residual jitter between this
1780        // and the DAC.
1781        let now = Instant::now();
1782        // How late this tick fired vs its 10 ms schedule: 0 when on-time/early, > 0
1783        // only when the RT thread was descheduled past its deadline (the device ring
1784        // then drains → all audio stutters). Record BEFORE pacing so the value is
1785        // the real slip, not the post-wait alignment. One uncontended lock/tick,
1786        // same discipline as the per-slot locks already on this path.
1787        let late_us = now.saturating_duration_since(pacer.deadline()).as_micros();
1788        if let Ok(mut h) = tick_late_lat.lock() {
1789            h.record(late_us.min(u64::MAX as u128) as u64);
1790        }
1791        pacer.pace();
1792        // Advance the schedule; if we fell badly behind (e.g. the thread was
1793        // descheduled), `advance` re-anchors to now so we don't spin catching up.
1794        let tick_at = Instant::now();
1795        pacer.advance(tick_at);
1796
1797        // Hot-swap: a changed speaker choice re-opens the single output device in
1798        // place (vanish-fallback lives in `CpalPlayback::start`).
1799        if speaker_rx.has_changed().unwrap_or(false) {
1800            choice = speaker_rx.borrow_and_update().clone();
1801            tracing::info!(?choice, "voice: speaker hot-swap requested (mix bus)");
1802            // Dropping the old sink releases the device on this (owning)
1803            // thread before the new one opens.
1804            drop(playback.take());
1805            playback = open_sink(&mut sink_factory, &choice, &mut health, tick_at);
1806            prefill_output(&mut playback);
1807            // A user-picked device may also be a BT headset needing the warmup reopen.
1808            warmup_reopen = warmup_reopen_at(&playback, Instant::now());
1809            // The explicit swap already re-derived the geometry any pending route
1810            // re-sync was going to fix.
1811            route_settle.disarm();
1812            last_open_attempt = Instant::now();
1813            reopen_backoff = REOPEN_BACKOFF;
1814        }
1815
1816        // One-shot warmup reopen: a non-48k (BT/HFP) output stream that opened onto a
1817        // not-yet-live SCO route plays silence and never errors, so the `is_dead`
1818        // reopen below never fires. Reopen it ONCE after the route has had time to
1819        // settle (the automatic equivalent of the rejoin that "fixes" it). Not
1820        // re-armed afterwards — a single nudge, no reopen loop.
1821        if let Some(at) = warmup_reopen
1822            && Instant::now() >= at
1823        {
1824            warmup_reopen = None;
1825            if playback.is_some() {
1826                tracing::info!(
1827                    "voice: warmup reopen of non-48k (BT/HFP) output — first-connect audio fix"
1828                );
1829                drop(playback.take());
1830                playback = open_sink(&mut sink_factory, &choice, &mut health, Instant::now());
1831                prefill_output(&mut playback);
1832                route_settle.disarm();
1833                last_open_attempt = Instant::now();
1834                reopen_backoff = REOPEN_BACKOFF;
1835            }
1836        }
1837
1838        // Mix on THIS real-time clock: each peer releases its due jitter-buffered
1839        // frames (`pop_due_into(clock.now() + lookahead, …)`) and we sum a 10 ms chunk + feed
1840        // one AEC render reference per chunk. This thread is the SOLE release
1841        // authority — the per-peer pumps only FILL the jitter buffers, so no
1842        // non-real-time scheduler sits on the playout path (one there gaps playout
1843        // audibly whenever it is descheduled).
1844        //
1845        // How MANY chunks is decided by the device-ring depth, not by the tick alone:
1846        // the cushion pre-filled at open is REGULATED from here (see
1847        // `chunks_for_tick`), because the DAC's crystal and this software clock drift
1848        // and an open-loop one-chunk-per-tick push walks the ring dry or full.
1849        let now_us = clock.now();
1850        registry.snapshot_into(&mut slots);
1851        tick_glitches.clear();
1852        let depth_ms = playback.as_ref().and_then(|p| p.buffered_ms());
1853        for _ in 0..chunks_for_tick(depth_ms, late_us) {
1854            // Mix + collect any per-peer underflow glitches (into the reused buffer —
1855            // empty in steady state). Wrap for the APM + device reusing `mixed_buf`'s
1856            // allocation (the frame is built from the taken buffer, reclaimed below).
1857            let mixed = mix_chunk(&slots, now_us, &mut scratch, &mut tick_glitches);
1858            mixed_buf.clear();
1859            mixed_buf.extend_from_slice(&mixed);
1860            let frame = chunk_to_frame(std::mem::take(&mut mixed_buf));
1861            // Play FIRST, then feed the render reference. A sink that partially
1862            // overran still gets the WHOLE chunk as reference: the dropped tail
1863            // shifts the played timeline by a few samples, which AEC3's adaptive
1864            // delay search re-tracks — whereas skipping the chunk leaves a hole
1865            // in the reference cadence that stalls the canceller for every
1866            // frame after it. Overruns stay counted either way.
1867            let played = match playback.as_mut() {
1868                Some(p) => {
1869                    let _ = p.play(&frame);
1870                    let dropped = p.take_output_overruns();
1871                    if dropped > 0 {
1872                        output_overruns.fetch_add(dropped, Ordering::Relaxed);
1873                    }
1874                    true
1875                }
1876                None => false,
1877            };
1878            if let Some(apm) = apm.as_ref() {
1879                if played {
1880                    apm.process_render(&frame);
1881                } else {
1882                    // No sink (device down / reopen backoff): nothing reaches the
1883                    // speaker, so the truthful reference is SILENCE. Still fed every
1884                    // chunk, so AEC3's render cadence stays warm across the outage.
1885                    silence_buf.clear();
1886                    silence_buf.resize(MIX_CHUNK_SAMPLES, 0);
1887                    let silent = chunk_to_frame(std::mem::take(&mut silence_buf));
1888                    apm.process_render(&silent);
1889                    silence_buf = silent.samples;
1890                }
1891            }
1892            // Reclaim the buffer for the next chunk (no allocator traffic on the RT path).
1893            mixed_buf = frame.samples;
1894        }
1895        // A meaningfully-late tick (the RT feeder slipped) is itself a glitch affecting
1896        // ALL audio — record it once with how late it was. Sub-threshold scheduling
1897        // noise (≲ half a tick) is ignored so the log stays signal.
1898        if late_us >= TICK_LATE_GLITCH_US {
1899            tick_glitches.push(AudioGlitch {
1900                at_us: now_us,
1901                peer_tag: NO_PEER_TAG,
1902                label: "tick",
1903                kind: GlitchKind::LateTick,
1904                detail_us: late_us.min(i64::MAX as u128) as i64,
1905            });
1906        }
1907        if !tick_glitches.is_empty()
1908            && let Ok(mut ring) = glitch_ring.lock()
1909        {
1910            for g in tick_glitches.drain(..) {
1911                if ring.len() >= GLITCH_RING_CAP {
1912                    ring.pop_front();
1913                }
1914                ring.push_back(g);
1915            }
1916        }
1917        if let Some(p) = playback.as_ref() {
1918            // Fold the device-side gap (silence the RT callback had to insert since
1919            // last tick) into the shared counter the app surfaces.
1920            let under = p.take_output_underruns();
1921            if under > 0 {
1922                output_underruns.fetch_add(under, Ordering::Relaxed);
1923            }
1924            // Non-fatal faults the sink demoted rather than dying on (cpal `Xrun` /
1925            // `RealtimeDenied`). Counted here so the demotion stays measurable — a
1926            // sustained storm keeps pushing the debounce out and so never produces the
1927            // reopen that would otherwise be its only trace.
1928            let soft = p.take_soft_faults();
1929            if soft > 0 {
1930                output_soft_faults.fetch_add(soft, Ordering::Relaxed);
1931            }
1932            // Neither an AUTOMATIC reroute nor a demoted quality fault is a death: the
1933            // stream is still live and playing. After a reroute what went stale is our
1934            // GEOMETRY — the sink's `device_rate`, its 48 k→device resampler, and hence
1935            // the millisecond scale of the `buffered_ms` the cushion regulator above
1936            // reads (a 48 k→24 k hop halves it); after an xrun / refused RT promotion
1937            // the remedy worth having is a fresh cushion. Both want the SAME thing: not
1938            // a teardown here, just (re-)arm the debounce and re-sync once it goes quiet.
1939            // A continuous fault storm never goes quiet, so it never reopens at all —
1940            // which is correct, since reopening under sustained xruns only thrashes.
1941            if p.take_route_changed() {
1942                let flapping = route_settle.due.is_some();
1943                route_settle.note_change(Instant::now());
1944                if !flapping {
1945                    tracing::info!(
1946                        soft_faults = soft,
1947                        "voice: output reported a non-fatal condition (auto-reroute, or \
1948                         an xrun / refused RT promotion) — stream still live; device \
1949                         re-sync armed in {:?}",
1950                        ROUTE_SETTLE
1951                    );
1952                }
1953            }
1954            // A dead stream (the device vanished / the config was invalidated) leaves
1955            // this sink object alive but draining nothing — drop it so the reopen path
1956            // below re-opens the current device. Otherwise output stays silent until a
1957            // manual speaker hot-swap. A real death OUTRANKS a pending re-sync: the
1958            // reopen below already gives us fresh geometry.
1959            if p.is_dead() {
1960                // The cause was captured by the stream's error callback (which only
1961                // warned — recovery had not been tried yet); carry it so an outage
1962                // that never recovers can name what actually broke.
1963                let cause = p.take_stream_error();
1964                tracing::warn!(
1965                    cause = cause.as_deref().unwrap_or("<no error captured>"),
1966                    "voice: output stream died — reopening the device"
1967                );
1968                health.died(Instant::now(), cause);
1969                drop(playback.take());
1970                route_settle.disarm();
1971                // Leave `last_open_attempt` alone (it is the last *successful* open,
1972                // long ago for a stream that ran fine) so the reopen path below fires
1973                // on the NEXT tick rather than after a backoff; reset the ladder so a
1974                // genuinely-down device still backs off from the fast cadence.
1975                reopen_backoff = REOPEN_BACKOFF;
1976            }
1977        }
1978        // The route has been quiet for `ROUTE_SETTLE`: rebuild the sink ONCE against the
1979        // device the OS finally landed on, so `dev_rate`/resampler/cushion geometry
1980        // describe it. Deliberately NOT conditioned on the new default device's rate
1981        // matching the old one: querying that would mean a blocking CoreAudio property
1982        // read on this real-time thread, which is exactly the cost this whole change is
1983        // removing. One unconditional reopen per settled burst (5 → 1) is the trade.
1984        if route_settle.fire(Instant::now()) && playback.is_some() {
1985            tracing::info!("voice: output route settled — re-opening the sink to re-sync geometry");
1986            drop(playback.take());
1987            reopen_backoff = REOPEN_BACKOFF;
1988        }
1989        ticks.fetch_add(1, Ordering::Relaxed);
1990
1991        // No live device: retry opening the current choice on an exponential
1992        // backoff (the vanished named speaker falls back to default inside
1993        // `start`). On success reset to the fast cadence; on continued failure
1994        // grow toward the cap so a persistently-held device is a slow heartbeat,
1995        // not a 2 Hz storm.
1996        if playback.is_none()
1997            && !stop.load(Ordering::Relaxed)
1998            && last_open_attempt.elapsed() >= reopen_backoff
1999        {
2000            let began = Instant::now();
2001            playback = open_sink(&mut sink_factory, &choice, &mut health, began);
2002            prefill_output(&mut playback);
2003            // Re-arm the one-shot BT/HFP warmup. This reopen can land on a 24 kHz SCO
2004            // route that is not carrying audio yet — exactly the initial-open case — and
2005            // without this the reopened sink plays silence forever with no error to
2006            // trigger another one. Safe from a reopen loop BECAUSE of the route debounce
2007            // above: a flap burst coalesces into a single reopen, so the warmup arms once
2008            // per settled route rather than once per reroute event.
2009            warmup_reopen = warmup_reopen_at(&playback, Instant::now());
2010            last_open_attempt = Instant::now();
2011            reopen_backoff = if playback.is_some() {
2012                // A reopen is an audible event in its own right (a blocking device open on
2013                // this RT thread + a fresh silence prefill), so record it — otherwise the
2014                // resulting tick slip and output underruns get diagnosed as CPU
2015                // contention. Only successful opens are recorded; failed retries are the
2016                // backoff ladder's business, not the glitch log's.
2017                record_glitch(
2018                    &glitch_ring,
2019                    AudioGlitch {
2020                        at_us: clock.now(),
2021                        peer_tag: NO_PEER_TAG,
2022                        label: "output",
2023                        kind: GlitchKind::DeviceReopen,
2024                        detail_us: began.elapsed().as_micros().min(i64::MAX as u128) as i64,
2025                    },
2026                );
2027                REOPEN_BACKOFF
2028            } else {
2029                (reopen_backoff * 2).min(REOPEN_BACKOFF_MAX)
2030            };
2031        }
2032
2033        // Still no device at the end of this tick — the outage clock runs and, once
2034        // the whole reopen ladder has demonstrably failed, files the ONE error event
2035        // this path ever produces. A device that comes back before then (the normal
2036        // case for an unplug/suspend/EIO) never reaches Sentry at all.
2037        if playback.is_none() {
2038            health.poll_down(Instant::now());
2039        }
2040    }
2041
2042    // Dropping the sink releases the device on this (owning) thread.
2043    drop(playback);
2044}

2621    // ── End-to-end audio playout-chain continuity (the crackle guard) ────────────
2622    //
2623    // Deterministic, sans-IO: drive a peer's audio through the REAL pull-based chain
2624    // — the PUMP pushes 20 ms tone frames into the slot's jitter buffer at their
2625    // (possibly delayed) arrival, and the MIX thread pulls exactly one 10 ms chunk
2626    // per STEADY tick via `pull_into` (the production cadence). Both sides share one
2627    // timeline (the `CaptureClock` invariant). Audio crackle, as a number, is a
2628    // silence/short chunk mid-stream — a `Slot` starvation. The decisive property the
2629    // pull model gives us: the mix's release clock is independent of the pump's push
2630    // timing, so pump jitter/descheduling (the live crackle cause) only delays a FILL,
2631    // which the jitter buffer absorbs — it can NOT race the release. These pin that.
2632
2633    const CHAIN_FRAME_US: i64 = 20_000; // 20 ms Opus frame
2634    const CHAIN_FRAME_SAMPLES: usize = 960; // 20 ms @ 48 kHz mono
2635    const CHAIN_TARGET_US: i64 = 60_000; // jitter cushion (PLAYOUT_TARGET_US)
2636    const CHAIN_TICK_US: i64 = (MIX_TICK_MS as i64) * 1_000; // 10 ms mix tick
2637    const CHAIN_TONE: i16 = 5_000;
2638
2639    /// Drive ONE peer through the real pull chain for `ticks` mix ticks. `arrival(k)`
2640    /// returns the shared-clock time at which the pump PUSHES frame `k` (its ideal
2641    /// arrival is `k·20 ms`; returning later models pump descheduling/jitter). The mix
2642    /// pulls exactly one chunk per steady 10 ms tick. Returns the per-tick mixed chunks
2643    /// and the slot starvation count.
2644    fn run_pull_chain(
2645        ticks: i64,
2646        target_us: i64,
2647        arrival: impl Fn(i64) -> i64,
2648    ) -> (Vec<[i16; MIX_CHUNK_SAMPLES]>, u64) {
2649        let starves = Arc::new(AtomicU64::new(0));
2650        let slot = Arc::new(Slot::new(starves.clone(), target_us, "mic", NO_PEER_TAG));
2651        let mut scratch = MixScratch::new();
2652        let slots = [slot.clone()];
2653        let mut out = Vec::new();
2654        let mut next_frame = 0i64;
2655        for t in 0..ticks {
2656            let now = t * CHAIN_TICK_US;
2657            // Pump: push every frame whose (possibly delayed) arrival has come, at its
2658            // arrival time on the shared clock — exactly what the live pump does.
2659            while arrival(next_frame) <= now {
2660                let ts = next_frame * CHAIN_FRAME_US;
2661                let at = arrival(next_frame);
2662                slot.push(Some(at), at, ts, &[CHAIN_TONE; CHAIN_FRAME_SAMPLES]);
2663                next_frame += 1;
2664            }
2665            // Mix: pull exactly one chunk on the steady RT clock.
2666            out.push(mix_chunk(&slots, now, &mut scratch, &mut Vec::new()));
2667        }
2668        (out, starves.load(Ordering::Relaxed))
2669    }
