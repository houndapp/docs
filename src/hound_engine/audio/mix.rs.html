1//! # Mixed-playout audio bus — one device stream + one coherent AEC reference
2//!
3//! All remote peers play through ONE mixed output stream. Echo cancellation
4//! requires it: [`Apm::process_render`] must be fed the one coherent stream the
5//! speaker actually plays — interleaving independent per-peer render references
6//! corrupts AEC3's canceller for any N>1. A single mixed playout makes the
7//! render reference exact for any N by construction, and halves the device
8//! handles (one stream per call, not one per peer).
9//!
10//! ## The tick model (PULL-based: the RT thread is the sole release clock)
11//!
12//! One dedicated playback thread per call owns the single [`CpalPlayback`](crate::platform::generic::cpal_io::CpalPlayback). It
13//! ticks on a **wall-clock 10 ms cadence** (the APM chunk size,
14//! [`MIX_CHUNK_SAMPLES`]) — driven by the OUTPUT side, never by peer frame
15//! arrival, because the cpal ring absorbs the jitter between the tick and the
16//! DAC. On each tick the bus, for EACH registered producer:
17//!
18//! 1. **pops every due frame from that peer's jitter buffer** on its OWN
19//!    real-time clock — `playout.pop_due_into(clock.now() + lookahead, …)` — appending the
20//!    released PCM to the slot's sample carry-queue, then drains up to
21//!    [`MIX_CHUNK_SAMPLES`] from the carry,
22//! 2. **sums** the producers sample-for-sample in **i32**, **soft-limits** the sum
23//!    (AGC2's limiter, as libwebrtc's `frame_combiner.cc` does) and converts to i16
24//!    with a saturating backstop — so N loud peers cost ~a dB of gain rather than a
25//!    flat-topped, broadband-distorted mix,
26//! 3. pushes the mixed chunk to the [`CpalPlayback`](crate::platform::generic::cpal_io::CpalPlayback) ring, and
27//! 4. feeds what the ring ACCEPTED to [`Apm::process_render`] (the single coherent
28//!    reference — only what the speaker actually emits belongs in it).
29//!
30//! Usually that is exactly one chunk per tick, but the count is REGULATED by the
31//! device ring's depth ([`chunks_for_tick`]): the DAC drains on its own crystal and
32//! this thread refills on a software clock, so an open-loop one-chunk-per-tick push
33//! walks the ring either dry (continuous dropouts) or full (latency pinned at the
34//! ring depth, overproduction silently discarded). Feeding back off the depth also
35//! makes a scheduling stall recoverable — the drained cushion is replayed instead of
36//! being spent for the rest of the call.
37//!
38//! ### Why pull, not push
39//!
40//! A push design — a per-peer pump task (a normal async task) calling `pop_due_into`
41//! and PUSHING samples into the slot for this RT thread to drain — puts a
42//! **second, non-real-time scheduler on the release path**: under video-encode
43//! load the pump gets descheduled, feeds its slot late, and the RT drain finds
44//! the slot short — an audible per-peer gap (`mix_starves`) with the device ring
45//! still full (`output_underruns == 0`). No slot lead or cushion can fix that,
46//! because the producer's *timing* is the variable. Pull — the RT thread is the
47//! ONLY thing that calls `pop_due_into`, on its own steady clock — removes that
48//! scheduler from the release path entirely. The pump's sole job is to FILL
49//! the jitter buffer (network-paced; its scheduling never affects playout),
50//! and the jitter buffer IS the cushion that absorbs the pump's arrival jitter.
51//! Both push (pump) and pop (this thread) read the same `Copy` [`CaptureClock`],
52//! so the buffer's sender→local timeline mapping is consistent across the two
53//! threads.
54//!
55//! ### How the tick is paced
56//!
57//! The cadence comes from an ABSOLUTE deadline schedule ([`TickPacer`]): tick `n`
58//! is due at `epoch + n × MIX_TICK`, never at `now + MIX_TICK`, so a late wake is
59//! not folded into the next deadline and the grid cannot drift. Each tick waits
60//! coarsely to within [`SPIN_MARGIN`] of its deadline and then busy-waits the
61//! remainder, because the coarse wait only guarantees a LOWER bound on the delay:
62//! its overshoot is the OS timer granularity, which on Windows is 15.6 ms by
63//! default — three tick periods over the ask, landing straight in the tick-late
64//! histogram (and, downstream, in the receiver's decode-budget limitation signal).
65//! The coarse wait is therefore per-platform ([`CoarseWait`](pacer::CoarseWait)): a plain `sleep` off
66//! Windows, and on Windows a **high-resolution waitable timer** whose ~0.5 ms
67//! accuracy is independent of that 15.6 ms clock.
68//!
69//! When **zero** producers are registered the bus STILL ticks (pushing silence),
70//! so the device stream and the AEC reference stay warm for the whole call —
71//! AEC3's delay/echo state does not have to re-converge each time the room goes
72//! briefly quiet or the last peer's pipeline is mid-rebuild.
73//!
74//! ## Registration + bounds
75//!
76//! A per-peer pipeline, instead of owning a playback thread, registers a
77//! [`BusProducer`] and PUSHES its decoded, timestamped PCM into the slot's jitter
78//! buffer via [`BusProducer::push`] (which also folds the arrival into the slot's
79//! [`AdaptiveJitter`](hound_media::AdaptiveJitter) and reports back the depth/jitter for stats). The RT thread
80//! pulls from that buffer. The jitter buffer is bounded (drop-oldest at its frame
81//! cap) and the sample carry-queue is bounded to ~100 ms ([`SLOT_CAPACITY_SAMPLES`])
82//! drop-oldest, so one stalled or runaway peer can never grow the bus's memory.
83//! Dropping a [`BusProducer`] (its pipeline torn down / aborted) unregisters its
84//! slot from the bus, so a left peer stops contributing to the mix with no explicit
85//! teardown call.
86//!
87//! ## Hot-swap / vanish / reopen
88//!
89//! The bus thread owns the speaker [`DeviceChoice`] hot-swap, the vanished-device
90//! fallback (handled inside [`CpalPlayback::start`](crate::platform::generic::cpal_io::CpalPlayback::start)), and the reopen backoff —
91//! in ONE place targeting the ONE stream. `call_set_speaker` nudges the shared `watch` sender;
92//! the bus thread re-opens the single device in place without disturbing the mix.
93//!
94//! Only a stream that actually DIED takes the immediate reopen. Everything the
95//! backend reports on a still-live stream — an automatic reroute, and the demoted
96//! quality faults (cpal `Xrun` / `RealtimeDenied`) — rides one debounce
97//! ([`RouteSettle`]) that collapses a burst into a single re-sync, because each
98//! reopen is itself a blocking device open on this real-time thread plus a fresh
99//! cushion prefill.
100//!
101//! Being the only party that sees a recovery's OUTCOME, this thread also owns the
102//! decision to report one: a stream error is logged at `warn` where it happens and
103//! only becomes an `error!` (a Sentry event) if playout is still down after the
104//! whole reopen ladder has run — see [`OutputHealth`].
105//!
106//! ## `!Send` discipline
107//!
108//! `cpal::Stream` is `!Send` on CoreAudio, so the [`CpalPlayback`](crate::platform::generic::cpal_io::CpalPlayback) is constructed,
109//! driven, and dropped on the bus's own thread and never crosses a thread
110//! boundary. Producers (`Send`/`Sync`) only ever touch the bounded slot queues.
111//!
112//! ## Decoupling
113//!
114//! This module is deliberately free of session-specific types: it takes raw mono
115//! i16 PCM (`&[i16]`) in and plain handles out. The only audio dependencies are
116//! [`Apm`] (the render-reference sink) and [`CpalPlayback`](crate::platform::generic::cpal_io::CpalPlayback) (the device), both
117//! behind narrow calls.

150/// Samples in one mix tick: 10 ms @ 48 kHz mono = **480**. Identical to the APM's
151/// native chunk ([`APM_FRAME_SAMPLES`]) so the mixed chunk feeds `process_render`
152/// as exactly one block, and the tick cadence matches the canceller's frame size.
153pub const MIX_CHUNK_SAMPLES: usize = APM_FRAME_SAMPLES;

155/// The wall-clock period the bus thread ticks at: 10 ms, matching
156/// [`MIX_CHUNK_SAMPLES`] at 48 kHz. Output-side cadence — the cpal ring absorbs
157/// the difference between this and the DAC's real pull timing.
158const MIX_TICK: Duration = Duration::from_millis(10);
159
160/// [`MIX_TICK`] in milliseconds — the chunk duration the output cushion is counted in.
161const MIX_TICK_MS: u32 = 10;

163/// How long before a tick's deadline [`TickPacer`] stops sleeping and busy-waits.
164///
165/// The trade is spin cost against release precision. Every coarse wait
166/// ([`CoarseWait`](pacer::CoarseWait)) guarantees only a lower bound on the delay; the overshoot is the
167/// OS timer granularity, so a pure `sleep(deadline - now)` releases the tick a
168/// granularity-sized quantum LATE, every tick — 15.6 ms on default-configured
169/// Windows (worse than the 10 ms period itself), and hundreds of µs on a loaded
170/// mac/Linux box. Ending each wait in a busy loop makes the release precise to
171/// within the loop's own iteration cost regardless of the wait clock.
172///
173/// 1.5 ms on every platform. On Windows it is sized off the worst overshoot the bus
174/// can still see from [`CoarseWait`](pacer::CoarseWait): ~0.5 ms from the high-resolution waitable
175/// timer, or a 1 ms `timeBeginPeriod` quantum on the pre-1803 fallback — a full
176/// quantum with headroom either way, so the busy loop is entered before the deadline
177/// rather than after it. A smaller non-Windows margin was tried and measured out: at
178/// 300 µs a loaded mac released 2.3 ms late on average — macOS timer coalescing gives
179/// short sleeps multi-ms slop — so the margin that keeps the release precise is the
180/// same one everywhere. It is also the worst-case busy time per tick (15% of one
181/// core, only while a call runs the bus); the actual figure is lower, since the wait
182/// only spins the part of the margin the preceding coarse wait did not consume, and
183/// the [`SPIN_YIELD_FLOOR`] band yields rather than spins.
184const SPIN_MARGIN: Duration = Duration::from_micros(1_500);
185
186/// Inside [`SPIN_MARGIN`], the point at which the pacer stops offering the CPU to
187/// other threads and only spins. Above the floor a `yield_now` per iteration keeps
188/// the busy wait from starving a runnable sibling on a core-starved box (this thread
189/// is RT-priority — it can and will win the CPU outright); below it, `yield_now`'s
190/// own syscall cost is on the order of the remaining wait, so the cheaper
191/// `spin_loop` hint carries the last stretch to the deadline.
192const SPIN_YIELD_FLOOR: Duration = Duration::from_micros(200);
193
194/// How far PAST strictly-due the RT thread pops each tick: exactly one [`MIX_TICK`]
195/// (10 ms). A 20 ms audio frame spans two 10 ms ticks, so its due-instant lands
196/// between ticks for some phase offsets; a one-tick lookahead releases the next
197/// frame into the carry-queue *before* the carry can bottom out, so the slot
198/// always has a full chunk to drain regardless of how the frame-due phase aligns
199/// to the tick grid. Because the RT thread (not the pump) owns this read, the
200/// lookahead is immune to producer scheduling — it just smooths the frame/tick
201/// phase. Net latency is unchanged: a frame released `lookahead` early simply
202/// waits that long in the carry-queue instead of the jitter buffer.
203const MIX_PULL_LOOKAHEAD_US: i64 = MIX_TICK_MS as i64 * 1_000;
204
205/// Ceiling on chunks emitted in ONE tick while catching up. Each chunk is a full
206/// mix + AEC render pass, so an unbounded catch-up would turn a stall into a CPU
207/// spike on the RT thread. 4 (40 ms) restores the whole cushion from a dry ring in
208/// a single tick, which is the worst case the depth signal can report.
209const MAX_CHUNKS_PER_TICK: usize = 4;
210
211/// Per-producer slot bound: ~100 ms of 48 kHz mono audio (4800 samples). A
212/// drop-oldest policy keeps a stalled/runaway peer from growing the bus's memory;
213/// 100 ms is ~5 mix chunks of slack, enough to ride out a scheduling hiccup
214/// without unbounded growth.
215const SLOT_CAPACITY_SAMPLES: usize = (SAMPLE_RATE.hz() as usize / 1000) * 100;
216
217/// Recycled PCM buffers per slot: the pump allocates a frame's samples in
218/// [`Slot::push`] and the bus thread frees them after draining into the carry, so a
219/// small free-list keeps ~50 malloc/free per second per peer off the RT tick. Bounded
220/// (a runaway pump can't grow it) and best-effort (the RT side only `try_lock`s).
221const SLOT_POOL_CAP: usize = 8;
222
223/// Initial capacity of the bus thread's per-tick release scratch ([`MixScratch::due`]).
224/// A steady 10 ms tick releases 0 or 1 of a peer's 20 ms frames. The headroom is for the
225/// case that actually produces a burst: a DESCHEDULED tick, where everything that came
226/// due while the thread was off-CPU is released at once (bounded by the jitter buffer's
227/// `max_frames`, 256). Pre-sizing keeps the common tick off the allocator entirely; a
228/// long stall still grows the `Vec` a handful of times, once, and then never again.
229const MIX_DUE_SCRATCH_FRAMES: usize = 8;
230
231/// Initial capacity of the bus thread's per-tick glitch buffer. One tick can record at
232/// most one underflow per registered slot plus a late-tick event; 8 covers any realistic
233/// call (mic + screen audio per peer) without the allocator ever appearing on the RT
234/// path — least of all on the already-late tick that is doing the recording.
235const TICK_GLITCH_CAPACITY: usize = 8;
236
237/// A mix tick this late (µs) or more is recorded as a [`GlitchKind::LateTick`]. Half a
238/// tick (5 ms) — below this is ordinary scheduler noise the output cushion absorbs;
239/// above it the RT feeder genuinely slipped and the device ring risks draining.
240const TICK_LATE_GLITCH_US: u128 = (MIX_TICK_MS as u128 * 1000) / 2;

242/// A handle a per-peer pipeline holds to push its decoded PCM into the mix. Pushing
243/// is non-blocking and bounded (the jitter buffer + the ~100 ms carry are both
244/// drop-oldest). Dropping the handle unregisters the producer's slot from the bus
245/// (so a torn-down peer stops contributing with no explicit call) — the Drop-safe
246/// teardown the ghost discipline requires.
247pub struct BusProducer {
248    id: u64,
249    slot: Arc<Slot>,
250    registry: Arc<Registry>,
251}

253impl BusProducer {
254    /// Push one decoded audio frame into this producer's jitter buffer: `now_us` is
255    /// the local receive time and `ts_us` the sender's capture timestamp (BOTH on the
256    /// session's shared [`CaptureClock`], which the bus thread pops against), and
257    /// `samples` the 48 kHz mono PCM. Folds the arrival into the adaptive jitter depth
258    /// and returns the resulting depth/jitter for per-peer stats. The bus thread
259    /// releases the frame on its own real-time clock — the pump's scheduling never
260    /// affects playout timing.
261    ///
262    /// For a pipeline that pushes as soon as the frame lands, this is the whole story.
263    /// A pipeline that HOLDS frames before pushing must use [`Self::push_at`].
264    pub fn push(&self, now_us: i64, ts_us: i64, samples: &[i16]) -> PushStatus {
265        self.slot.push(Some(now_us), now_us, ts_us, samples)
266    }
267
268    /// [`Self::push`] for a pipeline that delays frames between the wire and here:
269    /// `arrival_us` is when the frame came off the wire, `now_us` when it reaches the
270    /// buffer.
271    ///
272    /// The jitter estimator is differential — it measures `arrivalΔ − tsΔ` — so it must
273    /// be fed the WIRE instant or it measures the receive pipeline instead of the link.
274    /// The audio path is exactly this case: its encoded reorder hold releases by COUNT,
275    /// so how long a frame waits depends on when the *next* frames arrive. Push both as
276    /// `now_us` and the hold's own release cadence is reported as transit deviation —
277    /// which, against a publisher that suppresses silence, means each 500 ms keepalive
278    /// contributes a ~500 ms "spike", the windowed peak pins the recommended depth at
279    /// its cap for the full peak window, and a peer who was merely quiet comes back with
280    /// half a second of latency stapled to their first word.
281    pub fn push_at(&self, arrival_us: i64, now_us: i64, ts_us: i64, samples: &[i16]) -> PushStatus {
282        self.slot.push(Some(arrival_us), now_us, ts_us, samples)
283    }
284
285    /// [`Self::push`] for audio the receiver MANUFACTURED rather than received at its own
286    /// timestamp: Opus PLC concealment over a gap, and the slot redeemed from the next
287    /// packet's in-band FEC. It is scheduled and played like any other frame, but it is
288    /// never folded into the jitter estimator.
289    ///
290    /// **FEC-redeemed audio belongs here too**, and that is the non-obvious half: the
291    /// samples are real (a low-bitrate re-encode of frame N−1 riding in packet N), so it
292    /// is tempting to push it like any received frame — but the only arrival instant it
293    /// has is its SUCCESSOR's. Crediting the redeemed slot with the carrier's instant
294    /// books `arrivalΔ − tsΔ` = one frame time on the pair before it and the mirror image
295    /// on the pair after; crediting it with the pipeline's local `now` (which trails the
296    /// wire by the reorder hold) books one frame time PLUS the hold. Measured on the
297    /// audio receive path: a single-frame loss booked an 80 ms deviation (60 ms hold +
298    /// 20 ms frame) and pinned the recommended depth at 160 ms for the full peak window —
299    /// the CI regression in `a_silent_peer_quiesces_the_wire_and_resumes_instantly`.
300    ///
301    /// A concealed frame has no arrival instant to fold. The only clock available at the
302    /// point it is synthesized is the pipeline's own `now`, and pushing that as an
303    /// arrival makes the estimator measure the receive path instead of the link twice
304    /// over: the pair (last real frame → first PLC frame) books the whole concealed gap
305    /// PLUS however long the reorder hold and the task scheduler took, and the pair
306    /// (last PLC frame → the real frame behind it) books the mirror image, because that
307    /// real frame's WIRE stamp predates the `now` the PLC was pushed with. Both are pure
308    /// artefacts — the wire event that triggered them deviated by microseconds. Measured
309    /// on a live call across a one-frame (30 ms) gap: D = +62.6 ms then −61.7 ms against
310    /// a true deviation of +0.9 ms, and since the estimator provisions for the windowed
311    /// MAX deviation, that single fabricated spike deepened the buffer to 142 ms and held
312    /// it there for the whole 90 s peak window. Concealment happens precisely when a link
313    /// is lossy, so feeding it back into the depth is also a feedback loop.
314    ///
315    /// Skipping the observation entirely (rather than inventing an arrival) is what keeps
316    /// the estimate honest: the next REAL frame is then differenced against the last real
317    /// one, so a concealed gap contributes `arrivalΔ − tsΔ ≈ 0` — which is correct, since
318    /// loss is not jitter.
319    pub fn push_concealed(&self, now_us: i64, ts_us: i64, samples: &[i16]) -> PushStatus {
320        self.slot.push(None, now_us, ts_us, samples)
321    }
322}

333/// The set of live producer slots, shared between the bus thread (which iterates
334/// it every tick) and `register`/`unregister` (called from the async subscribe
335/// loop as peers come and go). A `std::sync::Mutex` is right: the critical section
336/// is a `HashMap` insert/remove or a cheap clone of the slot `Arc`s, never held
337/// across IO.
338#[derive(Default)]
339struct Registry {
340    slots: Mutex<HashMap<u64, Arc<Slot>>>,
341}
342
343impl Registry {
344    /// Snapshot the current slots into a caller-owned buffer (cheap `Arc` clones), so
345    /// the tick iterates without holding the registry lock across the mix/APM/playback
346    /// work AND without allocating a fresh `Vec` on the RT thread every 10 ms.
347    fn snapshot_into(&self, out: &mut Vec<Arc<Slot>>) {
348        out.clear();
349        if let Ok(g) = self.slots.lock() {
350            out.extend(g.values().cloned());
351        }
352    }
353
354    /// Allocating [`Self::snapshot_into`], for the non-RT callers (stats, tests).
355    fn snapshot(&self) -> Vec<Arc<Slot>> {
356        let mut out = Vec::new();
357        self.snapshot_into(&mut out);
358        out
359    }
360
361    fn unregister(&self, id: u64) {
362        if let Ok(mut g) = self.slots.lock() {
363            g.remove(&id);
364        }
365    }
366}

368/// The mixed-playout bus for one call. Owns the dedicated playback thread (which
369/// owns the single [`CpalPlayback`](crate::platform::generic::cpal_io::CpalPlayback) and runs the 10 ms mix tick) and the producer
370/// registry. Per-peer pipelines [`register`](Self::register) a [`BusProducer`] and
371/// push their due PCM into it; the bus sums them, feeds the mixed chunk to the APM
372/// render reference once, and plays it.
373///
374/// Dropping the bus signals its thread to stop (the `!Send` `CpalPlayback` is then
375/// dropped on its owning thread) — Drop-safe like the per-peer pipelines.
376pub struct PlayoutBus {
377    registry: Arc<Registry>,
378    next_id: AtomicU64,
379    /// Jitter-buffer depth floor (µs) for every new slot — the latency floor the
380    /// adaptive jitter grows from. Set by the call (`PLAYOUT_TARGET_US`). (The shared
381    /// capture clock itself is owned by the bus thread, not stored here — only the
382    /// thread reads `now()` each tick.)
383    playout_floor_us: i64,
384    stop: Arc<AtomicBool>,
385    /// Cumulative per-peer mix-STARVATION events shared with every [`Slot`] (a
386    /// primed slot that came up short at tick time — the per-peer audible gap). The
387    /// app polls this (diffing per window) to surface a live "mix starvation" stat
388    /// so playout stutter is a measured number, not a vibe. See [`Slot::starves`].
389    mix_starves: Arc<AtomicU64>,
390    /// Cumulative output-ring underrun SAMPLES (the device RT callback played
391    /// silence because the ring ran dry — the device-side gap). Accumulated each
392    /// tick from the sink's [`AudioOutput::take_output_underruns`].
393    output_underruns: Arc<AtomicU64>,
394    /// Cumulative output-ring OVERRUN samples (the sink's ring was too full to accept
395    /// what the bus pushed, so they were discarded and never reached the speaker) — the
396    /// opposite drift direction to [`Self::output_underruns`]. With the cushion
397    /// regulated this should hold at 0; a rising count means the regulator lost control
398    /// of the ring (output latency pinned at the ring depth). Accumulated each tick from
399    /// [`AudioOutput::take_output_overruns`].
400    output_overruns: Arc<AtomicU64>,
401    /// Cumulative NON-FATAL output-stream faults the backend reported and this bus
402    /// DEMOTED into the route-settle debounce instead of a reopen (cpal `Xrun` /
403    /// `RealtimeDenied`). Accumulated each tick from
404    /// [`AudioOutput::take_soft_faults`]. Steady state 0; rising means the device is
405    /// glitching without dying — the signal that would otherwise be invisible, since a
406    /// sustained storm keeps pushing the debounce out and so never produces a reopen.
407    output_soft_faults: Arc<AtomicU64>,
408    /// How LATE each 10 ms mix tick fired versus its schedule (µs), as a windowed
409    /// percentile histogram drained by the stats emitter. This is the RT-health
410    /// signal: if the bus thread is descheduled (e.g. a 60 fps screen-share encode
411    /// hogging the CPU), ticks slip, the device ring drains, and ALL audio stutters —
412    /// a p95 well above ~0 localizes the gap to the feeder thread, not the network.
413    tick_late_lat: Arc<Mutex<hound_media::LatencyHistogram>>,
414    /// Bounded ring of discrete audio-glitch events (drop-oldest), recorded by the bus
415    /// thread at the instant each gap happens and drained by the client each stats
416    /// window into a rolling history the debug report renders as a glitch log.
417    glitches: Arc<Mutex<VecDeque<AudioGlitch>>>,
418    /// The session capture clock (the same `Copy` clock the bus thread stamps glitches
419    /// against), so the client can compute each glitch's age (`now_us − at_us`).
420    clock: CaptureClock,
421    /// Mix-tick counter, surfaced for tests so a caller can confirm the bus keeps
422    /// ticking (silence) with zero producers. Test-only — the live path never
423    /// reads it.
424    #[cfg(test)]
425    ticks: Arc<AtomicU64>,
426}

576    /// Cumulative starve counts attributed BY SOURCE KIND (the `label` passed to
577    /// [`Self::register`]), summed across the currently-registered slots of each
578    /// kind. Lets the stats loop show WHICH audio is starving — e.g. a screen
579    /// share's intermittent app audio (often a metric artifact, inaudible on the
580    /// call) vs the remote mic (real voice stutter). Diagnostic only; the
581    /// authoritative aggregate is [`Self::mix_starves`].
582    pub fn starves_by_kind(&self) -> Vec<(&'static str, u64)> {
583        let mut totals: Vec<(&'static str, u64)> = Vec::new();
584        for slot in self.registry.snapshot() {
585            let n = slot.own_starves.load(Ordering::Relaxed);
586            match totals.iter_mut().find(|(label, _)| *label == slot.label) {
587                Some((_, sum)) => *sum += n,
588                None => totals.push((slot.label, n)),
589            }
590        }
591        totals

606    /// stutter. The app diffs this per window.

618    }

637            .lock()

664/// The bus thread body: own the single output sink (opened via `sink_factory`,
665/// with the speaker hot-swap / vanish-fallback / reopen-backoff), and every
666/// [`MIX_TICK`] sum the producers into one chunk, feed it
667/// to the APM render reference once, and play it. Ticks silence with zero
668/// producers so the device stream + AEC reference stay warm. The `!Send` sink
669/// never leaves this thread.
670#[allow(clippy::too_many_arguments)]
671fn mix_bus_loop(
672    stop: Arc<AtomicBool>,
673    mut speaker_rx: watch::Receiver<DeviceChoice<SpeakerId>>,
674    apm: Option<Arc<Apm>>,
675    registry: Arc<Registry>,
676    clock: CaptureClock,
677    ticks: Arc<AtomicU64>,
678    output_underruns: Arc<AtomicU64>,
679    output_overruns: Arc<AtomicU64>,
680    output_soft_faults: Arc<AtomicU64>,
681    tick_late_lat: Arc<Mutex<hound_media::LatencyHistogram>>,
682    glitch_ring: Arc<Mutex<VecDeque<AudioGlitch>>>,
683    mut sink_factory: SinkFactory,
684) {
685    // Promote this thread to real-time scheduling: it feeds the output device ring on
686    // a 10 ms software clock, and if video-encode load deschedules it the ring drains
687    // and the device plays silence (the under-load playout stutter the instrumentation
688    // showed spiking when a 60 fps screen share starts). The cpal output callback is
689    // already RT; this lets its feeder keep up. Best-effort — a failure just logs and
690    // runs at normal priority (the output cushion still absorbs ordinary jitter). The
691    // handle must stay alive for the thread's lifetime to hold the policy.
692    let _rt_handle = match audio_thread_priority::promote_current_thread_to_real_time(
693        MIX_CHUNK_SAMPLES as u32,
694        SAMPLE_RATE.hz(),
695    ) {
696        Ok(h) => {
697            tracing::info!("voice: mix-bus thread promoted to real-time priority");
698            Some(h)
699        }
700        Err(e) => {
701            tracing::warn!("voice: mix-bus RT priority unavailable ({e:?}) — normal priority");
702            None
703        }
704    };
705
706    let mut choice = speaker_rx.borrow().clone();
707    // Tracks whether the output device is UP, and escalates an outage the reopen
708    // ladder cannot fix (the only path from this thread to a Sentry event).
709    let mut health = OutputHealth::default();
710    let mut playback = open_sink(&mut sink_factory, &choice, &mut health, Instant::now());
711    prefill_output(&mut playback);
712    // One-shot reopen for a non-48k (BT/HFP) output whose route may not be live yet.
713    let mut warmup_reopen = warmup_reopen_at(&playback, Instant::now());
714    // Debounce for OS route changes (see `RouteSettle` / `ROUTE_SETTLE`).
715    let mut route_settle = RouteSettle::default();
716    let mut last_open_attempt = Instant::now();
717    // Exponential reopen backoff: doubles from REOPEN_BACKOFF up to
718    // REOPEN_BACKOFF_MAX while the device stays down, resets on a successful
719    // open or a hot-swap. Stops the persistent-failure log/device-churn storm.
720    let mut reopen_backoff = REOPEN_BACKOFF;
721
722    // Reused scratch so the per-tick mix allocates nothing — neither in the i32
723    // accumulate nor in releasing each slot's due frames.
724    let mut scratch = MixScratch::new();
725    // Reused per-tick glitch buffer — empty in steady state, filled only on the rare
726    // tick that has an underflow / late slip, then drained into the ring. Pre-sized
727    // because that tick is by definition ALREADY struggling: growing the `Vec` there
728    // would put the allocator on the RT path at exactly the wrong moment. A tick can
729    // record at most one glitch per slot plus the late-tick one.
730    let mut tick_glitches: Vec<AudioGlitch> = Vec::with_capacity(TICK_GLITCH_CAPACITY);
731    // Reused wrapper buffer for the mixed chunk fed to the APM + device each tick, so
732    // the RT thread allocates nothing per tick.
733    let mut mixed_buf: Vec<i16> = Vec::with_capacity(MIX_CHUNK_SAMPLES);
734    // Reused silence buffer for the render reference while no sink is open.
735    let mut silence_buf: Vec<i16> = Vec::with_capacity(MIX_CHUNK_SAMPLES);
736    // Reused registry snapshot (see `Registry::snapshot_into`).
737    let mut slots: Vec<Arc<Slot>> = Vec::new();
738    // Owns the platform coarse-wait mechanism (`CoarseWait`) for the bus thread's
739    // lifetime: on Windows a high-resolution waitable timer, so the coarse half of
740    // each wait lands inside `SPIN_MARGIN` instead of three tick periods past it.
741    // Dropped with this frame — the OS handle never outlives the call.
742    let mut pacer = TickPacer::new(Instant::now(), MIX_TICK);
743
744    while !stop.load(Ordering::Relaxed) {
745        // Pace to the next 10 ms boundary (output-side cadence) off the absolute
746        // deadline schedule; the cpal ring absorbs the residual jitter between this
747        // and the DAC.
748        let now = Instant::now();
749        // How late this tick fired vs its 10 ms schedule: 0 when on-time/early, > 0
750        // only when the RT thread was descheduled past its deadline (the device ring
751        // then drains → all audio stutters). Record BEFORE pacing so the value is
752        // the real slip, not the post-wait alignment. One uncontended lock/tick,
753        // same discipline as the per-slot locks already on this path.
754        let late_us = now.saturating_duration_since(pacer.deadline()).as_micros();
755        if let Ok(mut h) = tick_late_lat.lock() {
756            h.record(late_us.min(u64::MAX as u128) as u64);
757        }
758        pacer.pace();
759        // Advance the schedule; if we fell badly behind (e.g. the thread was
760        // descheduled), `advance` re-anchors to now so we don't spin catching up.
761        let tick_at = Instant::now();
762        pacer.advance(tick_at);
763
764        // Hot-swap: a changed speaker choice re-opens the single output device in
765        // place (vanish-fallback lives in `CpalPlayback::start`).
766        if speaker_rx.has_changed().unwrap_or(false) {
767            choice = speaker_rx.borrow_and_update().clone();
768            tracing::info!(?choice, "voice: speaker hot-swap requested (mix bus)");
769            // Dropping the old sink releases the device on this (owning)
770            // thread before the new one opens.
771            drop(playback.take());
772            playback = open_sink(&mut sink_factory, &choice, &mut health, tick_at);
773            prefill_output(&mut playback);
774            // A user-picked device may also be a BT headset needing the warmup reopen.
775            warmup_reopen = warmup_reopen_at(&playback, Instant::now());
776            // The explicit swap already re-derived the geometry any pending route
777            // re-sync was going to fix.
778            route_settle.disarm();
779            last_open_attempt = Instant::now();
780            reopen_backoff = REOPEN_BACKOFF;
781        }
782
783        // One-shot warmup reopen: a non-48k (BT/HFP) output stream that opened onto a
784        // not-yet-live SCO route plays silence and never errors, so the `is_dead`
785        // reopen below never fires. Reopen it ONCE after the route has had time to
786        // settle (the automatic equivalent of the rejoin that "fixes" it). Not
787        // re-armed afterwards — a single nudge, no reopen loop.
788        if let Some(at) = warmup_reopen
789            && Instant::now() >= at
790        {
791            warmup_reopen = None;
792            if playback.is_some() {
793                tracing::info!(
794                    "voice: warmup reopen of non-48k (BT/HFP) output — first-connect audio fix"
795                );
796                drop(playback.take());
797                playback = open_sink(&mut sink_factory, &choice, &mut health, Instant::now());
798                prefill_output(&mut playback);
799                route_settle.disarm();
800                last_open_attempt = Instant::now();
801                reopen_backoff = REOPEN_BACKOFF;
802            }
803        }
804
805        // Mix on THIS real-time clock: each peer releases its due jitter-buffered
806        // frames (`pop_due_into(clock.now() + lookahead, …)`) and we sum a 10 ms chunk + feed
807        // one AEC render reference per chunk. This thread is the SOLE release
808        // authority — the per-peer pumps only FILL the jitter buffers, so no
809        // non-real-time scheduler sits on the playout path (one there gaps playout
810        // audibly whenever it is descheduled).
811        //
812        // How MANY chunks is decided by the device-ring depth, not by the tick alone:
813        // the cushion pre-filled at open is REGULATED from here (see
814        // `chunks_for_tick`), because the DAC's crystal and this software clock drift
815        // and an open-loop one-chunk-per-tick push walks the ring dry or full.
816        let now_us = clock.now();
817        registry.snapshot_into(&mut slots);
818        tick_glitches.clear();
819        let depth_ms = playback.as_ref().and_then(|p| p.buffered_ms());
820        for _ in 0..chunks_for_tick(depth_ms, late_us) {
821            // Mix + collect any per-peer underflow glitches (into the reused buffer —
822            // empty in steady state). Wrap for the APM + device reusing `mixed_buf`'s
823            // allocation (the frame is built from the taken buffer, reclaimed below).
824            let mixed = mix_chunk(&slots, now_us, &mut scratch, &mut tick_glitches);
825            mixed_buf.clear();
826            mixed_buf.extend_from_slice(&mixed);
827            let frame = chunk_to_frame(std::mem::take(&mut mixed_buf));
828            // Play FIRST, then feed the render reference. A sink that partially
829            // overran still gets the WHOLE chunk as reference: the dropped tail
830            // shifts the played timeline by a few samples, which AEC3's adaptive
831            // delay search re-tracks — whereas skipping the chunk leaves a hole
832            // in the reference cadence that stalls the canceller for every
833            // frame after it. Overruns stay counted either way.
834            let played = match playback.as_mut() {
835                Some(p) => {
836                    let _ = p.play(&frame);
837                    let dropped = p.take_output_overruns();
838                    if dropped > 0 {
839                        output_overruns.fetch_add(dropped, Ordering::Relaxed);
840                    }
841                    true
842                }
843                None => false,
844            };
845            if let Some(apm) = apm.as_ref() {
846                if played {
847                    apm.process_render(&frame);
848                } else {
849                    // No sink (device down / reopen backoff): nothing reaches the
850                    // speaker, so the truthful reference is SILENCE. Still fed every
851                    // chunk, so AEC3's render cadence stays warm across the outage.
852                    silence_buf.clear();
853                    silence_buf.resize(MIX_CHUNK_SAMPLES, 0);
854                    let silent = chunk_to_frame(std::mem::take(&mut silence_buf));
855                    apm.process_render(&silent);
856                    silence_buf = silent.samples;
857                }
858            }
859            // Reclaim the buffer for the next chunk (no allocator traffic on the RT path).
860            mixed_buf = frame.samples;
861        }
862        // A meaningfully-late tick (the RT feeder slipped) is itself a glitch affecting
863        // ALL audio — record it once with how late it was. Sub-threshold scheduling
864        // noise (≲ half a tick) is ignored so the log stays signal.
865        if late_us >= TICK_LATE_GLITCH_US {
866            tick_glitches.push(AudioGlitch {
867                at_us: now_us,
868                peer_tag: NO_PEER_TAG,
869                label: "tick",
870                kind: GlitchKind::LateTick,
871                detail_us: late_us.min(i64::MAX as u128) as i64,
872            });
873        }
874        if !tick_glitches.is_empty()
875            && let Ok(mut ring) = glitch_ring.lock()
876        {
877            for g in tick_glitches.drain(..) {
878                if ring.len() >= GLITCH_RING_CAP {
879                    ring.pop_front();
880                }
881                ring.push_back(g);
882            }
883        }
884        if let Some(p) = playback.as_ref() {
885            // Fold the device-side gap (silence the RT callback had to insert since
886            // last tick) into the shared counter the app surfaces.
887            let under = p.take_output_underruns();
888            if under > 0 {
889                output_underruns.fetch_add(under, Ordering::Relaxed);
890            }
891            // Non-fatal faults the sink demoted rather than dying on (cpal `Xrun` /
892            // `RealtimeDenied`). Counted here so the demotion stays measurable — a
893            // sustained storm keeps pushing the debounce out and so never produces the
894            // reopen that would otherwise be its only trace.
895            let soft = p.take_soft_faults();
896            if soft > 0 {
897                output_soft_faults.fetch_add(soft, Ordering::Relaxed);
898            }
899            // Neither an AUTOMATIC reroute nor a demoted quality fault is a death: the
900            // stream is still live and playing. After a reroute what went stale is our
901            // GEOMETRY — the sink's `device_rate`, its 48 k→device resampler, and hence
902            // the millisecond scale of the `buffered_ms` the cushion regulator above
903            // reads (a 48 k→24 k hop halves it); after an xrun / refused RT promotion
904            // the remedy worth having is a fresh cushion. Both want the SAME thing: not
905            // a teardown here, just (re-)arm the debounce and re-sync once it goes quiet.
906            // A continuous fault storm never goes quiet, so it never reopens at all —
907            // which is correct, since reopening under sustained xruns only thrashes.
908            if p.take_route_changed() {
909                let flapping = route_settle.due.is_some();
910                route_settle.note_change(Instant::now());
911                if !flapping {
912                    tracing::info!(
913                        soft_faults = soft,
914                        "voice: output reported a non-fatal condition (auto-reroute, or \
915                         an xrun / refused RT promotion) — stream still live; device \
916                         re-sync armed in {:?}",
917                        ROUTE_SETTLE
918                    );
919                }
920            }
921            // A dead stream (the device vanished / the config was invalidated) leaves
922            // this sink object alive but draining nothing — drop it so the reopen path
923            // below re-opens the current device. Otherwise output stays silent until a
924            // manual speaker hot-swap. A real death OUTRANKS a pending re-sync: the
925            // reopen below already gives us fresh geometry.
926            if p.is_dead() {
927                // The cause was captured by the stream's error callback (which only
928                // warned — recovery had not been tried yet); carry it so an outage
929                // that never recovers can name what actually broke.
930                let cause = p.take_stream_error();
931                tracing::warn!(
932                    cause = cause.as_deref().unwrap_or("<no error captured>"),
933                    "voice: output stream died — reopening the device"
934                );
935                health.died(Instant::now(), cause);
936                drop(playback.take());
937                route_settle.disarm();
938                // Leave `last_open_attempt` alone (it is the last *successful* open,
939                // long ago for a stream that ran fine) so the reopen path below fires
940                // on the NEXT tick rather than after a backoff; reset the ladder so a
941                // genuinely-down device still backs off from the fast cadence.
942                reopen_backoff = REOPEN_BACKOFF;
943            }
944        }
945        // The route has been quiet for `ROUTE_SETTLE`: rebuild the sink ONCE against the
946        // device the OS finally landed on, so `dev_rate`/resampler/cushion geometry
947        // describe it. Deliberately NOT conditioned on the new default device's rate
948        // matching the old one: querying that would mean a blocking CoreAudio property
949        // read on this real-time thread, which is exactly the cost this whole change is
950        // removing. One unconditional reopen per settled burst (5 → 1) is the trade.
951        if route_settle.fire(Instant::now()) && playback.is_some() {
952            tracing::info!("voice: output route settled — re-opening the sink to re-sync geometry");
953            drop(playback.take());
954            reopen_backoff = REOPEN_BACKOFF;
955        }
956        ticks.fetch_add(1, Ordering::Relaxed);
957
958        // No live device: retry opening the current choice on an exponential
959        // backoff (the vanished named speaker falls back to default inside
960        // `start`). On success reset to the fast cadence; on continued failure
961        // grow toward the cap so a persistently-held device is a slow heartbeat,
962        // not a 2 Hz storm.
963        if playback.is_none()
964            && !stop.load(Ordering::Relaxed)
965            && last_open_attempt.elapsed() >= reopen_backoff
966        {
967            let began = Instant::now();
968            playback = open_sink(&mut sink_factory, &choice, &mut health, began);
969            prefill_output(&mut playback);
970            // Re-arm the one-shot BT/HFP warmup. This reopen can land on a 24 kHz SCO
971            // route that is not carrying audio yet — exactly the initial-open case — and
972            // without this the reopened sink plays silence forever with no error to
973            // trigger another one. Safe from a reopen loop BECAUSE of the route debounce
974            // above: a flap burst coalesces into a single reopen, so the warmup arms once
975            // per settled route rather than once per reroute event.
976            warmup_reopen = warmup_reopen_at(&playback, Instant::now());
977            last_open_attempt = Instant::now();
978            reopen_backoff = if playback.is_some() {
979                // A reopen is an audible event in its own right (a blocking device open on
980                // this RT thread + a fresh silence prefill), so record it — otherwise the
981                // resulting tick slip and output underruns get diagnosed as CPU
982                // contention. Only successful opens are recorded; failed retries are the
983                // backoff ladder's business, not the glitch log's.
984                record_glitch(
985                    &glitch_ring,
986                    AudioGlitch {
987                        at_us: clock.now(),
988                        peer_tag: NO_PEER_TAG,
989                        label: "output",
990                        kind: GlitchKind::DeviceReopen,
991                        detail_us: began.elapsed().as_micros().min(i64::MAX as u128) as i64,
992                    },
993                );
994                REOPEN_BACKOFF
995            } else {
996                (reopen_backoff * 2).min(REOPEN_BACKOFF_MAX)
997            };
998        }
999
1000        // Still no device at the end of this tick — the outage clock runs and, once
1001        // the whole reopen ladder has demonstrably failed, files the ONE error event
1002        // this path ever produces. A device that comes back before then (the normal
1003        // case for an unplug/suspend/EIO) never reaches Sentry at all.
1004        if playback.is_none() {
1005            health.poll_down(Instant::now());
1006        }
1007    }
1008
1009    // Dropping the sink releases the device on this (owning) thread.
1010    drop(playback);
1011}

1196    /// **Concealed audio must not deepen the buffer.** The estimator provisions for the
1197    /// windowed MAX transit deviation, so one fabricated observation costs the full peak
1198    /// window of added latency. This replays the exact shape the receive pipeline pushes
1199    /// — a clean link, then a gap concealed with PLC frames stamped at the local `now`
1200    /// of the real frame behind them (which is later than that frame's own wire arrival,
1201    /// by the reorder hold) — and pins that neither the concealment nor the real frame
1202    /// after it moves the recommendation. Measured before the fix, this same sequence
1203    /// booked +62.6 ms then −61.7 ms against a true wire deviation of +0.9 ms.
1204    #[test]
1205    fn concealed_pushes_never_reach_the_jitter_estimator() {
1206        const FLOOR_US: i64 = 80_000;
1207        const FRAME_US: i64 = 20_000;
1208        /// The reorder hold: how far the local push instant trails the wire arrival.
1209        const HOLD_US: i64 = 60_000;
1210        let registry = Arc::new(Registry::default());
1211        let slot = Arc::new(Slot::new(
1212            Arc::new(AtomicU64::new(0)),
1213            FLOOR_US,
1214            "test",
1215            NO_PEER_TAG,
1216        ));
1217        registry.slots.lock().unwrap().insert(0, slot.clone());
1218        let producer = BusProducer {
1219            id: 0,
1220            slot,
1221            registry,
1222        };
1223        let pcm = [0i16; 64];
1224
1225        // 1 s of a perfect link: arrival tracks capture, so the depth idles at the floor.
1226        let mut status = None;
1227        for k in 0..50i64 {
1228            let ts = k * FRAME_US;
1229            status = Some(producer.push_at(ts, ts + HOLD_US, ts, &pcm));
1230        }
1231        let base = status.expect("pushed").recommended_delay_us;
1232        assert_eq!(
1233            base, FLOOR_US,
1234            "precondition: a clean link idles at the floor"
1235        );
1236
1237        // A 100 ms hole: 5 frames concealed, then the real frame behind them. The PLC
1238        // frames carry no arrival; the real one carries its wire arrival, which is
1239        // HOLD_US BEFORE the instant the PLC was synthesized at.
1240        let last_ts = 49 * FRAME_US;
1241        let real_ts = last_ts + 6 * FRAME_US;
1242        let real_arrival = real_ts; // on time — the gap was loss, not delay
1243        let now = real_arrival + HOLD_US;
1244        for i in 1..=5i64 {
1245            producer.push_concealed(now, last_ts + i * FRAME_US, &pcm);
1246        }
1247        let after = producer.push_at(real_arrival, now, real_ts, &pcm);
1248        assert_eq!(
1249            after.recommended_delay_us, base,
1250            "loss is not jitter: a concealed gap leaves the depth where the link left it"
1251        );
1252    }
