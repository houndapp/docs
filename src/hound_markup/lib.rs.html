1//! Hound's message format: CommonMark plus a fixed extension set.
2//!
3//! A message is markup wherever it's composed or read — the backend stores
4//! raw source and re-parses it on the way out, the Flutter client's Rust
5//! core parses the exact same source through this same crate via
6//! flutter_rust_bridge. **The one invariant this crate exists to hold**:
7//! server and client run this exact crate, built against the exact `comrak`
8//! version and dialect pinned in [`parse`] — so what a reader sees resolved
9//! as a `hound:` reference is exactly what the composer typed and exactly
10//! what the server extracted, never a client-only or server-only reading of
11//! the source.
12//!
13//! - [`ast`] — [`Document`]/[`Block`]/[`Inline`]: plain owned data safe to
14//!   cross the FFI boundary (no lifetimes, no references, no maps;
15//!   recursion only through `Vec`).
16//! - [`parse`] — comrak wrapped behind a single, total entry point; comrak's
17//!   AST types never escape this crate.
18//! - [`reference`] — `hound:<kind>/<uuid>` references: hound's in-message
19//!   links to its own objects.
20//! - [`plain_text`] — rendering a [`Document`] back to plain text for
21//!   previews and notifications, with references resolved to display names.
22//! - [`validate`] — the length and reference-count limits enforced on every
23//!   accepted message.
24//! - [`kind`] — [`ContentKind`]: the coarse content facets ("has code", "has
25//!   a picture") a search filters on.
26//! - [`parsed`] — [`ParsedMessage`]: a body plus everything derived from it,
27//!   in one pass. The entry point for anything that *writes* a message.
28
