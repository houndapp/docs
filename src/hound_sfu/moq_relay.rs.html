1//! # MoQ relay — the native forward plane
2//!
3//! The MoQ forward plane: a thin, forward-only relay that fans every publisher's
4//! encoded media out to the other subscribers in the same space. This is the
5//! only media path the SFU serves — clients dial the [`RELAY_ALPN`] (`moql`)
6//! ALPN, negotiated via [`crate::sfu::Sfu`].
7//!
8//! ## Forward-only, no transcode
9//!
10//! The relay never decodes media. It re-emits the encoded objects a publisher
11//! writes to every subscriber of that track, byte-for-byte. moq-net owns the
12//! actual fan-out and per-subscriber prioritisation: each GOP is one QUIC
13//! uni-stream and the consumer's `next_group` priority-drops a stale group at
14//! its boundary, so a receiver never freezes replaying stale deltas while a
15//! fresh keyframe group waits. We do not hand-roll routing tables, NACK caches,
16//! or SSRC/seq rewrites — that is exactly what MoQ's group/object model gives
17//! us for free.
18//!
19//! ## How moq-net does the forwarding (the Origin)
20//!
21//! moq-net routes through a shared [`moq_net::Origin`]: a tree of broadcast
22//! paths. A [`moq_net::Server`] session is wired with two halves of that origin:
23//!
24//! * `with_consume(OriginProducer)` — "consume any **remote** broadcasts,
25//!   inserting them into this origin" (the publisher half: a connected publisher
26//!   announces a broadcast and moq-net inserts it into our shared origin).
27//! * `with_publish(OriginConsumer)` — "publish any **local** broadcasts from
28//!   this origin to the remote" (the subscriber half: a connected subscriber's
29//!   SUBSCRIBE is served from whatever the shared origin holds).
30//!
31//! Give every connection both halves of **one shared root origin** and moq-net
32//! itself forwards: publisher A announces `space/X/peer/A/video` into the origin
33//! → subscriber B's session sees the announce and serves the objects. The relay
34//! code never copies a byte; it only owns the origin and the auth gate.
35//!
36//! ## Auth gate (the mandatory bit)
37//!
38//! moq-net itself does not authenticate. Before any media flows we:
39//!
40//! 1. **Validate the relay-token JWT-equivalent** the client presents on a
41//!    dedicated control bi-stream, reusing [`crate::auth::verify_relay_token`]
42//!    (the same HMAC-SHA256 `{user}:{space}:{expiry}:{mac}` scheme the backend
43//!    mints). A bad/expired/missing token is rejected before the MoQ handshake
44//!    runs. The whole exchange is bounded by [`RelayConfig::auth_deadline`] (see
45//!    [`handle_connection`]) — a client that completes the QUIC handshake but
46//!    never opens/finishes the token stream cannot hold the connection open
47//!    indefinitely.
48//! 2. **Admit the session against [`SessionLimits`]** — a global cap and a
49//!    per-user cap, checked right after a successful token verification and
50//!    before the moq-net handshake runs (see [`SessionRegistry`]). Over-cap is a
51//!    clean [`AUTH_REJECT`], not a dropped connection.
52//! 3. **Scope the connection to its space** — always, both halves. From the
53//!    validated [`crate::auth::RelayTokenClaims`] we derive the namespace prefix
54//!    `space/{space_id}` and hand the moq-net session an origin **scoped** to it
55//!    via [`moq_net::OriginProducer::scope`] / [`moq_net::OriginConsumer::scope`].
56//!    A scoped producer's `publish_broadcast` returns `false` for any path
57//!    outside the prefix, and a scoped consumer never sees announcements outside
58//!    it — so a participant authenticated for space A **cannot** announce or
59//!    subscribe to space B's namespace. moq-net enforces the boundary; we just
60//!    set it from the token.
61//! 4. **Scope the INGEST half to the caller's own peer namespace, always.** The
62//!    two halves of a session are scoped independently (see
63//!    [`handle_connection`]): the SERVE half (`with_publish`, subscribing)
64//!    stays `space/{space_id}` — a participant must be able to subscribe to
65//!    anyone in the call. The INGEST half (`with_consume`, announcing) is
66//!    tightened to `space/{space_id}/peer/{user_id}`, so a connection
67//!    authenticated as user A can only announce broadcasts under its own
68//!    `user_id` sub-path — it can never publish (or displace, via moq-net's
69//!    route tie-break) under another peer's path. This is what makes the
70//!    `peer/{user_id}/{peer_id}/{track}` tail of [`NAMESPACE_CONVENTION`] a
71//!    real boundary rather than just a naming convention.
72//!
73//! This is **call-membership + per-user-namespace** auth. Per-track allow-listing
74//! (which *peer* may publish which *track* within a space, driven by
75//! `hound-control`'s `SessionServer` roster) remains a later refinement.
76//!
77//! ## Ongoing per-connection budgets (after admission)
78//!
79//! Auth and [`SessionRegistry::admit`] are one-time checks at connection
80//! start. A connection that passes both can still misbehave for the rest of
81//! its life — flooding ingress bytes, or announcing an unbounded number of
82//! broadcast paths — so [`handle_connection`] also spawns a per-connection
83//! [`ingress_watchdog`] that runs for the session's whole lifetime, enforcing
84//! [`IngressLimits`] and logging a periodic ops summary. See that function's
85//! doc for the enforcement details and close-code scheme.

100/// MoQ ALPN the relay accepts. Must be a moq-net ALPN: in raw mode
101/// `web-transport-iroh` reports the iroh connection's ALPN as the MoQ protocol
102/// and moq-net rejects an unrecognised one with `Error::UnknownAlpn`. `moql` is
103/// moq-net's version-negotiation ALPN and matches the client
104/// (`hound_transport::ALPN`). This is the only ALPN the SFU endpoint advertises.
105pub const RELAY_ALPN: &[u8] = b"moql";

107/// Marker documenting that [`RELAY_ALPN`] is the moq-net negotiation ALPN, not a
108/// free-to-choose `hound-*` value (the latter fails the handshake).
109pub const RELAY_ALPN_PREFIX: &[u8] = b"moq";

111/// The broadcast-namespace convention every announce/subscribe must obey.
112///
113/// ```text
114/// space/{space_id}/peer/{user_id}/{peer_id}/{track}
115/// ```
116///
117/// `user_id` is the AUTHENTICATED identity from the relay token / `PeerInfo`
118/// roster (a UUID) — the segment the relay enforces. `peer_id` is the
119/// control-plane-assigned `u32` tail that keeps a single user's multiple
120/// devices/sessions distinct within their own namespace.
121///
122/// The relay ALWAYS scopes each authenticated connection's SERVE (subscribe)
123/// half to the `space/{space_id}` prefix taken from its relay token — moq-net
124/// refuses any subscribe outside it (no cross-space leakage). The INGEST
125/// (publish) half is ALWAYS additionally tightened to
126/// `space/{space_id}/peer/{user_id}`, so a connection can only announce under
127/// its own authenticated user's sub-path — see [`handle_connection`] and
128/// [`peer_scope`]. Per-track allow-listing (e.g. gating who may publish a
129/// specific `hound-control` `TrackId`) remains a later refinement.
130pub const NAMESPACE_CONVENTION: &str = "space/{space_id}/peer/{user_id}/{peer_id}/{track}";

132/// Maximum relay-token length accepted on the control stream. A valid token is
133/// `36 + 1 + 36 + 1 + ~10 + 1 + 64 ≈ 150` bytes; this bound stops a malicious
134/// client pinning memory with a giant "token".
135const MAX_TOKEN_LEN: usize = 512;
136
137/// One-byte control-stream replies the relay sends after token verification.
138/// The client gates its MoQ handshake on reading [`AUTH_OK`].
139const AUTH_OK: u8 = 1;
140const AUTH_REJECT: u8 = 0;
141
142/// How long the relay waits, after sending an [`AUTH_REJECT`], for the client to
143/// read the verdict and close the connection before the handler gives up. A
144/// safety valve so a vanished client can't pin the task; we only care that the
145/// reject byte had a chance to land.
146const AUTH_REJECT_DRAIN: Duration = Duration::from_secs(5);
147
148/// Deadline for the whole relay-token control-stream handshake (`authenticate`:
149/// `accept_bi` + the two `read_exact`s). QUIC's automatic keepalives mean the
150/// idle timeout never fires on its own, so a bound here is the only thing
151/// stopping a client that completes the QUIC handshake but never opens (or
152/// never finishes) the token stream from holding the connection — and the task
153/// serving it — open indefinitely. [`SessionRegistry`] admission only ever runs
154/// after a successful auth (see `handle_connection`), so this deadline is also
155/// what keeps an unauthenticated connection from ever holding a session slot or
156/// blocking the SIGTERM drain wait: bounding "unauthenticated" bounds the
157/// exposure. Production default (see [`RelayConfig::default`]); tests
158/// substitute a much shorter value to exercise the timeout deterministically.
159pub const AUTH_DEADLINE: Duration = Duration::from_secs(10);

182/// Ongoing per-connection ingress budget, enforced continuously by
183/// [`ingress_watchdog`] for the life of an admitted session — unlike
184/// [`SessionLimits`] (checked once at admission), this is a running check
185/// against traffic the connection generates after it's already in the call.
186#[derive(Debug, Clone, Copy)]
187pub struct IngressLimits {
188    /// Sustained ingress cap in bytes/sec, read from `conn.stats().udp_rx.bytes`
189    /// (cumulative QUIC bytes received — the actual cost to the node, not just
190    /// media payload). `0` disables the budget. The default (~24 Mbit/s) is
191    /// generous headroom over the heaviest legitimate publisher (source + low
192    /// simulcast video, screenshare, audio).
193    pub max_bytes_per_sec: u64,
194    /// How often [`ingress_watchdog`] samples `conn.stats()`. Kept separate
195    /// from `window` (rather than derived from it) so tests can shrink both
196    /// independently instead of waiting out the production window.
197    pub sample_interval: Duration,
198    /// Sustained-rate averaging span handed to [`IngressBudget::new`] — a
199    /// spike shorter than this self-corrects (see that type's doc); a rate
200    /// held for the whole window trips.
201    pub window: Duration,
202    /// Maximum distinct broadcast paths ONE session (one `{peer_id}` under
203    /// `space/{s}/peer/{user_id}`) may have announced at once before
204    /// [`ingress_watchdog`] closes the connection; the identity as a whole is
205    /// bounded at `this × ` [`SessionLimits::max_per_user`], derived so the
206    /// two cannot drift. `0` disables enforcement. Bounds unbounded
207    /// origin-tree growth / task spawn from a connection announcing without
208    /// limit. The default leaves ~2.5× headroom over the six paths a live
209    /// client announces eagerly (`mic`, `cam`, `cam_l0`, `screen`,
210    /// `screen_l0`, `screen_audio`) — see [`crate::ingress::BroadcastQuota`]
211    /// for the grouping, and [`ingress_watchdog`]'s doc for why the announce
212    /// stream is identity-wide in the first place.
213    pub max_broadcasts_per_session: usize,
214}
215
216impl Default for IngressLimits {
217    /// Production defaults — see `main.rs`'s `MAX_INGRESS_BYTES_PER_SEC` /
218    /// `MAX_BROADCASTS_PER_SESSION` CLI flags, which override
219    /// `max_bytes_per_sec` / `max_broadcasts_per_session`. `sample_interval`
220    /// and `window` are not exposed as CLI flags (only tests need to shrink
221    /// them).
222    fn default() -> Self {
223        Self {
224            max_bytes_per_sec: 3_000_000,
225            sample_interval: Duration::from_secs(5),
226            window: Duration::from_secs(30),
227            max_broadcasts_per_session: 16,
228        }
229    }
230}

301/// Why [`SessionRegistry::admit`] refused a session — carries the count that
302/// triggered the rejection, purely for the log line at the call site.
303#[derive(Debug, Clone, Copy, PartialEq, Eq)]
304enum AdmitRejected {
305    /// The global cap was at (or, transiently, just over) this count.
306    Global(usize),
307    /// This user's own cap was at this count.
308    PerUser(usize),
309}
310
311/// Shared session accounting: a global count plus a per-user count, gating
312/// admission at [`SessionLimits`] and released via [`SessionGuard`]. Cheap to
313/// clone (every field is `Arc`-backed) — each accept-loop task holds its own
314/// clone.
315///
316/// Only *authenticated* sessions are ever admitted here (see
317/// [`handle_connection`]), so [`SessionRegistry::active_sessions`] — the
318/// counter `main`'s SIGTERM drain wait polls — never counts a connection that
319/// never passed the auth gate.
320#[derive(Clone)]
321pub struct SessionRegistry {
322    active: Arc<AtomicUsize>,
323    per_user: Arc<Mutex<HashMap<Uuid, usize>>>,
324    limits: SessionLimits,
325}
326
327impl SessionRegistry {
328    pub fn new(limits: SessionLimits) -> Self {
329        Self {
330            active: Arc::new(AtomicUsize::new(0)),
331            per_user: Arc::new(Mutex::new(HashMap::new())),
332            limits,
333        }
334    }
335
336    /// Shared handle on the global active-session counter.
337    pub fn active_sessions(&self) -> Arc<AtomicUsize> {
338        self.active.clone()
339    }
340
341    /// How many concurrent sessions one identity may hold — the multiplier the
342    /// watchdog derives its identity-wide broadcast cap from, so the two
343    /// cannot drift (see [`IngressLimits::max_broadcasts_per_session`]).
344    fn max_per_user(&self) -> usize {
345        self.limits.max_per_user
346    }
347
348    /// Try to admit one session for `user_id`.
349    ///
350    /// Reserves global capacity with `fetch_add` first and rolls it back on
351    /// rejection, rather than check-then-increment, so two concurrent
352    /// accept-loop tasks racing the last slot can't both observe "space
353    /// available" and overshoot the cap. `Ok` also bumps the per-user count and
354    /// returns the RAII guard that reverses both counters on drop; `Err` leaves
355    /// every counter exactly as it found it.
356    fn admit(&self, user_id: Uuid) -> Result<SessionGuard, AdmitRejected> {
357        let active = self.active.fetch_add(1, Ordering::SeqCst) + 1;
358        if active > self.limits.max_sessions {
359            self.active.fetch_sub(1, Ordering::SeqCst);
360            metrics::counter!("sfu_sessions_rejected_total", "reason" => "global_cap").increment(1);
361            return Err(AdmitRejected::Global(active - 1));
362        }
363
364        let mut per_user = self.per_user.lock().unwrap();
365        let count = per_user.entry(user_id).or_insert(0);
366        if *count >= self.limits.max_per_user {
367            let count = *count;
368            drop(per_user);
369            self.active.fetch_sub(1, Ordering::SeqCst);
370            metrics::counter!("sfu_sessions_rejected_total", "reason" => "per_user_cap")
371                .increment(1);
372            return Err(AdmitRejected::PerUser(count));
373        }
374        *count += 1;
375        drop(per_user);
376
377        metrics::gauge!("sfu_active_sessions").increment(1.0);
378        metrics::counter!("sfu_sessions_admitted_total").increment(1);
379        Ok(SessionGuard {
380            active: self.active.clone(),
381            per_user: self.per_user.clone(),
382            user_id,
383        })
384    }
385}

387/// RAII guard for one admitted session: decrements the global count and its
388/// user's per-user entry on drop (removing the entry once it reaches zero), so
389/// a panic or early return anywhere in the connection handler still releases
390/// capacity — admission can never wedge on a phantom session.
391pub struct SessionGuard {
392    active: Arc<AtomicUsize>,
393    per_user: Arc<Mutex<HashMap<Uuid, usize>>>,
394    user_id: Uuid,
395}
396
397impl Drop for SessionGuard {
398    fn drop(&mut self) {
399        self.active.fetch_sub(1, Ordering::SeqCst);
400        metrics::gauge!("sfu_active_sessions").decrement(1.0);
401        let mut per_user = self.per_user.lock().unwrap();
402        if let std::collections::hash_map::Entry::Occupied(mut entry) = per_user.entry(self.user_id)
403        {
404            *entry.get_mut() -= 1;
405            if *entry.get() == 0 {
406                entry.remove();
407            }
408        }
409    }
410}

412// ─── Pre-auth admission ──────────────────────────────────────────────────────
413
414/// How many times [`SessionLimits::max_sessions`] the pre-auth population may
415/// reach before new connections are refused. [`SessionRegistry`] deliberately
416/// admits only *authenticated* sessions (so the SIGTERM drain never waits on a
417/// stranger), which leaves the accept→auth window uncapped: every accepted
418/// connection costs a task plus quinn connection state for up to
419/// `auth_deadline` + [`AUTH_REJECT_DRAIN`]. Headroom is generous — a mass
420/// reconnect after an SFU restart is legitimate and must not be refused — the
421/// point is a ceiling that exists at all, and a counter that makes hitting it
422/// visible.
423const PRE_AUTH_HEADROOM: usize = 4;
424
425/// Bounds the connections in flight between `accept()` and the auth verdict.
426///
427/// A permit is taken *before* the QUIC handshake is driven (so the handshake
428/// cost itself is bounded) and released the moment [`SessionRegistry::admit`]
429/// succeeds — from there the session guard is the accounting. Refusals bump
430/// `sfu_connections_refused_total{reason="pre_auth_cap"}`; the in-flight count
431/// is exported as `sfu_preauth_connections`.
432#[derive(Clone)]
433pub struct PreAuthGate {
434    permits: Arc<tokio::sync::Semaphore>,
435}
436
437impl PreAuthGate {
438    pub(crate) fn new(capacity: usize) -> Self {
439        Self {
440            permits: Arc::new(tokio::sync::Semaphore::new(capacity.max(1))),
441        }
442    }
443
444    /// Derive the gate from the session caps, so the two can never drift.
445    pub(crate) fn for_limits(limits: SessionLimits) -> Self {
446        Self::new(limits.max_sessions.saturating_mul(PRE_AUTH_HEADROOM))
447    }
448
449    /// `None` when the pre-auth population is at capacity — the caller must
450    /// refuse the connection rather than queue it.
451    pub(crate) fn try_admit(&self) -> Option<PreAuthPermit> {
452        match self.permits.clone().try_acquire_owned() {
453            Ok(permit) => {
454                metrics::gauge!("sfu_preauth_connections").increment(1.0);
455                Some(PreAuthPermit { _permit: permit })
456            }
457            Err(_) => {
458                metrics::counter!("sfu_connections_refused_total", "reason" => "pre_auth_cap")
459                    .increment(1);
460                None
461            }
462        }
463    }
464
465    /// Permits currently available — tests assert the gate is exhausted and
466    /// restored without reaching into the semaphore.
467    #[cfg(test)]
468    fn available(&self) -> usize {
469        self.permits.available_permits()
470    }
471}

477    _permit: tokio::sync::OwnedSemaphorePermit,

486// ─── Origin-scope accounting ─────────────────────────────────────────────────
487
488/// Observability for the shared origin tree's monotonic growth.
489///
490/// `OriginProducer::scope` *materialises* a node per missing path segment, so
491/// each first-seen `space/{space}` and `space/{space}/peer/{user}` inserts a
492/// node into the process-wide tree — and moq-net 0.1.9 has no prune/gc entry
493/// point (its own `unconsume` carries a commented-out `TODO: empty node;
494/// memory leak`), so nothing ever removes them. A refcount-and-prune would
495/// need an upstream API that does not exist, so this exports the growth
496/// instead: `sfu_origin_spaces` and `sfu_origin_scopes` are the node counts
497/// the tree is retaining, alertable rather than invisible.
498///
499/// The tracker's own sets grow the same way by construction — that is the
500/// point, they mirror what the tree holds — at ~48 bytes per pair against the
501/// `OriginNode` (nested map + notify node) it is accounting for.
502#[derive(Clone, Default)]
503pub struct OriginScopes {
504    inner: Arc<Mutex<OriginScopesInner>>,
505}
506
507#[derive(Default)]
508struct OriginScopesInner {
509    spaces: HashSet<Uuid>,
510    peers: HashSet<(Uuid, Uuid)>,
511}
512
513impl OriginScopes {
514    /// Record the two scopes one authenticated connection materialises.
515    fn record(&self, space_id: Uuid, user_id: Uuid) {
516        let mut inner = self.inner.lock().unwrap();
517        inner.spaces.insert(space_id);
518        inner.peers.insert((space_id, user_id));
519        metrics::gauge!("sfu_origin_spaces").set(inner.spaces.len() as f64);
520        metrics::gauge!("sfu_origin_scopes").set(inner.peers.len() as f64);
521    }
522
523    #[cfg(test)]
524    fn counts(&self) -> (usize, usize) {
525        let inner = self.inner.lock().unwrap();
526        (inner.spaces.len(), inner.peers.len())
527    }
528}

532/// Everything a connection handler needs from the accepting server, cloned
533/// once per connection — every field is `Arc`-backed or a short `String`.
534/// Bundled rather than passed as six positional arguments so
535/// [`crate::sfu::Sfu`] and [`Relay`] hand the handler an identical context.
536#[derive(Clone)]
537pub(crate) struct ConnectionEnv {
538    /// Shared root origin every connection gets a scoped view of.
539    pub origin: OriginProducer,
540    pub relay_hmac_secret: String,
541    pub registry: SessionRegistry,
542    pub scopes: OriginScopes,
543    pub auth_deadline: Duration,
544    pub ingress: IngressLimits,
545}

547/// Errors from the relay's connection-acceptance / auth path. moq-net session
548/// errors after a successful handshake are logged inside the spawned session
549/// task, not surfaced here.
550#[derive(Debug, thiserror::Error)]
551pub enum RelayError {
552    /// An iroh stream/connection operation failed during the handshake.
553    #[error("iroh: {0}")]
554    Iroh(String),
555    /// The relay token was missing, malformed, failed verification, timed out,
556    /// or the session was over a [`SessionLimits`] cap.
557    #[error("auth: {0}")]
558    Auth(String),
559    /// The moq-net server handshake failed.
560    #[error("moq: {0}")]
561    Moq(String),
562}

564/// Create a fresh, wildcard-scoped root [`OriginProducer`] — the shared origin
565/// through which moq-net forwards every broadcast.
566///
567/// Every accepted relay connection gets a *space-scoped view* of this same
568/// origin (see [`handle_relay_connection`]), so a publisher and a subscriber in
569/// the same space meet here and moq-net fans the objects out. [`Relay`] builds
570/// one internally; the dual-ALPN SFU loop ([`crate::sfu::Sfu`]) builds one too so
571/// it can serve the relay on its own endpoint without constructing a [`Relay`].
572pub(crate) fn new_root_origin() -> OriginProducer {
573    Origin::random().produce()
574}
575
576/// Build the `space/{space_id}` namespace prefix a connection is scoped to.
577///
578/// This is the call-membership boundary: everything a participant may announce
579/// or subscribe lives under this prefix, and moq-net rejects anything outside
580/// it. The SERVE (subscribe) half is ALWAYS scoped to this — see [`peer_scope`]
581/// for the tighter INGEST-half prefix.
582fn space_scope(claims: &RelayTokenClaims) -> String {
583    format!("space/{}", claims.space_id)
584}
585
586/// Build the `space/{space_id}/peer/{user_id}` namespace prefix the INGEST
587/// (publish) half is ALWAYS scoped to. `user_id` comes from the validated relay
588/// token, never the client — so a connection can only announce broadcasts under
589/// its own authenticated user's sub-path, closing the "any space member can
590/// announce under (and displace) another peer's path" hole.
591fn peer_scope(claims: &RelayTokenClaims) -> String {
592    format!("space/{}/peer/{}", claims.space_id, claims.user_id)
593}

595/// The MoQ relay server.
596///
597/// Owns the iroh [`Endpoint`], the shared [`OriginProducer`] root through which
598/// moq-net forwards every broadcast, the relay-token HMAC secret, and the
599/// [`SessionRegistry`] admission accounting. Call [`Relay::run`] to accept
600/// connections.
601///
602/// This is a standalone-relay convenience used by tests; the production binary
603/// drives the same [`handle_connection`] logic through [`crate::sfu::Sfu`]
604/// instead so the service endpoint is a single iroh node.
605pub struct Relay {
606    endpoint: Endpoint,
607    /// Per-connection context (shared root origin, secret, registry, budgets)
608    /// — cloned per accepted connection. The origin's wildcard scope is what
609    /// lets a publisher in space X and a subscriber in space X meet, so
610    /// moq-net can fan the objects out.
611    env: ConnectionEnv,
612    /// Bounds the accept→auth population — see [`PreAuthGate`].
613    pre_auth: PreAuthGate,
614}
615
616impl Relay {
617    /// Build a relay around an already-bound iroh [`Endpoint`].
618    ///
619    /// The caller is responsible for having advertised [`RELAY_ALPN`] on the
620    /// endpoint. Mirrors [`crate::sfu::Sfu::from_endpoint`] so the hermetic
621    /// tests exercise the same accept/auth glue that runs in production.
622    pub fn from_endpoint(
623        endpoint: Endpoint,
624        relay_hmac_secret: String,
625        config: RelayConfig,
626    ) -> Self {
627        Self {
628            endpoint,
629            env: ConnectionEnv {
630                origin: new_root_origin(),
631                relay_hmac_secret,
632                registry: SessionRegistry::new(config.limits),
633                scopes: OriginScopes::default(),
634                auth_deadline: config.auth_deadline,
635                ingress: config.ingress,
636            },
637            pre_auth: PreAuthGate::for_limits(config.limits),
638        }
639    }
640
641    /// The iroh node id clients dial to reach this relay.
642    pub fn node_id(&self) -> iroh::EndpointId {
643        self.endpoint.id()
644    }
645
646    /// Shared handle on the active-session counter — see
647    /// [`SessionRegistry::active_sessions`]. Exposed for tests asserting that a
648    /// rejected/timed-out connection never touches it.
649    pub fn active_sessions(&self) -> Arc<AtomicUsize> {
650        self.env.registry.active_sessions()
651    }
652
653    /// Accept connections in a loop until the endpoint closes.
654    ///
655    /// Each connection is handed to [`handle_connection`] in its own task,
656    /// **including its QUIC handshake** — see [`crate::sfu::Sfu::run`] for why
657    /// awaiting the handshake in the loop body serialises every client's join.
658    /// The per-connection context is cloned per connection (cheap: the origin
659    /// and registry are `Arc`-backed, the secret is a short `String`).
660    pub async fn run(&self) -> eyre::Result<()> {
661        tracing::info!(node_id = %self.endpoint.id(), "MoQ relay accepting connections");
662
663        loop {
664            let Some(incoming) = self.endpoint.accept().await else {
665                tracing::info!("MoQ relay endpoint closed — stopping accept loop");
666                break;
667            };
668
669            let Some(pre_auth) = self.pre_auth.try_admit() else {
670                tracing::warn!("pre-auth capacity reached — refusing incoming relay connection");
671                incoming.refuse();
672                continue;
673            };
674
675            let env = self.env.clone();
676            tokio::spawn(async move {
677                let conn = match incoming.await {
678                    Ok(c) => c,
679                    Err(e) => {
680                        tracing::warn!("incoming relay connection failed: {e}");
681                        return;
682                    }
683                };
684                if let Err(e) = handle_connection(conn, env, pre_auth).await {
685                    tracing::warn!("relay connection handler error: {e}");
686                }
687            });
688        }
689
690        Ok(())
691    }
692}

694/// Handle one incoming MoQ relay connection on a **shared** origin.
695///
696/// This is the per-connection relay logic factored out of [`Relay::run`] so the
697/// SFU service's accept loop ([`crate::sfu::Sfu::run`]) can drive the relay
698/// with the SFU's shared origin, relay secret, and session registry.
699/// [`Relay::run`] (used by the standalone relay tests) and the SFU loop both
700/// call it, so they exercise identical auth/admission/scoping/session glue.
701pub(crate) async fn handle_relay_connection(
702    conn: iroh::endpoint::Connection,
703    env: ConnectionEnv,
704    pre_auth: PreAuthPermit,
705) -> Result<(), RelayError> {
706    handle_connection(conn, env, pre_auth).await
707}

709/// Handle one incoming MoQ relay connection: authenticate, admit, scope, run
710/// the moq-net server session.
711///
712/// ## Stream ordering (why the token stream is accepted first)
713///
714/// The client opens the **relay-token control bi-stream first** and awaits the
715/// relay's [`AUTH_OK`] before starting its MoQ handshake. The relay accepts that
716/// bi-stream (`conn.accept_bi`) before handing the connection to
717/// [`moq_net::Server::accept`] (which opens *its own* control stream). QUIC
718/// bi-streams are accepted in open order, so the token exchange always lands
719/// before the MoQ control stream. If auth fails the connection is closed and the
720/// MoQ handshake never runs.
721///
722/// ## Ordering of auth vs. admission vs. the verdict byte
723///
724/// [`authenticate`] verifies the token but deliberately does NOT write
725/// [`AUTH_OK`] on success — it hands back the still-open send half instead. That
726/// lets this function run the [`SessionRegistry::admit`] cap check *before*
727/// committing to a verdict, so an over-cap connection still gets a clean single-
728/// byte [`AUTH_REJECT`] (the same wire shape as a bad token) rather than
729/// silently being admitted and then killed, or racing a verdict it already sent.
730///
731/// `pre_auth` is the [`PreAuthGate`] permit taken before the QUIC handshake; it
732/// is released the moment the session is admitted, so the gate bounds exactly
733/// the unauthenticated population and nothing else.
734async fn handle_connection(
735    conn: iroh::endpoint::Connection,
736    env: ConnectionEnv,
737    pre_auth: PreAuthPermit,
738) -> Result<(), RelayError> {
739    let ConnectionEnv {
740        origin,
741        relay_hmac_secret,
742        registry,
743        scopes,
744        auth_deadline,
745        ingress,
746    } = env;
747    let peer = conn.remote_id();
748    tracing::info!(%peer, "relay connection accepted");
749
750    // ── Relay-token auth (control bi-stream, bounded) ──────────────────────
751    let (claims, mut auth_send) = match tokio::time::timeout(
752        auth_deadline,
753        authenticate(&conn, &relay_hmac_secret),
754    )
755    .await
756    {
757        Ok(Ok(pair)) => pair,
758        Ok(Err(e)) => {
759            tracing::warn!(%peer, "relay auth rejected: {e}");
760            metrics::counter!("sfu_sessions_rejected_total", "reason" => "auth").increment(1);
761            // Don't slam `conn.close` here: a `CONNECTION_CLOSE` frame can
762            // overtake the buffered reject byte, so the client would observe
763            // a generic connection error instead of the explicit reject
764            // verdict. Wait (bounded) for the client to read the verdict and
765            // close the connection itself, giving the reject byte a chance
766            // to land.
767            let _ = tokio::time::timeout(AUTH_REJECT_DRAIN, conn.closed()).await;
768            return Err(e);
769        }
770        Err(_) => {
771            // The client completed the QUIC handshake but never opened, or
772            // never finished, the token control stream — nothing was ever
773            // sent to drain, so close outright rather than leave the task
774            // and connection open behind QUIC's automatic keepalives.
775            tracing::warn!(%peer, deadline = ?auth_deadline, "relay auth handshake timed out — closing");
776            metrics::counter!("sfu_sessions_rejected_total", "reason" => "auth_timeout")
777                .increment(1);
778            conn.close(0u32.into(), b"auth timeout");
779            return Err(RelayError::Auth("auth handshake timed out".into()));
780        }
781    };
782
783    // ── Session admission (after auth, before moq-net) ──────────────────────
784    let _session_guard = match registry.admit(claims.user_id) {
785        Ok(guard) => guard,
786        Err(reason) => {
787            tracing::warn!(
788                %peer, %claims.user_id, %claims.space_id, ?reason,
789                "relay session rejected — over capacity"
790            );
791            let _ = reject(&mut auth_send).await;
792            let _ = tokio::time::timeout(AUTH_REJECT_DRAIN, conn.closed()).await;
793            return Err(RelayError::Auth(format!(
794                "session rejected: over capacity ({reason:?})"
795            )));
796        }
797    };
798    // Authenticated and accounted for by the session guard from here — the
799    // pre-auth slot must go back immediately or the gate would double as a
800    // (much larger) session cap.
801    drop(pre_auth);
802    // Session clock starts the moment admission succeeds — the span
803    // `sfu_session_duration_seconds` observes on close covers the whole live
804    // session, whether it ends by client hang-up, drain, or a watchdog policy
805    // close (all of which resolve `conn.closed()` below).
806    let session_start = Instant::now();
807    auth_send
808        .write_all(&[AUTH_OK])
809        .await
810        .map_err(|e| RelayError::Iroh(format!("write auth ok: {e}")))?;
811    let _ = auth_send.finish();
812
813    // ── Namespace scoping (the call-membership + per-user boundary) ────────
814    // The two halves are scoped INDEPENDENTLY from the shared root origin (not
815    // chained) because they need different prefixes:
816    //   * SERVE (subscribe, `with_publish`) — `space/{id}`: a participant must
817    //     be able to subscribe to anyone else in the call.
818    //   * INGEST (announce, `with_consume`) — `space/{id}/peer/{user_id}`: a
819    //     connection can only announce under its own authenticated identity.
820    let scope = space_scope(&claims);
821    let scope_path = Path::new(&scope);
822    let scoped_serve_producer = origin
823        .scope(std::slice::from_ref(&scope_path))
824        .ok_or_else(|| RelayError::Moq(format!("origin scope rejected namespace {scope:?}")))?;
825    // `.consume()` derives an OriginConsumer inheriting the producer's scope —
826    // this is the `with_publish` half, so subscribers here see any broadcast
827    // announced anywhere in the space, regardless of the ingest scope below.
828    let scoped_consume = scoped_serve_producer.consume();
829
830    let ingest_scope = peer_scope(&claims);
831    let ingest_path = Path::new(&ingest_scope);
832    let scoped_publish = origin
833        .scope(std::slice::from_ref(&ingest_path))
834        .ok_or_else(|| {
835            RelayError::Moq(format!("origin scope rejected namespace {ingest_scope:?}"))
836        })?;
837    // A second cursor over the same ingest scope, dedicated to the watchdog's
838    // broadcast-count budget (see `ingress_watchdog`). `consume()` takes `&self`
839    // so this doesn't disturb `scoped_publish`, which is still moved into
840    // `with_consume` below.
841    let ingest_announces = scoped_publish.consume();
842    // Both `scope` calls above materialise origin-tree nodes that moq-net
843    // never prunes — record them so the growth is measurable (see
844    // [`OriginScopes`]).
845    scopes.record(claims.space_id, claims.user_id);
846
847    tracing::info!(
848        %peer, %claims.user_id, %claims.space_id,
849        serve_namespace = %scope, ingest_namespace = %ingest_scope,
850        "relay connection authorised"
851    );
852
853    // ── MoQ server handshake + session ─────────────────────────────────────
854    // `web-transport-iroh` raw mode: speak MoQ directly over iroh, no HTTP/3.
855    //
856    // Bounded by the same deadline as the token handshake, and for the same
857    // reason: `accept` waits on the client opening the MoQ SETUP bi-stream and
858    // writing a full Client message, QUIC keepalives mean the idle timeout
859    // never fires, and by this point the connection already holds a session
860    // slot — so an unbounded wait here re-opens exactly the hole
861    // [`AUTH_DEADLINE`] closes, one step further in. The ingress watchdog is
862    // spawned only after this returns, so a stalled handshake is unwatched
863    // too.
864    let wt = web_transport_iroh::Session::raw(conn.clone());
865    // `accept` borrows the builder, so the builder needs its own binding to
866    // outlive the timeout future.
867    let server = moq_net::Server::new()
868        .with_consume(scoped_publish)
869        .with_publish(scoped_consume);
870    let session = match tokio::time::timeout(auth_deadline, server.accept(wt)).await {
871        Ok(Ok(session)) => session,
872        Ok(Err(e)) => return Err(RelayError::Moq(format!("server accept: {e}"))),
873        Err(_) => {
874            tracing::warn!(
875                %peer, %claims.user_id, deadline = ?auth_deadline,
876                "moq handshake timed out after auth — closing"
877            );
878            metrics::counter!("sfu_sessions_rejected_total", "reason" => "moq_timeout")
879                .increment(1);
880            conn.close(
881                CLOSE_MOQ_HANDSHAKE_TIMEOUT.into(),
882                b"moq handshake timed out",
883            );
884            return Err(RelayError::Moq("moq handshake timed out".into()));
885        }
886    };
887
888    // Ingress watchdog: bandwidth budget + broadcast-count quota + the
889    // periodic ops line, for the life of this session. Aborted the moment the
890    // connection closes so it never outlives what it's watching.
891    let watchdog_conn = conn.clone();
892    let watchdog = tokio::spawn(ingress_watchdog(
893        watchdog_conn,
894        ingest_announces,
895        ingest_scope,
896        claims.user_id,
897        claims.space_id,
898        registry.max_per_user(),
899        ingress,
900    ));
901
902    // The session drives forwarding on background tasks (moq-net spawns them in
903    // `lite::start`). Hold it alive until the connection closes, then drop it so
904    // its broadcasts unannounce and subscribers see end-of-track.
905    let _session = session;
906    conn.closed().await;
907    watchdog.abort();
908    metrics::histogram!("sfu_session_duration_seconds")
909        .record(session_start.elapsed().as_secs_f64());
910    tracing::info!(%peer, %claims.user_id, "relay connection closed");
911    Ok(())
912}

914/// Per-connection ops surface + policy enforcement, run for the life of one
915/// authenticated relay session (spawned in [`handle_connection`], aborted the
916/// instant the connection closes). Three concerns share one loop so there is
917/// exactly one task watching a connection's health:
918///
919/// * **Ingress budget** — samples `conn.stats().udp_rx.bytes` (cumulative
920///   QUIC bytes received) every [`IngressLimits::sample_interval`] and feeds
921///   an [`IngressBudget`] to catch a sustained flood
922///   ([`IngressLimits::max_bytes_per_sec`]).
923/// * **Broadcast quota** — counts currently-announced broadcast paths from
924///   `ingest_announces`' event stream, bounding runaway
925///   `space/{s}/peer/{user_id}` fan-out
926///   ([`IngressLimits::max_broadcasts_per_session`]).
927///
928///   Why an announce-event count and not moq-net's `Stats` aggregator (the
929///   module built for exactly this kind of counting): `Stats`'s per-broadcast
930///   counters are private and only reach the outside world by publishing a
931///   JSON snapshot onto a broadcast that a consumer must then subscribe to
932///   and parse — there is no synchronous in-process accessor. Standing up a
933///   scratch origin plus a self-subscribing background task just to read back
934///   two integers is exactly the kind of indirection not worth adding for a
935///   number this cheap to derive directly. `ingest_announces` is a consumer
936///   over the SAME shared origin subtree `scoped_publish` (this connection's
937///   ingest half) publishes into, via the ordinary [`OriginConsumer`] announce
938///   API every other subscriber in this codebase already uses — so counting
939///   its live announce/unannounce events is both cheaper and simpler.
940///
941///   The wrinkle: that subtree is keyed by the authenticated `(space, user)`
942///   pair, not by QUIC connection identity, so if the SAME user holds more
943///   than one concurrent session in the SAME space (allowed up to
944///   [`SessionLimits::max_per_user`]), every one of those connections'
945///   watchdogs sees the group's COMBINED announce stream. Counting that sum
946///   against a nominally per-session cap made `max_per_user` sessions of an
947///   ordinary user (~6 announced paths each) able to cross a 16-path cap and
948///   close EVERY one of that user's connections — so
949///   [`crate::ingress::BroadcastQuota`] instead groups the paths by their
950///   `{peer_id}` segment (the per-session tail of
951///   [`NAMESPACE_CONVENTION`]) and applies the cap per group, with a derived
952///   `cap × max_per_user` identity-wide ceiling behind it so announcing under
953///   endlessly-invented peer ids cannot evade it.
954/// * **Ops log** — every [`OPS_LOG_INTERVAL`], one `info!` line summarising
955///   both, so "which connection is the problem" is answerable by grepping one
956///   connection's lines rather than reasoning about aggregate metrics.
957///
958/// Either policy trip closes the connection with a distinct close code
959/// ([`CLOSE_INGRESS_BUDGET_EXCEEDED`] / [`CLOSE_BROADCAST_QUOTA_EXCEEDED`])
960/// rather than the generic `0` other close paths use, so a client inspecting
961/// the code/reason on `conn.closed()` can tell a policy close from a network
962/// failure.
963/// Tracks this connection's contribution to the process-wide
964/// `sfu_broadcasts_active` gauge, decrementing whatever it still holds on drop.
965/// The watchdog is `abort()`ed the instant the connection closes — before
966/// moq-net's unannounce events for this session's broadcasts drain through
967/// `ingest_announces` — so relying on those events to zero the gauge would leak
968/// it by the live count on every disconnect. A drop guard closes that: aborting
969/// the task drops its stack, and this `Drop` releases the remainder.
970#[derive(Default)]
971struct BroadcastGauge {
972    live: usize,
973}
974
975impl BroadcastGauge {
976    fn inc(&mut self) {
977        self.live += 1;
978        metrics::gauge!("sfu_broadcasts_active").increment(1.0);
979    }
980
981    fn dec(&mut self) {
982        self.live -= 1;
983        metrics::gauge!("sfu_broadcasts_active").decrement(1.0);
984    }
985}
986
987impl Drop for BroadcastGauge {
988    fn drop(&mut self) {
989        if self.live > 0 {
990            metrics::gauge!("sfu_broadcasts_active").decrement(self.live as f64);
991        }
992    }
993}
994
995async fn ingress_watchdog(
996    conn: iroh::endpoint::Connection,
997    mut ingest_announces: OriginConsumer,
998    ingest_scope: String,
999    user_id: Uuid,
1000    space_id: Uuid,
1001    max_per_user: usize,
1002    limits: IngressLimits,
1003) {
1004    let mut budget = IngressBudget::new(limits.max_bytes_per_sec, limits.window);
1005    let mut quota = BroadcastQuota::new(
1006        ingest_scope,
1007        limits.max_broadcasts_per_session,
1008        max_per_user,
1009    );
1010    // Mirrors `quota.live()` into the global `sfu_broadcasts_active`
1011    // gauge, drop-safe against the watchdog's `abort()` (see the type's doc).
1012    let mut broadcast_gauge = BroadcastGauge::default();
1013    // Once the announce cursor closes (the session ended) stop polling it —
1014    // a closed `OriginConsumer` future resolves `None` immediately, and
1015    // without this guard that would spin the select loop.
1016    let mut announces_open = true;
1017    // Baseline for turning `conn.stats()`'s cumulative counter into the
1018    // per-sample delta `sfu_ingress_bytes_total` accumulates — the global
1019    // counter tracks bytes actually received, not a connection-count proxy.
1020    let mut last_ingress_bytes: u64 = 0;
1021
1022    let mut sample_ticker = tokio::time::interval(limits.sample_interval);
1023    sample_ticker.set_missed_tick_behavior(tokio::time::MissedTickBehavior::Delay);
1024    let mut log_ticker = tokio::time::interval(OPS_LOG_INTERVAL);
1025    log_ticker.set_missed_tick_behavior(tokio::time::MissedTickBehavior::Delay);
1026
1027    loop {
1028        tokio::select! {
1029            _ = sample_ticker.tick() => {
1030                let bytes = conn.stats().udp_rx.bytes;
1031                metrics::counter!("sfu_ingress_bytes_total")
1032                    .increment(bytes.saturating_sub(last_ingress_bytes));
1033                last_ingress_bytes = bytes;
1034                if let Some(rate) = budget.sample(bytes, Instant::now()) {
1035                    tracing::warn!(
1036                        %user_id, %space_id, bytes_per_sec = rate, cap = limits.max_bytes_per_sec,
1037                        "relay connection exceeded its ingress budget — closing"
1038                    );
1039                    metrics::counter!("sfu_connections_closed_total", "reason" => "ingress_budget")
1040                        .increment(1);
1041                    conn.close(
1042                        CLOSE_INGRESS_BUDGET_EXCEEDED.into(),
1043                        b"ingress budget exceeded",
1044                    );
1045                    return;
1046                }
1047            }
1048            update = ingest_announces.announced(), if announces_open => {
1049                match update {
1050                    Some((path, Some(_))) => {
1051                        if quota.announce(path.as_str()) {
1052                            broadcast_gauge.inc();
1053                        }
1054                    }
1055                    Some((path, None)) => {
1056                        if quota.unannounce(path.as_str()) {
1057                            broadcast_gauge.dec();
1058                        }
1059                    }
1060                    None => announces_open = false,
1061                }
1062                if let Some(trip) = quota.trip() {
1063                    tracing::warn!(
1064                        %user_id, %space_id, ?trip, broadcasts = quota.live(),
1065                        cap = limits.max_broadcasts_per_session,
1066                        "relay connection exceeded its broadcast quota — closing"
1067                    );
1068                    metrics::counter!("sfu_connections_closed_total", "reason" => "broadcast_quota")
1069                        .increment(1);
1070                    conn.close(
1071                        CLOSE_BROADCAST_QUOTA_EXCEEDED.into(),
1072                        b"broadcast quota exceeded",
1073                    );
1074                    return;
1075                }
1076            }
1077            _ = log_ticker.tick() => {
1078                tracing::info!(
1079                    %user_id, %space_id,
1080                    bytes_per_sec = ?budget.observed_rate(),
1081                    broadcasts = quota.live(),
1082                    "relay connection ingress"
1083                );
1084            }
1085        }
1086    }
1087}

1089/// Read and verify the relay token off the dedicated control bi-stream.
1090///
1091/// Wire format (client → relay): `u16 LE length` + `token bytes`. The token
1092/// scheme is the backend's HMAC `{user_id}:{space_id}:{expiry}:{mac}`, verified
1093/// by the shared [`crate::auth::verify_relay_token`].
1094///
1095/// On a format/verification failure the one-byte [`AUTH_REJECT`] reply is
1096/// written and the stream finished here. On success this returns the claims AND
1097/// the still-open send half WITHOUT writing a verdict — the caller
1098/// ([`handle_connection`]) still has to run the post-auth session-cap check
1099/// before it knows whether the final byte is [`AUTH_OK`] or [`AUTH_REJECT`];
1100/// writing here would foreclose that choice.
1101async fn authenticate(
1102    conn: &iroh::endpoint::Connection,
1103    secret: &str,
1104) -> Result<(RelayTokenClaims, iroh::endpoint::SendStream), RelayError> {
1105    let (mut send, mut recv) = conn
1106        .accept_bi()
1107        .await
1108        .map_err(|e| RelayError::Iroh(format!("accept token stream: {e}")))?;
1109
1110    let mut len_buf = [0u8; 2];
1111    recv.read_exact(&mut len_buf)
1112        .await
1113        .map_err(|e| RelayError::Iroh(format!("read token len: {e}")))?;
1114    let len = u16::from_le_bytes(len_buf) as usize;
1115    if len == 0 || len > MAX_TOKEN_LEN {
1116        let _ = reject(&mut send).await;
1117        return Err(RelayError::Auth(format!(
1118            "token length {len} out of bounds (1..={MAX_TOKEN_LEN})"
1119        )));
1120    }
1121
1122    let mut token_buf = vec![0u8; len];
1123    recv.read_exact(&mut token_buf)
1124        .await
1125        .map_err(|e| RelayError::Iroh(format!("read token: {e}")))?;
1126    let token = String::from_utf8(token_buf)
1127        .map_err(|_| RelayError::Auth("token is not valid UTF-8".into()))?;
1128
1129    let now = chrono::Utc::now().timestamp();
1130    match verify_relay_token(&token, secret, now) {
1131        Ok(claims) => Ok((claims, send)),
1132        Err(e) => {
1133            let _ = reject(&mut send).await;
1134            Err(RelayError::Auth(e.to_string()))
1135        }
1136    }
1137}
1138
1139/// Send the one-byte rejection and finish the control stream. Best-effort: the
1140/// caller has already decided to reject, so a write error here is not fatal.
1141async fn reject(send: &mut iroh::endpoint::SendStream) -> Result<(), RelayError> {
1142    send.write_all(&[AUTH_REJECT])
1143        .await
1144        .map_err(|e| RelayError::Iroh(format!("write auth reject: {e}")))?;
1145    let _ = send.finish();
1146    Ok(())
1147}
