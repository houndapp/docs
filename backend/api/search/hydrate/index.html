Turning a page of (id, score) pairs into renderable results.

Same rule as the history endpoint it mirrors: a fixed number of queries per page, never one per row. A page is at most super::LIMIT_RANGE’s ceiling of rows, and the hydration is four reads (messages, attachments, embeds, profiles) plus one per community the page touches.

The hit order is the database’s, and it is preserved: the ranking is the whole point of the response, and a HashMap iteration would throw it away.
