Module embed

Expand description

Link embeds: unfurling URLs found in messages into renderable previews, the media proxy that serves their images, and the debugger that explains both.

§The shape of the feature

  POST /space/{id}/message
       │  stores + answers immediately
       └─▶ spawn_unfurl ──▶ guard ──▶ fetch ──▶ parse ──▶ build ──▶ cache
                                                             │
                                       realtime: MessageEmbedsUpdated

  GET /embed/media/{embed}/{slot}   the only URL a client loads
  POST /embed/debug                 the same pipeline, traced, cache bypassed

§Module map

  • guard — the SSRF/size/redirect boundary. Read this one first; it is what makes the rest of the feature safe to have.
  • parse — HTML → raw ordered metadata.
  • oembed — the oEmbed 1.0 document.
  • providers — oEmbed endpoints for hosts we already know, so a page that does not advertise one (or does not load at all) still unfurls properly.
  • build — precedence and sanitisation → a [LinkEmbed].
  • store — the per-URL cache and the message→embed join.
  • media — the proxy route and its byte cache.
  • unfurl — the pipeline that drives all of the above.

§Trust boundary, stated once

Everything upstream of build is attacker-controlled: the URL comes from a message, the page comes from whoever that URL resolves to, and the oEmbed endpoint is named by that page. Nothing downstream of build is: a [LinkEmbed] is entity-decoded, control-character-stripped, length-capped plain text plus http(s) URLs that point at this deployment. Clients are told they may render it as text, and this module is where that becomes true.
