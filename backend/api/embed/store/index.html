Persistence for link embeds: the per-URL unfurl cache and the message→embed join.

§The cache is keyed by URL, not by message

A link posted in fifty spaces is one row and one outbound fetch. That is the whole point of the split: without it, unfurl traffic would scale with how often people quote each other, and a popular link would be a small denial of service aimed at whoever published it.

§Failures are cached too

On a shorter clock (TTL_ERROR) than a success, but cached all the same. A link to a host that times out must not cost eight seconds every time somebody mentions it, and a 404 is a stable fact for at least half an hour.

§Refresh keeps the row id

A stale row is updated in place rather than replaced, because the id is in every proxy URL the embed hands out. Minting a new one would break the media links of every message already pointing at it.
