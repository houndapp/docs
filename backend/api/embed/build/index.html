Precedence and sanitisation: raw metadata in, a renderable [LinkEmbed] out.

§The precedence rules, and why

Three vocabularies describe the same page and disagree constantly. The order below is applied per field, not per vocabulary, because no single source is best at everything:

fieldorder
titleoEmbed → og:title → twitter:title → <title>
descriptionog:description → twitter:description → oEmbed → <meta description>
site nameog:site_name → oEmbed provider_name → the registrable domain
authoroEmbed author_name → article:author → <meta author>
imagesog:image (all of them) → twitter:image → oEmbed thumbnail
videoog:video → twitter:player:stream

oEmbed wins the title because it is the service describing its own resource, where og:title is whatever the page author typed — but it loses the description, because endpoints routinely return a boilerplate one (“Watch on …”) while og:description carries the actual summary.

§Sanitisation is not optional here

Every string leaving this module has been through clean_line or clean_block: control characters removed (they let a title forge line structure in a renderer that lays out its own text), whitespace collapsed, and lengths capped. Clients are told they may render these as plain text, and this is the function that makes that true.
