Module guard 

Source
Expand description

The outbound-fetch guard: everything that stops “unfurl this link” from becoming “make my server issue requests of the attacker’s choosing”.

Anyone who can post a message can make this service open a connection, so the guard is the feature’s real security boundary. It enforces, in order:

  1. Scheme + shape. http/https only, no embedded credentials, no fragment-only or opaque URLs.
  2. Port. A blocklist of ports that speak something other than HTTP (BLOCKED_PORTS). An HTTP request to an SMTP or Redis port is a protocol-smuggling primitive, not a page fetch.
  3. Address. Every IP the hostname resolves to must be publicly routable (is_public_ip) — loopback, RFC 1918, link-local (which is where cloud instance-metadata lives), CGNAT, unique-local, and the v6 tunnels that smuggle a v4 address inside a v6 one are all refused.
  4. Pinning. The client for a hop is built with resolve_to_addrs fixed to the addresses just validated, so the connection cannot go anywhere else. This is what closes DNS rebinding: a name that answers publicly on the check and 127.0.0.1 on the connect has no second lookup to win.
  5. Redirects, manually. reqwest’s own follower would re-resolve inside the connector, unpinned — so redirects are off and each hop re-enters this module from the top. That is the only reason the loop below is hand-rolled.
  6. Size and time. A byte cap enforced while streaming (a Content-Length is the server’s claim, not a limit) and a whole-fetch deadline that spans every hop, so N redirects cannot each cost the full timeout.

§The cost that was accepted

A reqwest::Client per hop, rather than one shared client with a custom dns::Resolve. The shared-client form needs the validated addresses to reach the connector through side-channel state keyed by hostname, which is ambiguous the moment two unfurls of the same host overlap. Per-hop pinning has no such state: the addresses are arguments. no_proxy() keeps the build cheap (it is system-proxy discovery, not TLS setup, that makes Client::new() slow), and hops are usually cross-host anyway, so a shared pool would rarely be reused.
