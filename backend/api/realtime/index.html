The realtime plane: messages, space layout, voice roster, screenshare.

The wire protocol and the routing rules are transport-agnostic and live in [hound_realtime]; this module is the connection, authentication, and database glue around them.

§Two legs, one session

A client reaches this plane over WebTransport (hound_wt, preferred: one QUIC connection, per-stream head-of-line blocking, no TCP handshake to re-do after a network change) or a plain WebSocket (universally reachable, the fallback when WebTransport is unavailable or the endpoint is not configured). Both legs authenticate identically, then hand a hound_wt::MessagePipe to the same hub::run_session — the transport difference ends there.

§Endpoints

  • GET /realtime/ws — WebSocket upgrade.
  • CONNECT https://<rt-host>/realtime — WebTransport session, on the endpoint advertised by /realtime/config.
  • GET /realtime/config — where the WebTransport endpoint is, and (dev only) the certificate hash to pin. Absent URL means “WebSocket only”.

§Authorization (trust boundary)

Both legs take the credential from an Authorization: Bearer <jwt> header, falling back to a ?token=<jwt> query parameter — the header is preferred because a token in the URL lands in access logs and proxy traces, and the query form exists because a browser can set neither headers on a WebTransport construction nor on a WebSocket one. It must be an unrevoked access token, and it is validated before the session exists: a WebSocket that fails gets a 401 instead of an upgrade, a WebTransport session a 403 CONNECT response. Per-space subscriptions and screenshare toggles are authorized separately against the owning community’s membership, on every request; a live session that loses a membership has that community’s rooms revoked (see Api::revoke_realtime_membership).

§Lifecycle (SPOF flag)

Connection state is in-memory and per-process: it does not survive a redeploy and does not coordinate across replicas, so like /control this plane is only correct on a single backend replica. Clients recover by reconnecting — the Welcome snapshot is a full resync by design.
