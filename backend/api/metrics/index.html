Prometheus metrics: the process-wide recorder + render handle, and the HTTP request-instrumentation middleware. /internal/metrics’s handler lives in super::internal (co-located with the other internal-auth-gated routes); this module owns everything that feeds it.

Constants§

HTTP_DURATION_BUCKETS 🔒
Explicit bucket boundaries (seconds) for http_request_duration_seconds. Without an override the exporter renders histogram! as a SUMMARY (rolling quantiles), which can’t feed histogram_quantile or bucket-ratio SLIs — the buckets below make it a real Prometheus histogram (_bucket series). Spaced for web-request latency: dense sub-100ms, out to a 10s tail.

Functions§

handle 🔒
Installs the global recorder and returns its render handle. OnceLock makes repeated calls within one process return the same handle instead of erroring on a second install_recorder() — irrelevant in production (Api::serve calls this once) but keeps the test harness, which constructs a fresh super::Api per test function, safe regardless of how the test runner schedules those calls.
init_series 🔒
Zero-initialise every low-cardinality series the process owns, so a fresh pod’s first scrape already exposes them instead of each appearing lazily on its first event — dashboards and alerts can’t rate()/threshold a series that doesn’t exist yet. Runs once, inside handle’s recorder install (so the global recorder is already live). Every known label combination of a labelled counter is touched; gauges get their real startup value. Only bounded label sets appear here — never a per-request/route/user series.
track_http_requests 🔒
Records http_requests_total{method,route,status} and http_request_duration_seconds{method,route,status} for every request.
