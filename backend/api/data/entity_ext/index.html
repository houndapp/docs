Hand-written extensions to the generated entities in super::entity.

mise run db:generate deletes and rewrites entity/ from the live schema, so nothing in there is ever edited by hand: derives and attributes are generator flags (see the task), and every method, invariant or note that belongs to an entity type lives here instead. The enums’ variant names are derived from their database values, which is why those values are snake_case (view_channels becomes Permission::ViewChannels); the wire form is the database form.

Semantics of the permission enums, since the generated file cannot carry per-variant documentation:

Permission (community roles; stored in role_permission and the two overwrite tables):

  • ManageCommunity: community-level settings.
  • ManageChannels: create, delete and rename channels.
  • ManageUsers: kick members.
  • ManageRoles: create, delete and edit roles; assign permissions.
  • ViewChannels: view and read a channel (channel-applicable).
  • SendMessages: send messages in a channel (channel-applicable).
  • ReadHistory: read message history in a channel (channel-applicable).
  • ManageMessages: edit or delete other members’ messages (channel-applicable).

InstancePermission (scoped to the server instance, stored in instance_user_permission): ManageCommunities creates and deletes communities; ManageInstance manages instance-level settings.

IdentityProvider (one identity row per login method; that table is the only one holding PII): Email signs in with a passkey ceremony keyed by the address; Steam with a Steamworks session ticket or Steam OpenID.
