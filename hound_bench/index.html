§Deterministic inputs for the client media benchmarks

Every bench target draws its frames from here so a measurement depends only on the code under test: the generators are pure functions of a frame index — no clock, no RNG crate, no device — so two runs on the same machine differ only by the change being measured.

§Why not the engine’s synthetic capturer

[hound_engine]’s synthetic camera renders the same pattern, but it is a capture source: it sleeps to pace itself to the requested fps, and its renderer is pub(crate). A bench that called it would measure the sleep. i420_frame mirrors its pattern (scrolling gradient + bouncing block + cycling chroma) so the encoder does the same inter-frame work.

Constants§

FRAME_INTERVAL_US
Nominal capture cadence the generators stamp at: 30 fps, matching the client’s camera and screen publish rate (CAM_FPS/SCREEN_FPS).

20 ms in microseconds — the Opus frame duration the audio path is fixed at.
