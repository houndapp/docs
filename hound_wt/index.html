A reusable WebTransport shell — endpoints, the pre-accept authorization surface, and a message pipe. It knows nothing about any application protocol.

§Layers

  • WtServer / WtClient wrap wtransport’s endpoints with the knobs this workspace always wants set: an explicit idle timeout (wtransport’s default is infinite, which parks a dead connection’s futures forever), a keep-alive interval, and identity/trust chosen by a small enum rather than a typestate builder.
  • Incoming is a peer at the UDP boundary, before any handshake. It is returned immediately so admission is per-peer: the caller spawns a task that handshakes, authenticates, and accepts or rejects under its own deadline, and one stalled peer never delays the accept queue behind it.
  • SessionRequest is the trust boundary: a peer that has completed the QUIC+HTTP/3 handshake but has NOT been admitted. Callers read its path, query, and headers, decide, and then SessionRequest::accept or SessionRequest::reject — no application state exists until they do.
  • FramedBi is one bidirectional stream carrying length-delimited (u32 big-endian, MAX_FRAME_BYTES cap) UTF-8 JSON frames.
  • MessagePipe is the transport-agnostic seam: send/recv/close over whole text frames. FramedBi implements it, a WebSocket adapter can implement it, and protocol shells program against the trait so one session loop serves both legs. Liveness is the companion seam for the probe-and-reap a keep-alive-less transport needs.

§Domain note

WebTransport multiplexes independent streams over one QUIC connection, so head-of-line blocking is per-stream: a stalled control stream cannot delay anything else on the connection. This crate deliberately does not expose datagrams — a control plane wants the ordered, reliable stream.

Constants§

DEFAULT_ADMISSION_TIMEOUT
How long a peer may take to get from “the endpoint saw its first packet” to admitted or turned away — the whole handshake + authenticate + accept/reject sequence.
DEFAULT_KEEP_ALIVE
Keep-alive interval. Well under DEFAULT_MAX_IDLE so an idle-but-live session is never mistaken for a dead one, and short enough that a NAT binding for the UDP flow stays open.
DEFAULT_MAX_IDLE
Idle timeout after which a silent connection is dropped.
MAX_FRAME_BYTES
Largest frame accepted in either direction (1 MiB). A control frame is kilobytes at most; the cap bounds what a peer can make the receiver buffer before the length prefix is even satisfied.
