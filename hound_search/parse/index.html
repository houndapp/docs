Turning a line of query text into a Query, its highlight tokens and its diagnostics, in one pass.

§The grammar

Chunks are whitespace-delimited; " groups whitespace into one chunk and runs to the end of the input when unterminated. A chunk is

  • a filter when it opens key: with one of crate::FILTER_KEYS, matched case-insensitively — anything else before a colon is not a filter, so foo:bar is searched for literally;
  • a phrase when it opens with ", whose words must appear adjacent;
  • a word otherwise.

A leading - negates a term; a lone - is text. Only text terms negate: -has:image is DiagnosticKind::NegationNotSupported, because “message lacks a content kind” has no index to answer it from.

Filter values fall in two classes. from:/in:/mentions: take a hound:<kind>/<uuid> reference and nothing else — the UI resolves a name to a pill before submitting, and a name the user typed but never resolved is dropped rather than guessed at, so no display name ever reaches the wire. has:/is: and the date keywords are closed vocabularies, matched case-insensitively; text and reference values are taken verbatim.

§Repeats

Identity filters accumulate (the backend ORs them, so repeating widens); has: accumulates (the backend ANDs them, so repeating narrows). Both de-duplicate — a repeated value cannot change a result, only the SQL’s size. Dates are single-valued: the last wins, and the earlier is reported DiagnosticKind::Superseded at its own span so the field can strike it through.
