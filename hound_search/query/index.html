Query: the structured search, and the only part of a parse that crosses the wire.

Every field is already validated — ids are ids, kinds are kinds, dates are calendar-real — so the backend compiles it to SQL without re-checking user text. Anything the parser could not validate is a crate::Diagnostic and is simply absent here.

§How the fields combine

Identity filters (Query::from, Query::in_spaces, Query::mentions) are OR within a field: naming two people widens the search, which is what repeating them reads as. Everything else is AND: each Query::has kind, each positive Term, and the date bounds all narrow it. A negated term is a NOT.
