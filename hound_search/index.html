Hound’s message-search query language.

A search is one line of text. [parse] turns it into three things at once, from a single scan: the Query the backend runs, the Tokens the composer paints its highlighting from, and the Diagnostics shown under the field. The invariant this crate exists to hold: server and client run this exact crate, so the filter the field highlights is the filter the SQL applies — a from: the UI drew as resolved can never be a word term to the backend.

Parsing is total. There is no error type: a half-typed from:, an unterminated quote, or a filter value the UI never resolved becomes a diagnostic and a dropped filter, never a failure. The field is parsed on every keystroke; refusing to parse would mean refusing to highlight.

  • [parse] — the parser and Parsed, its whole output.
  • query — Query/Term: the structured search, and the only part that crosses the wire.
  • date — DateSpec/DateContext: before:/after:/during: values resolved against the reader’s own UTC offset.
  • token — Token/TokenKind: UTF-16 spans for composer styling.
  • diagnostic — Diagnostic/DiagnosticKind: what was dropped and why, positioned in the input.
