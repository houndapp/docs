Expand description

One attempt: fetch the config, then WebTransport (if advertised, allowed, and working), else the WebSocket.

The config fetch is what re-mints the credential: it goes through RestClient, whose 401 hook rotates the session and republishes the access token, so the token read straight after is current by construction. Reading a captured token instead is the stale-JWT strand this ordering exists to prevent.

A config fetch that FAILS does not fail the attempt: the WebSocket leg is derived from the REST base URL and needs nothing the config carries, so a backend blip in that one endpoint must not cost the whole plane. Only an Auth error propagates — that one is an answer (it has already survived the REST layer’s refresh-and-retry).
