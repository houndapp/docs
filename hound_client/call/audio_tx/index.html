Module audio_tx 

Source
Expand description

Outbound audio: the mic capture loop + Opus publish, and the screen APP-AUDIO leg (its !Send capture thread + publish task). Encode + publish run on the RT audio runtime (“audio is sacred”: a screenshare encode can’t stall the mic), and audio frames publish via the ordered-substream path (count-rolled groups) so successive Opus frames ride one in-order QUIC stream — never one stream per frame.

Structs§

OsInputVolume 🔒
The capture-loop-facing handle onto the OS input-volume round trip: an atomic mailbox to a dedicated background thread (volume_actor_loop) that owns the resolved platform handle and does every HAL/COM call. The capture loop only ever touches atomics here — never blocks, never does device I/O itself.
VolumeWriteGate 🔒
The write-side decision for the OS input-volume round trip: given the controller’s live recommendation and the gate state, decide whether to push a write now. Pure (no I/O, no Apm, no platform handle) so the AGC-off/ mute/rate-limit/unavailable-provider rules are unit-testable without real hardware. Owned by mic_capture_loop; consulted once per captured frame.

Constants§

OS_VOLUME_PERIODIC_READ_INTERVAL 🔒
Floor between the actor’s own periodic re-reads when there is no write to service. Independent of OS_VOLUME_WRITE_INTERVAL — this is the READ side (catching external changes), not the write throttle.
OS_VOLUME_POLL_INTERVAL 🔒
How often the volume actor polls its device-change mailbox (and, with no pending write, re-reads the OS level to catch an out-of-band change — the user manually moving the OS mixer slider mid-call).
OS_VOLUME_WRITE_INTERVAL 🔒
Rate limit for OS input-volume WRITES: at most one per this interval even if the controller’s recommendation changes every frame. A real HAL/COM round trip per 20 ms frame would be needless syscall churn for a value that only needs to track speech level on a many-seconds timescale.

Functions§

dbfs 🔒
Full-scale RMS (0..1) to dBFS, for the mic-stage gauges. -inf on digital silence is fine — the stats layer clamps it to its -100 dBFS floor.
mic_capture_loop 🔒
The mic capture loop: pull PCM, process (AEC/NS/AGC), gate on mute, meter the level, forward to the encoder. Hot-swaps the device when device_rx changes; re-opens on error.
open_mic 🔒
Open the mic per capture_source: real hardware, or (behind synthetic) the engine’s mic-free test tone. The one seam every (re)open site in mic_capture_loop routes through, so a headless build never needs its own copy of the branch.
publish_audio_one 🔒
Publish one AUDIO frame via the ordered-substream path (count-rolled groups), so successive Opus frames ride one in-order QUIC stream instead of one stream per frame (the source of the cross-stream reordering). Use for mic + screen-audio.
screen_audio_capture_loop 🔒
The !Send screen APP-AUDIO capture thread: block on the engine ScreenAudio (the mic-thread analogue — no APM, no levels, no hot-swap) and forward each 20 ms PCM frame to the publish task. A next_frame error/panic is the leg’s clean end (its parent screen stream stopped); drop the leg on this owning thread and exit.
silence_mic_meter 🔒
Force the mic meter to silence.
spawn_mic_publish 🔒
Spawn the mic publish task. A blocking capture thread pulls PCM from the engine Microphone (hot-swappable via device_rx); the async half Opus-encodes and publishes each frame on the relay session’s mic track.
spawn_screen_audio_publish 🔒
The async screen AUDIO publish task: the mic publish path MINUS APM / levels / hot-swap (app audio is not a mic). Opus-encodes each forwarded PCM frame and publishes it on the screen_audio track; the receiver plays it on the shared mix bus exactly like a mic.
volume_actor_loop 🔒
The volume actor’s body: owns the resolved InputVolumeHandle and does every HAL/COM call, off the mic capture thread. Exits when device_rx’s sender drops (OsInputVolume — and so this actor — lives exactly as long as one mic_capture_loop call).
