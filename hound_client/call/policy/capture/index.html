Module capture 

Source
Expand description

Capture-source policy: aspect-preserving low-rung screen geometry, the source-liveness probe throttle and first-frame watchdog, the dry-restart give-up bound, resize debounce, capture-device open retry + log dedupe, and the mid-stream encoder-rebuild throttle.

Structs§

OpenRetry 🔒
Retry cadence + log dedupe for a capture-device (re)open loop. Pure: it decides whether this failure is worth a log line and how long to wait before the next attempt; the caller owns the message.
RebuildRetry 🔒
Rate-limits mid-stream encoder rebuilds after a failed open (ENCODER_REBUILD_RETRY). Pure; unit-tested.
ResizeWatch 🔒
The resize watch’s running state inside the capture loop, factored out PURE so the debounce classification is unit-testable without a live capture source. Tracks the baseline content size and a pending (changed-but-not-yet-held) candidate.

Constants§

ENCODER_REBUILD_RETRY 🔒
Minimum spacing between mid-stream encoder-rebuild attempts once one has failed to open. Opening an encoder spins a whole platform session (VideoToolbox / MFT / openh264), so a rebuild the device cannot satisfy must not be re-attempted per captured frame.
OPEN_RETRY_DENIED 🔒
A denied device retries at this (slow) cadence: the grant can arrive at any time — the user flips the toggle in System Settings and capture must resume without a rejoin — but spinning at capture speed on a permanent denial is pure waste.
OPEN_RETRY_MAX 🔒
Ceiling for the transient-failure backoff.
OPEN_RETRY_MIN 🔒
First retry delay for a transient open failure, doubling to OPEN_RETRY_MAX.
SCREEN_DRY_RESTART_LIMIT 🔒
Consecutive capture incarnations that delivered NOTHING before the supervisor stops restarting the share and surfaces a terminal error instead.
SOURCE_LIVENESS_IDLE 🔒
How long the screen capture must be IDLE (no real frames delivered) before the loop starts probing whether the source still exists. Static content is legitimately idle, so probing starts only after a quiet spell.
SOURCE_LIVENESS_INTERVAL 🔒
Minimum spacing between source-liveness probes (each is a blocking ~tens-of-ms shareable-content fetch on the otherwise-idle capture thread).

Functions§

first_frame_overdue 🔒
Whether a screen capture that has never delivered a frame has waited too long (SCREEN_FIRST_FRAME_DEADLINE) and should be restarted. Pure — the whole no-first-frame policy in one testable place.
low_screen_dims 🔒
The LOW simulcast layer’s encode geometry for a screen share at rung, derived from the SOURCE so it preserves aspect ratio — a fixed 16:9 rung (e.g. 640×360) would stretch any non-16:9 share (a near-square window gets squished horizontally).
screen_restarts_exhausted 🔒
Whether a screen share should be ABANDONED rather than restarted again, given how many consecutive capture incarnations exited without ever delivering a real frame. Pure — the give-up policy in one testable place; the supervisor owns the counter (any incarnation that delivered frames resets it to zero).
source_probe_due 🔒
Whether an idle capture loop should probe source liveness now. Pure — the throttle policy in one testable place: probe only after a real-frame drought of SOURCE_LIVENESS_IDLE, at most every SOURCE_LIVENESS_INTERVAL.
