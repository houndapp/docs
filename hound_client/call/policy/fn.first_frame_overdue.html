Whether a screen capture that has never delivered a frame has waited too long (SCREEN_FIRST_FRAME_DEADLINE) and should be restarted. Pure — the whole no-first-frame policy in one testable place.

captured_any is the discriminator, and it is what makes this safe on a legitimately static share: a static source still delivered frame #1 (the capture thread caches it and re-emits it), so this can only ever fire on a source that has produced NOTHING since the loop started. The liveness probe cannot cover that case — the source handle exists and answers “alive” — so without this a share whose source never produces (Windows WGC does exactly this) idles forever: no re-emit, no exit, no supervisor notification.
