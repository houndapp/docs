Module mic_monitor 

Source
Expand description

The out-of-call microphone monitor — what the settings screen’s mic test runs.

One blocking capture thread walking the same open → APM → meter path the call’s mic publish walks (super::audio_tx::spawn_mic_publish), with everything downstream of the meter removed: no Opus, no MoQ, no OS input-volume controller (a preview must not leave the user’s OS mic slider somewhere else than it found it). The level is published onto the SAME LevelsView channel the in-call meter reads, so both meters are one widget over one stream.

The call owns the microphone. A monitor is refused while a call is live: two opens of one input device is either an outright EBUSY (ALSA’s exclusive hw devices) or two APMs adapting against each other on the same signal. The refusal lives at the command seam (crate::HoundClient::mic_monitor_start); this module assumes it has the device to itself.

Voice processing is applied through the very VoiceProcessing cell the call uses, so “noise suppression off” reaches the meter by the same code path it reaches a call — which is the whole point of a test that is supposed to sound like the call will.

Constants§

REOPEN_DELAY 🔒
How long the loop waits before re-opening after the device faults mid-test. Slower than the call’s ladder on purpose: a settings preview has no far end waiting on it, and the user is looking straight at the meter — a quiet second is cheaper than a device thrash.
