hound_client::call::session

Module supervisor 

Source
Expand description

The auto-reconnect supervisor: owns the live session + the backoff + the screen-share state (desired source, running pipeline, dry-exit streak); monitors every layer, tears down on failure, rebuilds with backoff, and republishes the share against each fresh session.

choice_from 🔒
handle_screen_command 🔒
Handle one ScreenCommand inside the supervisor loop, against the CURRENT live session. Start replaces any running share (stop-old-first + unpublish), starts a fresh pipeline, records the desired source for cross-reconnect republish, and replies on the oneshot. Stop and Ended both tear the pipeline down + unpublish the tracks + drop the desire (a clean user/OS stop). Resized/Retry RESTART the same share in place (the share must NOT end on a resize or a transient glitch).
note_screen_exit 🔒
Fold one restarting exit into the dry-restart streak and decide whether the share may be restarted at all. Returns true to restart, false when the share has been GIVEN UP on (in which case this has already torn it down, dropped the desire, logged the terminal error and published it to the screen-error surface).
restart_screen_share 🔒
Tear down the running screen pipeline and start it again against the SAME source (recorded in desired_source). Shared by the Resized and Retry exits: receivers see the screen track replaced and the desire is untouched on success.
spawn_supervisor 🔒
Spawn the auto-reconnect supervisor. It owns the live session + a Backoff + the screen-share state, monitors every layer, and on a failure tears the broken session fully down and rebuilds it with exponential backoff + jitter — re-minting via voice/join each attempt (which also refreshes the relay token). It gives up only on a FATAL (auth/permission) error or an explicit leave (cancel); transient errors retry FOREVER. State transitions are published on channels.connection.
start_screen_pipeline 🔒
Start ONE screen-share pipeline against the current session — the single place the long spawn_screen_publish argument list is spelled out, shared by the three sites that start a share (the Start command, a restart, and the post-reconnect republish) so they cannot drift apart.
