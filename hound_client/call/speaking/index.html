The dominant-speaker plumbing: the shared [SpeakerRanking] every part of one establish reads, and the task that reports THIS client’s own level.

The policy itself is in hound_media::speaking (pure, virtual-clock, tested there). This file is only the IO shell around it:

  • SharedSpeakers — the ranker behind a mutex plus the monotonic epoch that turns wall time into the now_us the core wants. Written by the control reader (one report per speaking peer per 300 ms), read by the subscribe reconcile (twice a second). Per-establish, like the roster: peer ids are assigned per Welcome, so a ranking that outlived a reconnect would promote whoever inherits a departed speaker’s id.
  • spawn_speaking_report — samples our own mic meter on the same 300 ms grid and puts a coarse subband on the control plane, suppressed while silent.

ReportGate 🔒
The emitter’s decision, as a pure policy so the wire cost is a unit test rather than a claim: send on change, re-assert a non-silent band before the receiver would time it out, and otherwise say nothing at all.
SharedSpeakers 🔒
The per-establish ranking, shared between the control reader and the subscribe loop. A plain Mutex: contention is a handful of 300 ms reports against one 2 Hz reader, and neither side holds it across an await.

Constants§

SPEAKING_REASSERT 🔒
How long a non-silent report may go unrepeated before the receiver’s ranker would read the peer as gone quiet. The emitter only sends on a change, so a peer talking steadily at one band would otherwise fall off the grid; re-asserting well inside [hound_media::speaking::IDLE_US] keeps a steady speaker steady without paying the full 3 Hz for an unchanging level.
