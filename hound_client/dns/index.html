Test-harness DNS pinning for the REST plane (see the module docs). Test-harness DNS pinning for the REST plane (feature dns-override).

Overrides hostname → IP for crate::rest::RestClient’s reqwest client, so an e2e run can drive a deployment whose hostnames don’t resolve to it yet (a pre-DNS-cutover cluster) while every URL keeps the REAL hostname — TLS SNI and certificate validation stay honest, which an IP-in-the-URL rewrite would not. Same shape as curl --resolve; set by hound-testkit from E2E_RESOLVE (see hound_testkit::remote).

Also honoured by the realtime plane, which reads these pins at dial time (crate::realtime): its WebTransport leg installs a hound_wt::PinnedResolver over them, and its WebSocket leg opens the TCP socket itself against the pin and then handshakes TLS against the original hostname. The call plane (control WS, iroh relay) still resolves inside its dependencies — see hound_testkit::remote for what to do about that one.

Process-global and write-once because the override is a property of the whole test process, and RestClient builds its reqwest::Client lazily on first use — install before the first request or not at all.
