Message search and the detached history it jumps into.

Two commands and one piece of state. HoundClient::search is a plain request/response over POST /search; the rest of this module exists because jumping to a hit puts a space’s message list somewhere the live tail is not.

§The detached state machine

A space’s MessageList is normally the live tail: page 0 seeded by open_space, extended by realtime message:* events. Jumping to a search hit replaces it with a window centred on that hit — possibly years back — and appending live traffic to that window would be wrong twice over: the new messages do not belong next to what is on screen (there is a gap of unloaded history between them), and the list would silently grow a second, disconnected region.

So the list carries a per-space detached flag:

                   open_space_around(space, message)
       ATTACHED  ──────────────────────────────────────►  DETACHED
       (live tail)                                        (around-window)
           ▲                                                   │
           │        resume_live(space) — reload page 0          │
           │        open_space(space)  — reload page 0          │
           └───────────────────────────────────────────────────┘
  • ATTACHED — every message:create / message:update / message:embeds event for the space folds into the list, as before.
  • DETACHED — an event is applied only when the list already holds that message id (see the gate in super::realtime_wiring). An edit or a link preview for something on screen still lands; a newly posted message is dropped, because nothing on screen is next to it. Nothing is lost: leaving the state re-fetches page 0 from the server, which is authoritative.
  • Both exits replace the window rather than merging into it — the around-window and page 0 are slices of different parts of the log, and a merge would splice an invisible hole between them (the same hazard MessageList::reconcile_window documents for a full reconnect window).
  • A sign-out clears the flags with the lists they describe.

The flag is observable (HoundClient::watch_history_detached) through the same watch mechanism as the message list itself, so the UI can show its “viewing older messages · jump to present” banner from a stream rather than from a command’s return value it would have to remember.
