The orchestration facade: ties the REST data plane, the session lifecycle, and the realtime (/community) plane into one observable, UI-free app core.

HoundClient is what the FRB layer (and any future native UI) drives. It owns the pieces and an AppState of tokio::sync::watch channels — one per observable snapshot, latest-wins, which is exactly what a UI wants (it never needs the history, only the current view). REST loads seed the snapshots; a single background task consumes the typed RealtimeEvent stream, folds each event through the pure reducers (CommunityTree/RosterView/MessageList), and republishes the mutated snapshot onto the matching watch sender.

Commands are async and return Result<_, HoundError>; observable getters return [watch::Receiver]s the binding subscribes. No FFI and no UI types live here — the crate stays standalone-buildable.

Structs§

AppState 🔒
The observable app state: one watch channel per snapshot the UI renders. Each holds the latest value (a new subscriber sees it immediately) and notifies on change. Per-space message lists are created lazily on HoundClient::open_space.
HoundClient
The headless application core. Cheap to share via the returned Arc<Self>; every command takes &self. Holds the REST client, the session, the observable state, and the live realtime connection (replaced on each (re)connect).

Constants§

KEYRING_READ_GRACE 🔒
How long startup waits on the credential store before giving up on a fast restore. Sized for a read that only hits the store (milliseconds); anything past it means the OS is asking the user something — see Session::load_stored — and no startup path may wait on a human.
MESSAGE_WINDOW 🔒
How many messages a space’s history window holds — the page the UI loads on open, and the same page a reconnect re-fetches to reconcile against.
REALTIME_WELCOME_GRACE 🔒
How long a realtime connect waits for the server’s Welcome before letting the caller proceed anyway. See HoundClient::await_realtime_live.
RESYNC_SUBSCRIBE_GRACE 🔒
How long the post-reconnect re-fetch waits for the server to confirm it re-joined a space’s room before going ahead without the confirmation.
STEAM_INIT_BOUND 🔒
How long HoundClient::new_bounded waits for the local Steam client before starting without it. Sized for a handshake with an already-running process; past it, Steam is booting (or wedged) and no startup path may keep waiting.

Functions§

bounded_steam_init 🔒
[SteamHandle::init] moved off the async worker and given a deadline. None for “no app id”, “not a Steam launch”, and “Steam did not answer in time” alike — all three mean the same thing to every caller: no Steam sign-in.
steam_auth_error 🔒
Map a Steam-client ticket failure onto the auth registry, one code per cause: “not under Steam”, “Steam is offline”, “the ticket callback never came” and “the SDK itself failed” are four different things to tell a user (and four different things to triage), so they must not share a Sentry bucket. The upstream display text stays as the message.
