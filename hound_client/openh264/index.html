§Cisco’s openh264 binary: fetch, verify, install

The software H.264 codec is not compiled into a shipped build. Cisco’s H.264 patent grant covers their binary module, and only when it is downloaded at the time the product is installed on the user’s device — a codec we compiled ourselves, or one we bundled into the release artifact, carries no grant at all. So the app fetches the blob itself, on first run, straight from Cisco, and hands it to the engine (hound_engine::api::Engine::set_openh264_blob).

§Where it fits in startup

spawn_install is fire-and-forget from init_app: the download must never be on the path to the first frame (the Dart bootstrap has a 30 s wedge watchdog, and a user on a slow link would otherwise stare at a black window while ~500 KB trickles in). Until it lands there is simply no software H.264 — encode_caps/decode_caps report h264: false, so peers are told the truth and never sent a stream this client cannot decode. Hardware H.264 (VideoToolbox, Media Foundation, VAAPI) is unaffected and needs none of this.

The one place that does wait is a capability probe taken moments after startup — see settle, which bounds the “joined a call before the codec arrived” race.

§Trust

Three independent checks, none of them skippable:

  1. HTTPS to ciscobinary.openh264.org (rustls, webpki roots — the workspace TLS stack).
  2. SHA-256 of the decompressed library against BLOBS below, which is transcribed from openh264-sys2’s own hashes.txt — so a corrupted transfer or a substituted file never reaches the cache.
  3. The engine re-verifies at install time, because the cache is a file on disk that anything could have rewritten between runs.

§Cache

<app-support>/openh264/<version>/<cisco file name>. Versioned by directory so a future openh264 release is a new download rather than an in-place overwrite, and so remove can drop the codec entirely (the settings toggle: openh264’s BINARY_LICENSE requires the user to be able to turn it off).

Statics§

AVAILABILITY 🔒
Generation counter bumped every time this process’s software-H.264 availability may have changed — a blob installed, the kill switch flipped either way. The value itself is meaningless; the wake is the signal, and the observer re-probes hound_engine::api::Engine::decode_caps for the truth.
DOWNLOADING 🔒
Set from the moment a first-run download is scheduled until it finishes, so settle knows there is something worth waiting for.
SETTLED 🔒
Woken when a download finishes, however it finishes.
