Relay-token handshake (client side).

When connecting to the MoQ relay (services/sfu::moq_relay) the client must present its relay token BEFORE the MoQ handshake. The relay reads the token off the first bi-stream, verifies the backend’s HMAC scheme, and replies one byte (1 = ok, 0 = reject). The client gates its MoQ handshake on reading the ok byte, so the relay’s token bi-stream is always accepted before moq-net opens its own control stream (QUIC accepts bi-streams in open order).

Wire (client → relay): u16 LE length + token bytes. (relay → client): 1 byte.

Direct peer-to-peer pub/sub (crate::MoqPublisher::connect / crate::MoqSubscriber::accept) does NOT use this — only the relay path does.
