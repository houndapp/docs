The MoQ object envelope.

A MoQ object payload is opaque to the relay, but the endpoints still need to recover the hound_media::Frame envelope (which track, which codec, the keyframe flag, the capture timestamp) that the encoder stamped and the jitter/playout core consumes. We prepend a tiny fixed descriptor to the object payload and forward the encoded bytes after it verbatim. The relay never reads it.

Layout (little-endian), OBJ_HEADER_LEN = 16 bytes, then the encoded payload:

  [0]       track     (TrackKind as u8)
  [1]       codec     (Codec as u8)
  [2]       flags     (bit0 = keyframe)
  [3]       layer     (bits 0..3 = temporal id; bits 3..8 reserved, zero)
  [4..8]    frame_seq (u32)
  [8..16]   timestamp_us (i64)
  [16..]    encoded frame bytes (forwarded verbatim)

Kept separate from hound_media::HEADER_LEN because this is the MoQ-object envelope, not the datagram PacketHeader.

Byte 3 was the pad byte and now carries the L1T2 temporal id (§2.3 of the large-call research). It is deliberately a flat per-frame value rather than the AV1 Dependency Descriptor: the DD is stateful (templates arrive only at intervals, so a relay must carry template state and survive a missed update) and has no Rust implementation at all — Pion, webrtc-rs and str0m all lack it. A masked 3-bit id in a byte we already send is a strictly simpler, already codec-blind version of RFC 9626’s short form, and it costs zero extra bytes.

It is also the ONLY thing the relay reads out of a hound object (services/sfu::derive), which is why object_temporal_id is public: the SFU must never grow its own copy of “where the tid lives”.

Constants§

MAX_AUDIO_OBJECT 🔒
Per-object payload bound for AUDIO tracks (defense-in-depth; see MAX_VIDEO_OBJECT). A real Opus frame is on the order of tens to low hundreds of bytes — 256 KiB is orders of magnitude above any legitimate frame, so this only ever catches a malformed/hostile object, never real traffic.
MAX_VIDEO_OBJECT 🔒
Per-object payload bound for VIDEO tracks (defense-in-depth on top of moq-net’s own transport-level frame cap). Deliberately equals moq-net 0.1.9’s MAX_FRAME_SIZE (16 MiB): sizing here is trusted to that cap today, but a relay/moq-net change should not silently widen what this layer accepts without the bound being visibly re-examined.

object_temporal_id
Read the temporal id off an encoded object, without decoding the rest of it — the relay’s derive filter (services/sfu::derive) is the only caller, and it runs per object, so it does exactly this much work: one bounds check and one mask. None for a buffer too short to be an object at all.
