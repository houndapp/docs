The shared GOP↔group/object mapping and the drain disciplines.

The single publish path (keyframe rolls the group; audio rolls by count) and the single subscribe drain (priority-drop across groups, ordered within one) that every publisher/subscriber-shaped type in this crate is built on — see the module docs on crate::moq for the frame ↔ group/object model.

Constants§

AUDIO_GROUP_OBJECTS 🔒
Audio objects per group before rolling the group boundary (the ordered audio substream model). Audio is sequential and stateful — not GOP-structured like video — so instead of one group (= one QUIC uni-stream) PER FRAME (which gives ~50 unordered racing streams/s whose cross-stream reordering corrupts playout), successive Opus frames are appended as objects to ONE group so QUIC delivers them in order. The group is rolled every AUDIO_GROUP_OBJECTS frames because a single never-rolled group is not viable in moq-net 0.1.9 (the 1024-object / 32 MB eviction cap → fatal CacheFull; late-join only attaches at a group boundary; and a lost object head-of-line-blocks the whole group until retransmit).

gop_publish_audio_frame 🔒
Publish one audio frame as an object in a COUNT-ROLLED group (the ordered-substream model — see AUDIO_GROUP_OBJECTS). The first frame and every AUDIO_GROUP_OBJECTS-th frame opens a fresh group (new ordered QUIC stream); the rest append to the open group, so a window of frames rides one in-order stream. The frame’s keyframe bit is IGNORED — every Opus frame is independently decodable, so audio grouping is driven by count, not by a keyframe flag. Shared by crate::MoqPublisher and crate::MoqTrackPublisher.
