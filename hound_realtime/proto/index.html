Wire types for the realtime plane.

A structured, versioned message protocol carried over whichever transport is available — WebTransport where it works, a plain WebSocket where it does not. These types serialize with serde (JSON on the wire) and carry no I/O, so the same declarations serve the server hub and the client session.

§Compatibility rules

  • Both directions are internally tagged ({"type": …}). An unknown tag fails to deserialize that frame only: transports skip it and keep the session, which is what makes a new variant additive rather than breaking.
  • Fields added after v1 carry #[serde(default)] (+ skip_serializing_if where absence is meaningful) so an older peer’s frame still parses.
  • Anything else — a renamed field, a changed tag, a removed variant — is a PROTOCOL_VERSION bump, detected at ClientMessage::Hello time rather than as a confusing parse failure later.

Constants§

MIN_PROTOCOL_VERSION
The oldest version this build still speaks. A server accepts any ClientMessage::Hello in MIN_PROTOCOL_VERSION..=PROTOCOL_VERSION and answers with the negotiated version in its ServerMessage::Welcome; raising this is what drops support for an old client, and is the only reason a connect is refused on version grounds.
PROTOCOL_VERSION
The newest version this build speaks. Bumped on any breaking change to the message set below.
