Module hub 

Source
Expand description

Authoritative, sans-IO routing state for the realtime plane.

Hub owns what the server knows about live connections — who each one is, which community and space rooms it belongs to — and turns every input into Outgoings tagged with who should receive them (Target). It performs no I/O: the shell feeds it inputs, asks it to resolve targets (Hub::recipients), and does the sending.

§Rooms

A connection auto-joins one room per community the user belongs to, and joins a space room on request. Community rooms carry space/voice events; space rooms carry message events. A user in three communities therefore receives voice and space-layout changes everywhere, but message traffic only for the spaces actually open in front of them.

§Facts, not questions

The hub cannot reach the database, so it never asks anything. Every input is a fact the shell has already resolved: whether a subscribe is authorized, which community owns a space. That keeps authorization testable here (the reducer decides what a denial does) while the lookup stays in the shell (which decides what the answer is).
