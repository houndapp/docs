Optional stable code signature for the binaries this harness builds (macOS only, opt-in).

§Why

Every Mach-O cargo produces is ad-hoc signed by the linker: no team, no stable identifier, and a designated requirement that is a bare cdhash of the binary’s own bytes. macOS keys its permission grants on that requirement, so a rebuild — any rebuild, one changed line — produces a different cdhash, a different “application” as far as TCC is concerned, and every grant the previous binary held is void.

The grant that bites this harness is Local Network privacy: the scenario suite’s test client runs an iroh endpoint that binds 0.0.0.0, and macOS gates such a socket’s non-loopback traffic behind a per-application grant. Ad-hoc signed, each run is a new application — either a fresh prompt, or (unattended) silent denial and a suite that fails on “no route” in ways that look like an SFU bug.

The stack’s SFU now runs on the host and advertises 127.0.0.1 only (see crate::sfu), so the only peer address a scenario is handed is loopback and there is no LAN traffic left to gate. Signing stays worth doing as belt and braces — the wildcard bind itself is unchanged, a firewall-on machine still prompts per application, and a stable identity keeps every other TCC grant (screen recording, microphone) alive across rebuilds.

Signing with a real Apple identity replaces that requirement with one keyed on identifier + team, both of which we hold fixed here (chat.hound.stack.<binary>). The grant is then made once and survives every rebuild.

§Opting in

Set APPLE_SIGNING_IDENTITY in the gitignored per-developer .mise.local.toml [env] (the same variable the Tauri-era note in that file already documents); list candidates with security find-identity -v -p codesigning. Unset — the default, and CI — this module is a no-op and the harness behaves exactly as it did before it existed.

Constants§

IDENTITY_ENV
The signing identity, as codesign --sign takes it. Named to match what .mise.local.toml already exports for the macOS app bundle.

Functions§

enabled
Whether signing is configured for this run: a non-empty identity AND a macOS host. Callers check this before doing work that only exists to feed sign (e.g. asking nextest to list its test binaries).
identifier 🔒
The stable identifier for a harness binary: half of the designated requirement (the team anchor is the other half). It must NOT be derived from the binary’s content — that is precisely what the linker’s ad-hoc signature does — and must not collide with the shipped app’s chat.hound.app.
identity 🔒
requirement 🔒
The designated requirement this module signs for: our identifier, signed under an Apple-issued certificate chain.
satisfies_requirement 🔒
Does binary ALREADY carry a signature satisfying requirement?
sign
Sign binary in place with the configured identity, output appended to build_log. No-op when signing isn’t enabled.
