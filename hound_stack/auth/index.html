The host hound-auth page process — the browser-deferred auth pages (passkey sign-in/sign-up, Steam, email link) a dev client opens in the system browser, and the page every magic link points at (MAGIC_BASE_URL, crate::backend).

A HOST process rather than the hound-auth compose container (which compose.dev.yaml still defines for the prod-like topology): the container meant a release cargo build inside docker on every --fresh, for a binary the host already builds under crate::cargo::STACK_SELECTION. The HTML is include_str!’d, so the binary needs no working directory.

Stateless: its only upstream is a fixed URL (HOUND_API_URL), so a backend restart does NOT restart it — only a rebuilt binary does.

DETACHED like the backend and SFU beside it — see crate::process.

Constants§

LISTEN 🔒
Bind address. NOT loopback, unlike the SFU: the opt-in passkeys-front Caddy container reaches this page from inside docker via host.docker.internal (see tools/houndbot/compose.e2e-override.yaml), which a 127.0.0.1 bind would refuse. Safe to widen: it is a plain HTTP page server — no media, and nothing it serves makes a LAN peer dial it.
PORT
The page’s port — the same one the container published, and what the backend’s RP_ORIGIN/MAGIC_BASE_URL default to.
READY_BUDGET 🔒
How long the page gets to answer after spawn. It binds one TCP listener and does no I/O first, so this is generous.
