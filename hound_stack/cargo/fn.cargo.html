A nested cargo invocation from root, with the environment cargo run injected into THIS process scrubbed off it.

hound-stack is itself launched by cargo run, which sets CARGO_MANIFEST_DIR, CARGO_PKG_* and friends for the child. A nested cargo inherits them and evaluates every build script’s rerun-if-env-changed against them — and ring’s build.rs declares CARGO_MANIFEST_DIR, so under the harness it always sees a value the shell never sets. Measured: 28 crates (ring, rustls, quinn, reqwest, iroh…) recompiled on every harness run, then again from the next shell build, and each relink of backend tripped the staleness check into restarting a backend that had not changed. Everything under CARGO_* that is cargo CONFIG (CARGO_HOME, CARGO_TARGET_DIR, CARGO_BUILD_JOBS, CARGO_INCREMENTAL, CARGO_TERM_COLOR, CARGO_LOG, …) is kept.
