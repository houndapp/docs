Expand description

ONE cargo build for several binaries: -p for every package in packages, --bin for every name in bins. Returns the built paths in bins order.

Why one invocation and not a build_bin per binary: each distinct -p set is a distinct feature resolve, and a crate already compiled under one resolve is recompiled under the next. Every caller therefore passes STACK_SELECTION and varies only bins — a package contributing no --bin (e.g. hound-testkit, whose test binaries nextest builds itself) still belongs in packages, purely so this build resolves the features that one did. Measured on a cold scratch target dir, after cargo nextest run --no-run -p hound-testkit --profile e2e: 478 units recompiled with -p hound-testkit in the selection, 482 without (the extra four — objc2, block2, dispatch2, brotli-decompressor — are ones nextest had already built under features this selection otherwise fails to reproduce). Adding -p hound-bot on top measured 478 as well: it is already inside the same dependency graph, so carrying it costs nothing and buys the visual flow’s houndbot the same resolve.

What must NOT join this call is --tests: it would pull in backend’s and hound-sfu’s own (heavy) test binaries on every backend edit.
