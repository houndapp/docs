Module signal

Expand description

Signalling a detached stack process by pid.

The processes this stops belong to no Child we hold — an earlier hound-stack invocation spawned them and exited (see crate::process::state), so Child::kill/wait are unavailable and the raw signals are the whole interface. SIGTERM, then a bounded poll with signal 0 (the “does this pid exist” probe), then SIGKILL: the backend closes its listeners on TERM and the SFU drains-then-exits, and nothing here may leave :8080 or :7890 held once teardown claims it finished.

Pid reuse is the one hazard, and it is bounded by hygiene rather than checked: the state entry is removed the moment we stop or replace the process it names, so a stale pid only survives a kill -9 of this harness itself. Unix-only — Windows dev is not a supported workflow here.

STOP_GRACE
How long a process gets to exit on SIGTERM before it is killed. Covers the SFU’s drain as well as the backend’s listener close — the dev SFU runs with a 1 s drain deadline (see crate::sfu), so neither is slow here.
