hound_stack::lifecycle

Module repair 

Source
Expand description

What to do with whatever answers on the stack’s ports: the pure half of [super::is_live]’s successor. Probing is I/O (probe); turning the four probe results into a Plan is not (plan), so that is where the decision lives and what the tests cover.

The backend is the only probe that decides between reuse and bring-up. Everything else a live backend is missing is REPAIRED in place: a bring-up would run the port preflight, which the answering backend fails by definition — refusing with “run hound-stack down” for a state the harness can fix itself.
