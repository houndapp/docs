hound-stack: the dev/CI stack lifecycle library backing the hound-stack CLI (src/main.rs). One implementation shared by every caller that needs “make sure the dev backend stack is up and healthy” — the e2e and visual subcommands, plus the up/down manual-dev commands. Replaces the hand-synced tools/houndbot/e2e.sh / ui/integration_test/visual.sh shell scripts.

The stack is PERSISTENT: every flow reuses a live one and leaves it running, --fresh replaces it, --teardown/down removes it. It is three compose services (postgres, mailpit, iroh-relay — none built from this repo) plus THREE detached host processes — the backend, the SFU and the auth page. See lifecycle for the full contract and for why the SFU and auth page are not containers.

Noise contract (every flow): the console gets one line per lifecycle step; every subprocess’s full output lands in a separated artifact file (build.log for all build phases, compose.log, backend.log, sfu.log, auth.log, bot logs, test output); binaries are built quietly first and then exec’d so runtime logs hold runtime lines only; a failure surfaces the relevant log’s tail inline.

Module map:

  • ports — host port preflight, run only when this invocation is about to bind those ports itself.
  • compose — the docker compose/docker-compose/mise fallback chain, output to compose.log.
  • wait — deadline-bounded polling (HTTP reachability, container health, log lines) — no bare sleeps beyond the poll interval.
  • cargo — quiet builds to build.log; runtime logs never see compiler chatter. One package selection per flow (see cargo::build_bins).
  • codesign — optional stable macOS signature, so a rebuild doesn’t void the harness’s Local Network grant.
  • logs — log sectioning + failure-tail helpers.
  • process — the detached-process machinery the host processes share; process::state is the pid/staleness record they leave on disk (target/hound-stack/stack.json) and process::signal how a later run stops them.
  • backend — spawns the (prebuilt) host backend DETACHED with the shared dev env (the one place that env lives).
  • sfu — spawns the (prebuilt) host SFU DETACHED, bound and advertising LOOPBACK only, plus the “is voice routable” contract. The dev stack does not run the hound-sfu compose container; see lifecycle for why.
  • auth — spawns the (prebuilt) host hound-auth page DETACHED on :3100 (replacing the hound-auth compose container, so --fresh builds no docker image from this repo).
  • artifacts — E2E_OUT_DIR/VISUAL_OUT_DIR-style output dir resolution.
  • tee — runs a child process, teeing its output to console + a log file (the Rust equivalent of cmd | tee log).
  • lifecycle — lifecycle::LiveStack::ensure_up (reuse or bring up, always leave running) and lifecycle::teardown (the explicit removal), composing the modules above.
  • e2e — the hound-testkit scenario suite flow.
  • visual — the visual snapshot harness flow (bootstraps via hound_testkit::Env rather than re-implementing it in shell).
  • updown — manual up/down dev commands.

Modules§

artifacts
Artifact directory resolution: an env var (E2E_OUT_DIR/VISUAL_OUT_DIR — a durable, CI-collectible dir) if set, else a throwaway temp dir left in place for local inspection. Same compat contract the two shell scripts documented.
auth
The host hound-auth page process — the browser-deferred auth pages (passkey sign-in/sign-up, Steam, email link) a dev client opens in the system browser, and the page every magic link points at (MAGIC_BASE_URL, crate::backend).
backend
The host backend process: the exact dev env both shell harnesses ran the backend under — this is the one place that env now lives.
cargo
Quiet cargo builds, separated from runtime logs. Every binary the harness runs (backend, SFU, auth page, houndbot, snapdiff, the nextest test binaries) is built HERE first — full compiler output captured into the run’s build.log, surfaced only on failure — and then executed directly, so each runtime artifact (backend.log, bot logs, test output) contains runtime lines only, never pages of “Compiling…” chatter.
codesign
Optional stable code signature for the binaries this harness builds (macOS only, opt-in).
compose
Compose driver: resolves the same docker compose (plugin) → docker-compose (standalone) → mise-pinned fallback chain the shell harnesses used, so a CI host that ships bare docker (no plugin, no standalone binary — the X64 runner) still works without a host install.
e2e
hound-stack e2e: ensure the stack is up, run the hound-testkit scenario suite (cargo nextest run -p hound-testkit --profile e2e) against it, collect artifacts. Mirrors the retired tools/houndbot/e2e.sh. Extra CLI args forward to cargo nextest run (e.g. an -E filter for a fast local iteration loop against one scenario file).
lifecycle
The shared stack lifecycle: ensure the stack is up (reusing a live one), and — only when asked — tear it down again.
logs
Log-file helpers for the harness’s noise policy: every subprocess writes its full output to a per-concern artifact file, the console gets one progress line per lifecycle step, and a failure surfaces the relevant log’s tail inline — never the whole stream.
ports
Port preflight: fail fast if this run’s fixed host ports are already taken by a leftover/concurrent stack, instead of racing it through compose up/backend-startup timeouts.
process
The stack’s DETACHED host processes — the backend (crate::backend), the SFU (crate::sfu) and the auth page (crate::auth) — and the machinery they share.
sfu
The host SFU process, and the “is voice routable” contract.
tee
Run a child process, teeing its stdout/stderr to both this process’s own stdout/stderr and a log file — the Rust equivalent of the shell scripts’ cmd 2>&1 | tee "$LOG".
updown
hound-stack up/down: the manual dev pair.
visual
hound-stack visual: ensure the stack is up, bootstrap the shared community via [hound_testkit::Env] (no bash curl/jq re-implementation — see its module doc), spawn one houndbot --testcard peer into the voice call, run the real-app Flutter integration test, then snapdiff compare against the accepted baselines. Mirrors the retired ui/integration_test/visual.sh.
wait
Deadline-bounded polling — no bare sleeps beyond the poll interval (see AGENTS.md’s “Test determinism”). Every waiter here bounds total wall time and returns a descriptive eyre error on timeout instead of hanging or (worse) racing a downstream timeout with a less useful cause.
