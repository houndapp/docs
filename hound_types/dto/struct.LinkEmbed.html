Expand description

The unfurled preview of one URL, ready to render.

Additive by construction: every field after the first three is optional or defaulted, so a client built against an older field set still decodes a newer server’s embed (see the compatibility rules on the realtime protocol).

Fields§

§request_url: String

The URL as it appeared in the message. This is what a client highlights in the body text, and what pairs an embed with its link.

§url: String

Where the fetch actually ended up: redirects followed, then og:url / oEmbed url if the page declared a canonical form. What a click opens.

§kind: EmbedKind§title: Option<String>§description: Option<String>

Summary text. Newlines survive (a publisher’s paragraph breaks are meaningful); every other control character does not.

§site_name: Option<String>

og:site_name, else the registrable domain.

§author: Option<EmbedAuthor>§provider: Option<EmbedProvider>§accent_color: Option<String>

The page’s theme-color, as #rrggbb. Tints the card’s accent rail. Validated to exactly that form — a client can parse it with confidence.

§published_at: Option<i64>

article:published_time, as unix milliseconds.

§locale: Option<String>

og:locale, e.g. en_GB.

§images: Vec<EmbedMedia>

Every og:image the page declared, in document order, capped at MAX_EMBED_IMAGES. The first is the primary/poster; the rest render as a gallery. Empty is normal.

§video: Option<EmbedVideo>§audio: Option<EmbedMedia>§favicon: Option<EmbedMedia>

The site’s icon, proxied like any other media.

pub fn is_renderable(&self) -> bool

Whether there is anything worth drawing a card for.

A page with no title, no summary and no media unfurls to a card that says only what the link text already said — so callers drop it rather than stack an empty box under every URL.
