Link-embed wire types — the unfurled preview of a URL found in a message.

One shape serves three consumers, which is why it lives here rather than in the backend: the REST message endpoints return it, the realtime plane pushes it (MessageEmbedsUpdated), and the client mirrors it into Dart untouched.

§What the server promises the renderer

Everything here is already sanitised. The backend is the only party that parses third-party HTML, so a client may render every string as plain text with no further escaping: text fields are entity-decoded, control characters are stripped, and lengths are capped (MAX_TITLE_CHARS and friends).

Two deliberate omissions keep that promise cheap to hold:

  • No HTML reaches a client. oEmbed’s html field and twitter:player are iframe players. They are captured for the embed debugger (EmbedDebugReport::oembed_html) and are never part of a LinkEmbed, so there is no path by which a renderer could be tempted to execute one.
  • No third-party URL is fetched by a client. Every media URL a LinkEmbed carries points at this deployment’s media proxy (EmbedMedia::url); the origin URL travels alongside it in EmbedMedia::source_url for attribution and for the debugger, not to be loaded.
