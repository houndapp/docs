Remote-target mode: running the scenario suite against a DEPLOYED hound (staging, or a new cluster pre-DNS-cutover) instead of the local compose stack. Selected explicitly by hound-stack e2e --target <url> — never by default; see tools/stack/src/e2e.rs.

Two env vars, both set by the harness on the cargo nextest run:

  • E2E_REMOTE=1 — “there is no local stack”. skip_local_only is the runtime gate scenarios use to bow out. Chosen over a nextest filter expression so remote mode stays ONE invocation with one env var, and so the skip reason prints in the test’s own output next to the assertion it replaced — a filter would silently omit the test from the report instead.
  • E2E_RESOLVE=host:port:ip[,…] — curl --resolve-shaped DNS pinning, so the suite reaches a cluster its hostnames don’t resolve to yet. URLs keep the real hostnames, so TLS SNI/cert validation still proves we hit the intended deployment.

Reach of the pin: every reqwest client in the run — this crate’s Mailpit/bootstrap calls (http_client) and hound-client’s REST plane (install_dns_overrides, via its dns-override feature). NOT the realtime or media planes: rust_socketio 0.6 exposes only tls_config/ opening_header on its builder (its engine.io transport builds its own reqwest/tokio-tungstenite connections), and the call plane’s control WS (tokio_tungstenite::connect_async) and iroh relay dial (RelayUrl) resolve internally too. So E2E_RESOLVE alone carries auth + REST + messaging REST; a remote run that must also exercise realtime/calls needs the hostnames genuinely resolving — an /etc/hosts pin on the runner is the operator-side equivalent, and covers every plane at once.

Functions§

http_client
A reqwest client carrying the run’s DNS pins — the constructor for every HTTP call this crate makes itself (Mailpit polling, the admin bootstrap REST calls). Falls back to a default client if E2E_RESOLVE is unset or unparseable (the pin is a convenience; a bad spec must not make every scenario fail as if the backend were down — parse_resolve surfaces the error where it can be acted on, in the harness).
install_dns_overrides
Push the run’s DNS pins into hound-client’s REST plane. Idempotent and write-once there; call before the first client request (i.e. at crate::Env::from_env).
is_remote
Whether this run targets a remote deployment (no local stack to poke).
parse_resolve
Parse host:port:ip[,host:port:ip…] (curl --resolve shape) into hostname → SocketAddr pins. Bracketed IPv6 literals ([::1]) are accepted for the address, matching curl.
resolve_overrides
The parsed E2E_RESOLVE pins, or empty when unset/invalid.
skip_local_only
Gate for a scenario that drives LOCAL infra (spawns a process, stops a compose service): true means “skip, and here’s why” — already printed to the test’s output. Returns false (proceed) in the default local mode.
