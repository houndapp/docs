ci-metrics — what a CI job left on disk, as prometheus exposition.

Every metrics step in .github/workflows/ is now one command:

cargo run -q -p ci-metrics -- <subcommand> --push

Three subcommands, one per producer:

  • bench — criterion’s own on-disk state (target/criterion/<bench id>/new/estimates.json, one directory per bench_function; the suite uses no groups, so ids are flat) becomes one ci_bench_ns_per_iter series per benchmark. The JSON is read rather than the bencher-format stdout because it is what criterion itself reads back for baseline comparison, and it survives whatever else the build printed. The figure is the median point estimate — the same statistic the bencher format prints.
  • job — the job-level trio on its own, plus (with --junit) the ci_e2e_tests counts read out of nextest’s JUnit report. This is also what the plain trio-only steps (nightly build/smoke) call.
  • visual — the trio plus the ci_visual_snapshots counts from snapdiff’s run summary.

Every run ends with the trio the dashboards key off — ci_job_success, ci_job_duration_seconds, ci_run_info — whose values come from the environment the workflow step exports (WORKFLOW, JOB, PLATFORM, RUN_ID, SHA, JOB_SUCCESS, JOB_DURATION).

The lines always go to stdout, so the job log keeps the record of exactly what was reported; --push additionally POSTs them to the backend’s ingest route (see push). This tool absorbed both halves of what used to be a producer script piped into .github/scripts/push-ci-metrics.sh, which the runners’ missing jq/python3 had forced into unreviewable grep/sed.

Report-only by construction. A CI job must never fail because its metrics couldn’t be produced, so once the arguments parse, every path exits 0: a missing criterion directory, an unreadable estimates.json, an absent or malformed junit.xml, an unset token, a refused connection, and a value that can’t be a prometheus label are each a stderr warning and a dropped series, never an abort. (Bad arguments still exit non-zero via clap — that is a broken workflow step, not a broken CI run, and it should be loud.)
